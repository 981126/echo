# 标准工作流（WORKFLOW）

> AGENTS.md 引用的流程细则。纯 Markdown、工具无关，任何 AI 工具打开项目都按此执行。

## 一、需求输入与反问（人类 + AI）
人类说出自然语言需求后，AI：
1. **原样登记**：先记 `requirements/R-xxx.md`（原文，禁止改写删减；编号取 `requirements/` 现存最大 +1，与 README 索引同步）
2. **反问清单（10 项，逐项过，不许跳过）**：
   1. 范围与边界——包含什么？明确不包含什么？
   2. 场景与影响——在哪用？影响现有功能吗？
   3. 数据——需要哪些新数据？来源可靠吗？拿不到怎么办？
   4. 边界与异常——空数据、失败、重复、极端情况？
   5. 验收标准——怎么算完成？可测试吗？
   6. 成本与性能——多花钱吗？拖慢系统吗？
   7. 依赖与风险——依赖外部服务吗？它挂了怎么办？
   8. 优先级——现在做还是排期？
   9. 动效（R-175 起必问）——列表/卡片入场、TAB 切换、抽屉/弹窗、加载与状态变化，该有的动画不能省，且美观流畅。
   10. 非实时返回（R-202 起必问）——同步还是耗时/后台返回？**所有非实时结果必须有进行中动效，且切页/刷新回来仍能恢复「进行中」**（否则误以为已完成）。
3. **复述确认**：把「需求 + 反问答案 + 你的理解」复述给作者；作者确认后才写业务代码。
   （线上**明显 bug** 可先定位根因、直接修复并登记，不必等待「继续」，但要说明根因与影响。）
4. **写入归档**：原文 + 反问 + 确认/处理结论全部进 `requirements/R-xxx.md`。

## 二、PRD 与里程碑更新（AI）
- 更新 `docs/PRD.md`（范围/现状/验收）
- 在 `docs/milestones.md` 新增/调整条目（里程碑 = M 序号；需求 = R-xxx，两者对应）
- 展示计划，等作者说「继续」才写业务代码（bug 修复除外）

## 三、实施与自愈（AI）
- 按里程碑实现，顺序遵守依赖
- 每完成一个里程碑：`scripts/verify.sh`（lint + 类型检查 + 测试 + 构建）→ 修复全部失败 → 再验证
- 涉及外部依赖（DeepSeek/阿里云/TikHub）的测试一律 mock，保证离线可跑；**线上联调走真实模式**
- 涉及接口/表结构：用自动生成器刷新 `docs/API.md`、`docs/DATABASE.md`
- UI 类功能输出截图/预览供作者确认
- **AI 自测（强制，交付前必做）**：
  1) scripts/verify.sh 全绿；
  2) 相关后端接口冒烟（真实或 mock，跑通关键链路）；
  3) 前端关键交互点检（无 JS 报错，弹窗/按钮/勾选/跳转可用）；
  自测不过 = 不算完成，不许说“做好了”。
- **保持服务运行（强制）**：改动完成后确认后端 http://127.0.0.1:8000 与前端 http://localhost:5173 都在运行并已加载最新代码（必要时重启），health/页面可访问后再交付。

## 四、记录与提交（AI）
- 更新需求状态（已登记→澄清→已确认→实施中→已完成/搁置/拒绝）
- 更新 `docs/milestones.md` 勾选进度；追加 `docs/CHANGELOG.md`
- commit 信息带需求编号：`feat(R-xxx)` / `fix(R-xxx)` / `docs(R-xxx)`
- 每个需求一个 commit，不夹带无关改动

## 五、定义完成（Definition of Done）
- [ ] 代码通过 `scripts/verify.sh`
- [ ] AI 已自测：verify + 相关接口冒烟 + 前端关键交互，均通过
- [ ] 动效点检：新交互都有动效且流畅，切换类无空白闪帧（首帧 opacity ≥0.6、落定 1/none）——规范见 `DESIGN.md` §8
- [ ] 非实时结果可见（R-202）：耗时/后台返回的功能有进行中动效，且切页/刷新回来仍能恢复「进行中」——规范见 `DESIGN.md` §8.6
- [ ] 服务运行中：后端/前端已启动并加载最新代码，health 与页面可访问
- [ ] 验收标准逐条可验证
- [ ] 需求状态已更新，PRD/里程碑/CHANGELOG 已同步
- [ ] 已提交，commit 带编号
