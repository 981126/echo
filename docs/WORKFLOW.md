# 标准工作流（WORKFLOW）

> AGENTS.md 引用的流程细则。纯 Markdown、工具无关，任何 AI 工具打开项目都按此执行。

## 一、需求输入与反问（人类 + AI）
人类只需说一句自然语言需求。AI 收到后：

1. **原样登记**：先记 `requirements/R-xxx.md`（原文，禁止改写删减）
2. **反问清单（8 项，逐项过，不许跳过）**：
   1. 范围与边界——包含什么？明确不包含什么？
   2. 场景与影响——在哪用？影响现有功能吗？
   3. 数据——需要哪些新数据？来源可靠吗？拿不到怎么办？
   4. 边界与异常——空数据、失败、重复、极端情况？
   5. 验收标准——怎么算完成？可测试吗？
   6. 成本与性能——多花钱吗？拖慢系统吗？
   7. 依赖与风险——依赖外部服务吗？它挂了怎么办？
   8. 优先级——现在做还是排期？
3. **复述确认**：把"需求 + 反问答案 + 你的理解"复述给作者，作者确认后才继续
4. **写入归档**：原文 + 反问 + 确认结论全部进 `requirements/R-xxx.md`

## 二、PRD 与里程碑更新（AI）
- 更新 `docs/PRD.md`（范围/非目标/数据/验收）
- 在 `docs/milestones.md` 新增或调整里程碑
- 展示计划，等作者说"继续"才写代码

## 三、实施与自愈（AI）
- 按里程碑逐个实现，顺序严格遵守
- 每完成一个里程碑：`scripts/verify.sh`（lint + 类型检查 + 测试 + 构建）→ 修复全部失败 → 再验证
- 涉及外部依赖（DeepSeek/阿里云）的测试一律 mock，保证离线可跑
- UI 类功能输出截图/预览供作者确认
- **AI 自测（强制，交付前必做）**：任何功能开发/修复完成后，AI 必须先自测再交付——
  1) scripts/verify.sh 全绿（lint+类型+测试+构建）；
  2) 相关后端接口冒烟（真实或 mock 均可，跑通关键链路）；
  3) 前端关键交互点检（无 JS 报错，弹窗/按钮/勾选/跳转可用）；
  自测不过 = 不算完成，不许说“做好了”

## 四、记录与提交（AI）
- 更新需求状态（已登记→澄清→已确认→实施中→已完成/搁置/拒绝）
- 更新 `docs/milestones.md` 勾选进度
- commit 信息带需求编号：`feat(R-003): ...` / `fix(R-003): ...`
- 每个里程碑/需求一个 commit，不夹带无关改动

## 五、定义完成（Definition of Done）
一个需求/里程碑只有满足以下全部才算完成：
- [ ] 代码通过 `scripts/verify.sh`
- [ ] **AI 已自测**：verify.sh + 相关接口冒烟 + 前端关键交互点检，均通过
- [ ] 验收标准逐条可验证
- [ ] 需求状态已更新，PRD/里程碑已同步
- [ ] 已提交，commit 带编号
