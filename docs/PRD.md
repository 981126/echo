# PRD — 自媒体复盘纠错平台

> 状态：`待确认`
> 最后更新：2026-09-01
> 用户：单人（作者本人），程序员，会用 AI 工具

---

## 1. 背景与目标

作者在抖音 / B站 / 小红书三个平台发布短视频（1~2 分钟纯口播），当前赛道为
求职、面试、赚钱、知识（**仍在试错，尚未固定**）。已有约 50 条历史视频，部分保留文案（与口播内容可能不一致）。

**核心目标**：让系统越来越懂作者的人设 →
- 每天自动产出与"人设 × 当日热点"匹配的选题与脚本
- 对已发布内容做复盘纠错（数据 + 归因 + 建议 + 赛道方向）
- 辅助作者找到适合自己的赛道

## 2. 非目标（明确不做）
- 不做多用户 / 账号体系（单用户，NAS 局域网使用）
- 不做自动发布到平台
- 不做视频自动剪辑（封面仍由作者选帧，系统只给"建议截取时间点"的加分项）
- 不做视频封面自动生成 / 自动抽帧（封面由作者上传图片，R-016；抽帧列为未来扩展）
- 不做移动端 App；但 **Web 需做移动端响应式适配**（手机浏览器可用）
- **暂不接入 WorkBuddy / 微信通道**（列为未来扩展，不进入里程碑）

## 3. 功能范围

### 3.0 项目自描述体系（M0，基石）
- 项目根目录内置完整"自描述体系"，保证**任何 AI 编码工具**（Codex / Cursor / Claude Code 等）打开项目都能快速理解背景与架构，并按同一标准流程产出：
  - `AGENTS.md`：行为手册入口（项目一句话背景、技术栈、目录速览、新需求标准流程、硬性规则）
  - `docs/ARCHITECTURE.md`：架构总览（模块图、数据流、数据模型、目录结构、运行/测试方式）
  - `docs/WORKFLOW.md`：新需求标准流程（读文档 → 改 PRD/里程碑 → 等确认 → 实现 → 验证 → 记录）
  - `docs/DECISIONS.md`：关键设计决策记录（防 agent 改坏）
  - `docs/PRD.md`、`docs/milestones.md`：需求与进度
  - `scripts/verify.sh`：标准验证门槛，任何改动必须通过
- 硬性规则：**任何新需求必须先进 PRD/里程碑并经作者确认，才允许写业务代码**

### 3.1 内容库与转写
- 批量导入 50 条历史视频；支持逐条导入新视频
- **导入双通道**：Web 直接上传 + NAS 文件夹自动监听（`data/inbox/` 拖入文件自动转写入库）
- 视频自动转写（**阿里云 ASR API**；1~2min 口播，成本低）
- 文案可附带导入，标注"与口播可能不一致"，仅作辅助参考，**分析以转写稿为准**
- 视频状态：**计划中 / 已发布**，含**计划发布时间**与**实际发布时间**字段（支撑时间线视图）
- **平台、赛道均支持多选**（`platforms` / `main_topics`，JSON 数组；求职/面试/赚钱/知识/其他；存量单值自动迁移）；看板/复盘/赛道雷达按视频选中项各自聚合，一条视频可同时计入多个赛道/平台（M6，R-016）
- **素材库封面功能**：作者上传封面图（jpg/png，存 `data/covers/`，视频表 `cover_path` 字段），素材库卡片与详情展示（M6，R-016）
- 视频标签系统：**商务广告标签**（广告视频只归档、不参与人设/风格学习）+ 自定义标签（赛道、风格等）
- 历史 50 条：**AI 预打标签（赛道/广告）+ 作者批量确认**（M1），避免手动逐条打标

### 3.2 人设系统
- 人设档案 = **标签 + 描述** 的结构化列表（例：`标签: 犀利敢说 / 描述: 常用反问句和短句，喜欢一针见血`）
- 初始化：分析全部历史转写稿，生成初版人设档案
- 迭代：新视频进入 → 增量分析 → **AI 建议扩充（新标签+描述）→ 作者确认 → 更新档案**（保留版本历史）
- 作者可手动添加标签与描述，随时扩充边界
- 商务广告内容不参与人设学习
- 人设档案含**红线/边界字段**：作者明确"不做什么"（不蹭某类热点、不接某类广告、不用某种语气），生成时强制遵守，作者手动维护
- **人设验收样例（golden test）**：M1 从历史中选 3~5 条基准视频，验证生成结果"像不像作者"，达标后才继续（最大质量风险防线）
- **改稿差异分析**：作者在 Web 工作台改写 AI 脚本的差异是"最强风格纠偏信号"，纳入人设学习闭环（M5）
- **生成质量护栏（M10，R-022）**：自动优化节流（每 3 条素材 1 候选）；候选启用前 diff；1-5 分高低分反馈回流（样本权重 + 优化输入）；金样本自测（先提示后强制）
- **AI 提示词版本管理（M9，R-021）**：各功能提示词 tab 页查看/编辑；手动编辑另存新版本并启用；上传新视频后基于当前启用版自动产出候选新版（不直接启用），历史版本可预览与回滚启用
- **全量风格学习（M8，R-020）**：分析库内全部非广告素材——生成时注入"风格画像"（口头禅/句长/语气统计）并按"表现加权 + 时间衰减 + 去重"召回风格样本；草稿 1-5 分打分进入学习与复盘

### 3.3 每日热点挖掘与匹配
- 每日抓取：抖音热榜 / B站热门 / 小红书热搜（**免费爬虫优先，第三方聚合热点 API 兜底**，数据源可切换）
- 热点 × 人设 × 历史选题 匹配打分（**DeepSeek**），输出当日候选选题

### 3.4 生成
- 输出三件套：**视频标题 + 封面字（与标题不同）+ 口播脚本**
- 可选平台外壳：小红书正文、B站简介、发布话题标签
- 语气一致性：人设档案 + 精选风格样本（**本地 BM25/TF-IDF 检索**历史最"像作者"的表达，零成本、单用户够用）
- 加分项：建议封面字从视频第几秒截取
- 选题/草稿可设置**计划发布时间**（进入时间线视图）

### 3.5 Web 界面（核心工作台，Vue 3 SPA）
- **全站视觉升级（M6，R-015）**：统一设计系统——参考 seanhalpin.xyz 的极简/留白/文艺风格；以轻量 UI 组件体系替代原始 HTML 控件（可用 UI 库，实施时说明理由）；系统字体栈 + 内联 SVG 图标，不依赖外部 CDN；桌面 + 手机全响应式
- 素材库：视频卡片（含封面）、转写稿、标签管理；**编辑面板全量回显**（平台/赛道多选、状态、计划/实际发布时间、广告、标签、原始文案、校对稿）；**转写稿/校对稿可修改**（ASR 原始转写只读）
- 人设档案：查看、编辑、确认 AI 建议
- 每日选题列表 + **脚本编辑工作台（内置 Markdown 写作编辑器，所见即所得、支持插入图片；作者直接在平台撰写与改写文案；M6，R-018）**
- 数据看板：各视频指标增长曲线
- 复盘报告查看
- **移动端响应式**：全部页面适配手机浏览器（阅读、确认、快速改稿场景）
- **内容时间线**：日历/时间轴视图，标出历史已发布视频与计划中视频（含计划发布时间），支持查看发布节奏、防断更、拖拽调整计划时间
- **右上角通知中心（M7，R-019）**：异步长任务（转写/人设初始化/每日流水线/改稿差异/AI 生成）完成或失败时右上角铃铛提示（红点 + 下拉列表），点击跳转对应界面；通知入库支持全部已读/清空
- **AI 对话页**：与系统直接对话（查询素材/指标、触发生成、改稿、复盘问答），基于 DeepSeek 函数调用访问系统能力，对话历史入库；**M6 升级为 ChatGPT 式（R-017）**：多会话列表（新建/切换/重命名/删除）+ SSE 流式输出 + Markdown 渲染 + 复制按钮
  - **权限边界**：只读问答（查数据/素材）直接答；写操作（生成/改稿/删除）必须先经作者确认

### 3.6 指标归档（每日自动）
- 每天自动抓取每个视频的：播放 / 点赞 / 收藏 / 评论（+涨粉如可得）
- **三通道可插拔**：cookie 自动抓取（best-effort，失效自动降级）/ 平台导出导入 / 手动填写
- 归档到数据库，支持按视频、按赛道、按平台分析增长与问题

### 3.7 复盘与赛道雷达
- A 报表：每视频 / 每赛道 / 每平台指标汇总
- B 归因：内容特征 × 数据 → 解释为什么好 / 为什么差
- C 建议：下一条应该做什么
- D 赛道方向：求职 / 面试 / 赚钱 / 知识 表现对比，建议试错重心

### 3.8 推送通道（每日早间）
- **邮件（QQ 邮箱 SMTP）**：每日 3 个以上选题 + 脚本 + 标题 + 封面字
- 邮件内可打分（用 / 不用 + 星级，可选）
- **隐式反馈为主**：作者实际采用选题发布新视频 → 新视频进系统 → 自动分析 → 人设更精准
- （微信推送：暂不接入，未来扩展）

### 3.9 需求管理与留痕
- 所有需求（无论来自对话 / Web）都必须归档留痕，全生命周期可追溯
- **单一入口 + 编号**：每条需求自动分配编号 `R-001`…，原文原样记录，禁止改写删减
- **双写**：`requirements/` 文件夹（每需求一个文件 + 索引表）为事实源，数据库同步一份供 Web 展示
- **状态机**：已登记 → 澄清中 → 已确认 → 实施中 → 已完成 / 已搁置 / 已拒绝（含原因）
- **可追溯链**：需求 ↔ PRD 章节 ↔ 里程碑 ↔ commit（commit 信息必须带编号，如 `feat(R-003): …`）
- Web 提供"需求管理"页：查看、筛选、检索、状态变更
- `AGENTS.md` 硬性规则：任何 agent 收到需求，第一步必须建档编号，再进入标准流程
- **需求反问机制（强制）**：agent 收到新需求后，必须先按"需求反问清单"逐项追问作者**可能未考虑的问题**，作者确认/修改后再进入 PRD 与排期；**原文 + 反问 + 确认结论全部留档**（含在需求文件内）

### 需求反问清单（agent 收到新需求必须逐项检查并追问）
1. **范围与边界**：具体包含什么？明确不包含什么（非目标）？
2. **场景与影响**：在什么场景用？对现有功能/工作流有什么影响？
3. **数据**：需要哪些新数据？来源可靠吗？拿不到时怎么办？
4. **边界与异常**：空数据、失败、重复、极端情况怎么处理？
5. **验收标准**：怎么算完成？可测试吗？
6. **成本与性能**：会增加 API 成本或拖慢系统吗？
7. **依赖与风险**：依赖外部服务吗？它挂了怎么办？
8. **优先级**：现在做还是排期？

## 5. 技术方案（已确认）

### 数据与隐私（已确认）
- 视频转写稿、人设分析、生成内容会发送至**阿里云（ASR）**与**DeepSeek（LLM）**，作者已知情同意
- 局域网**简单访问令牌**（防止其他设备误访问 / NAS 暴露公网时兜底）
- 定时备份：SQLite 热备份（官方备份接口）+ `docs/` + `requirements/` 快照

### 架构原则
- **单用户、轻量、低内存**：单进程单体应用，不引入 Redis / 消息队列 / 微服务
- **方便扩展**：模块化 + 适配器模式（热点源、指标源、ASR、LLM、推送均可插拔替换）
- **开发与运行分离**：笔记本开发，NAS 只跑 Docker 产物
- 长任务（批量转写、生成）用"DB 任务表 + 后台线程"跟踪状态

| 项 | 选型 | 说明 |
|---|---|---|
| 部署 | NAS（Intel N150 / 4C12G），Docker Compose | 只跑 Docker；开发在作者笔记本 |
| 后端 | Python FastAPI + APScheduler | 单进程；轻量低内存 |
| 数据库 | SQLite + Alembic 迁移 | 单用户足够，备份即拷文件 |
| 前端 | Vue 3 + Vite（SPA，响应式适配移动端） | 工作台交互多；手机浏览器可用 |
| 任务模型 | DB 任务表 + 后台线程 | 不引入 Redis/队列 |
| ASR | **阿里云 ASR API** | 一次性批量 50 条，成本低 |
| LLM | **DeepSeek API** | 中文语气好、成本低 |
| 热点源 | 免费爬虫优先 + 聚合 API 兜底 | 适配器模式，可切换 |
| 指标源 | cookie 抓取 / 导出导入 / 手动 | 三通道，自动降级 |
| 邮件 | QQ 邮箱 SMTP（授权码） | 每日早间推送 |
| 封面建议 | 后端抽帧 + 简单场景检测 | 加分项，M 后期 |
| 需求留痕 | `requirements/` 文件（事实源）+ 数据库 + git | 双写，编号 R-xxx，commit 关联 |
| AI 对话 | DeepSeek 函数调用（function calling）访问系统数据/动作 | 查询、生成、改稿、复盘问答；对话历史入库 |
| 密钥 | 全部环境变量（.env），不硬编码 | — |
| 时区 | 容器内强制 Asia/Shanghai | 每日任务按北京时间 |
| 失败告警 | 每日流水线失败发送"失败"邮件 | 不能悄悄断掉 |
| 指标口径 | 按"发布天数"归一化对比 | 新老视频可比 |
| 测试 | pytest + mock API（离线可跑） | verify.sh 不依赖真实 key |
| 备份 | SQLite 热备份 + 快照 | 防备份出坏库 |
| 流水线幂等 | 同一天重复运行不生成重复内容/不重复发邮件；中断可续跑 | 可靠性 |
| 手动触发 | Web"立即运行今日流水线"按钮 | 失败/提前看时一键触发 |
| 转写校对 | 转写后 AI 结合文案自动修正行业词 + 作者抽查 | 提高转写质量 |
| 数据保留 | 热点快照保留 30 天；指标全留；视频可压缩/冷归档 | 控制存储增长 |
| 邮件增强 | 每条选题带"去工作台"链接（手机点开直达改稿） | C2 |
| 更新脚本 | NAS 一键更新：git pull + 重建 + 健康检查 | C3 |
| 表现加权 | 人设学习按视频表现加权（表现好的风格权重高） | M5，C1 |
| 备份 | 定时快照 SQLite + `docs/` + `requirements/` + 视频文件 | 核心资产 |

### 工程标准（五维质量约束，M0 起强制，写入 AGENTS.md 硬性规则）
| 维度 | 执行方式 |
|---|---|
| 简单 | 单进程单体不过度设计；新增依赖必须说明理由；拒绝重复代码；路由薄、业务厚 |
| 易读 | 统一风格（Python: ruff；前端: ESLint/Prettier）+ 类型标注 + 小函数 + 清晰命名 |
| 可靠 | 测试覆盖（pytest + mock，离线可跑）+ 统一异常/重试/降级 + 日志 + 失败告警 + 备份 |
| 扩展性 | 适配器模式（LLM/ASR/热点/指标/推送）+ 分层依赖方向（api→services→models，不反向）+ 接口契约稳定（Pydantic） |
| 性能 | 异步 IO + SQLite 索引 + 分页 + 长任务后台线程不阻塞 UI + 前端按需加载；单用户目标：低内存、低延迟 |

**质量门禁**：`scripts/verify.sh` 必须通过 lint + 类型检查 + 测试 + 构建，任何改动（含 AI 改动）不通过不算完成。

## 6. 数据模型（概要）
- `videos`（视频、封面 `cover_path`、**平台/赛道多选 `platforms`/`main_topics`**、状态：计划中/已发布、计划/实际发布时间、广告标记、标签）
- `transcripts`（转写稿、原始文案）
- `persona_tags`（标签+描述、来源：AI建议/手动、版本、确认状态）
- `hot_topics`（每日热点快照）
- `drafts`（生成的标题/封面字/脚本（Markdown 富文本）、平台外壳、作者改写记录）
- `metrics_snapshots`（每日指标快照，可回溯）
- `feedback`（打分、采用标记）
- `review_reports`（复盘报告）
- `requirements`（需求编号、原文、状态、渠道、关联）
- `chat_conversations`（会话：标题、创建/更新时间；M6，R-017）
- `notifications`（通知：任务类型/状态/文案/目标页/已读；M7，R-019）
- `chat_messages`（AI 对话历史：角色、内容、时间、**会话归属 conversation_id**）

## 7. 验收标准（Definition of Done）
- [ ] M0：项目自描述体系就位；`requirements/` 归档机制启用（编号/状态/可追溯）
