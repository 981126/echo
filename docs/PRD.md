# PRD — 自媒体复盘纠错平台（echo）

> 状态：`已实现主体`（M0–M52 已完成/部分推进中，见 milestones）
> 最后更新：2026-09-30（R-219 同步进度可见性 ✅；R-220 素材库切页遮罩必现 ✅）｜ 用户：单人（作者本人，程序员，会用 AI 工具）
> 需求原文：`requirements/`（事实源）；本文为产品范围与验收的总纲。

## 1. 背景与目标
作者在抖音 / B站 / 小红书发布 1~2 分钟纯口播短视频（求职、面试、赚钱、知识赛道，仍在试错），已有数十条历史视频。
系统目标：让 AI 越来越懂作者的人设——
- 每天自动产出与「人设 × 当日热点」匹配的选题与脚本；
- 对已发布内容做数据复盘纠错（平台数据 + 评论 + 归因 + 建议 + 赛道方向）；
- 辅助作者找到适合自己的赛道。

## 2. 非目标（明确不做）
- 不做多用户/账号体系（单用户，局域网/NAS 使用）
- 不做自动发布、不做视频自动剪辑/封面自动生成（封面作者上传，转写建议时间点为加分项）
- 不做移动端 App；Web 做响应式（手机浏览器可用）——**R-218 全站兑现（含导航重构为底部 Tab，320px 起，见 §3.13）**
- 暂不接入 WorkBuddy / 微信通道（未来扩展）
- ~~平台同步不下载视频（D-027，已被 R-077/R-085 取代：每日同步会下载低清视频并自动转写 15 条）~~ 云端作品用于选题/对标；素材卡「同步数据」可按需下载视频（低清）并自动转写（R-077 ✅：抖音/小红书可用，B站受 TikHub 端点 404 限制暂不可用）

## 3. 功能范围与现状

### 3.1 项目自描述体系（M0 ✅）

### 3.2 内容库（素材）与转写
- 本地素材：Web 上传 + `inbox` 拖入自动入库（watcher 10s，R-033 起入库不自动转写）

- 标题/封面落盘统一「标题-视频/封面」命名（R-058 ✅）；删除素材同步清理文件
- 素材库卡片：本地+云端合一展示；封面/标签/平台三行指标占位；同排等高；点赞筛选；本地评论 tab（R-037 ✅）；编辑页封面替换+点击封面播放（R-121 ✅）；云端卡片平台名可点击跳转对应平台作品页（R-111 ✅）；广告标记合并本地素材的 is_ad（R-112 ✅）；卡片「同步数据」（R-067 ✅：绑定平台全同步 + 评论点赞 Top50）；非主博主（对标）素材的编辑页 ASR「已转写」旁提供「洗稿」（R-152/R-153 ✅，行为同博主对标页；卡片列表上不放入口）；**R-179 ✅ 加载提速：服务端统一列表 `GET /api/library` 分页（每批 20、距底 1 屏预取、游标稳定）+ 筛选/搜索/计数下推 + 封面缩略图（`/covers/x.jpg?w=400`，Pillow 按需生成并缓存、启动后台预热）；实测：首屏请求 1.63MB→42KB、首屏封面 13.15MB→486KB、DOM 24k→1.1k、长任务 616ms→0，卡片数合计与旧口径逐条一致**
- 素材库筛选栏（R-198 ✅）：下拉默认态=「不筛选」，触发器按**字段名灰字**展示（`FilterValue`：默认 `text-muted-foreground`、选中具体值才恢复正常前景色），字段文案统一为「博主（默认当前主博主）/ 平台 / 发布状态 / 有无视频 / 是否广告 / 标签 / ≥点赞 / ≤点赞」；下拉内保留「全部」项用于取消筛选；六个筛选项一律「点【查询】才生效」（R-199 ✅：查询 key 收敛为 `applied`，只切博主下拉不再发空请求）
- 素材库换批动效（R-199 ✅）：切博主/改筛选查询后，**旧卡先退场（0.18s）→ 新结果逐张飞入**（基础延迟 0.2s + 每张 0.018s 错峰、一屏 20 张铺满约 0.9s），令牌 `lib/motion.ts#listReplace`
- 素材卡「同步数据」补齐媒体（R-077/R-078 ✅）：数据同步后检查本地视频文件+转写，缺视频则从平台下载（低清；抖音/小红书走 TikHub，B站 TikHub 404 时回落 yt-dlp 直连），下载完自动触发转写（后台任务+通知）；已有则跳过
- 平台/赛道多选（platforms/main_topics JSON）；广告打标后不参与人设/风格学习

### 3.4 每日热点、选题与生成
- 热点：真实源（R-065 ✅：TikHub 热搜，抖音/B站/小红书），来源/话题缺口/换一批
- 每日流水线：热点→关键词命中匹配（可 LLM）→ 生成 ≥3 选题+脚本 → 入库幂等 →（邮件，可关）
- 每日三槽生成（R-073 ✅）：候选=评论区 1（人设筛选）+ 热榜 1（人设匹配）+ AI 建议 1（人设/热榜/评论高频/赛道缺口），缺源回退补足；TopicCandidate 记来源 slot
- 生成上下文：人设(标签/描述/红线/禁词) + 风格画像 + 检索加权样本 + 金句/最佳实践 + 对标风格卡；模型由「AI 设置 → 模型设置」的**生成方/评审方**两个下拉决定（R-138/R-139，可相同；`generation_model` 旧配置自动迁移）
- 双模型讨论（R-023 ✅ / R-139 统一）：生成方初稿 → 评审方 N 轮挑刺 → 生成方修订 → 自检收口，全程留痕 `draft_discussions`；轮次取「AI 设置」的讨论轮次（1–10）；单侧失败自动换另一位，初稿也失败才回落 mock；**R-178 ✅：留痕/状态条/草稿卡片/编辑 tab 全部显示并记录「真实模型 + 版本」（`DeepSeek · deepseek-flash`，实际出结果为准），每次讨论留运行头（当时配置的生成方/评审方 + 轮次 + 是否降级），历史留痕显示「未记录模型（历史）」不伪造**

### 3.11 口播生产工具：提词器 + 内置网页录像（R-214 / R-215 ✅）
> 起因（作者现场照片）：镜头架在行李箱顶上、稿子在镜头后方显示器里，看镜头看不到字、看字眼睛下垂 → 眼睛必然乱飘。
> 做法：把笔记本摆在镜头正下方，用系统里的稿子做全屏提词，并且**就在同一个页面把视频录下来**（不用再去相机→卡→剪映倒腾）。
- **入口**：脚本工作台草稿抽屉「口播脚本」标题行【提词器】（正文非空可点；进入前先补存当前改动，保证提词的就是眼前这版）。
- **全屏提词页**（`#/prompter/:draftId`，顶层路由、无导航/顶栏，`Esc` 回草稿列表）：纯黑底暖白大字（默认 56px，28–120 可调）、行距 1.4–2.4、
  **首行贴屏幕上沿**（减小视线下移角）；按空行分段 + 当前段高亮（**只换字色**，正文区零动画）；`rAF` 恒速滚动 + 快捷键
  （空格播放/暂停 · ↑↓ 手动 · `±` 字号 · `[`/`]` 速度 · `M` 镜像 · `R` 回开头 · `Esc` 退出 · `?` 快捷键面板）；
  镜像翻转 `scaleX(-1)`（留给分光镜式硬件提词器）；已录时长 + 按 4 字/秒预估的剩余/全长；设置刷新后沿用；控制条 3s 无操作淡出、移动鼠标唤醒。
- **内置录像**（与提词同页，边看字边录）：`getUserMedia` 取摄像头（默认优先 Ace Pro UVC，1080p）与内置麦 → 3 秒倒计时（可跳过/可调）→
  `MediaRecorder` 录制 → 空格停止（**录制中空格=停止，优先于播放/暂停**）→ 内联回放 +【重录】/【下载】/【存入素材库】（复用素材库上传接口，
  **不自动转写**）；**状态带明示实际录制格式**（mp4 或 webm）；单次超 5 分钟自动停；`Esc`=停止并退出。
- **只读稿子**：提词页不改稿、不回写、不标记已用（是否采用仍在草稿页决定）。
- **明确不做**：语音跟读（R-216 下一版）、手机/粘贴任意文字的入口、云转码/强制 MP4、分段重录拼接、多机位、美颜滤镜、提词页内改稿。
- **已知限制（界面上对作者明示）**：Chrome 的 `mp4/avc1` 有产出损坏文件的已知缺陷，**WebM 是可靠基线**（MP4 录后校验异常会自动退回 WebM 重录）；
  WebM 在剪映/PR 里不如 MP4 顺（本期不做云转码）；内置麦有房间噪音（正式录制建议换 USB/无线麦）；画质上限 = 相机 UVC 输出。
- **成本/依赖**：纯前端，零云服务、零 LLM 成本、**后端零改动**（无新接口/新表/新定时任务）。

### 3.14 同步进度可见性（R-219 ✅）
- **背景**：博主管理页 sync-all 并发消费时，先完成的博主进度条瞬间消失，与「还在转圈」的整批状态矛盾；被跳过的博主（已在运行/无启用账号）无声无息。
- **规则**：
  - **完成不瞬删**：done 的同步条停留约 8s（绿条「同步完成」+ 进度 100%）后淡出；failed 停留约 60s（红条 + 失败原因摘要）。历史旧记录（超阈值）打开页面不误显示。
  - **排队可见**：批次内未开始博主持续显示「排队中…」条（R-163 已预置 job，保持不回退）。
  - **跳过可见**：被 skip 博主卡片下显示灰色提示条注明原因；该博主开跑或下次 sync-all 后移除；`/api/platform/sync-all` 的 `skipped` 改结构化 `[{creator_id, name, reason}]`。
- **范围不变**：sync-all 批次仍只含「当前主博主+其对标」（R-162 口径）；单博主同步的懒建 job 行为不动；`/api/platform/jobs` 契约不变（前端改为拉最近全状态任务）。
- **动效（R-175）**：新增 done/failed 形态沿用展开/收起动效，收口 `opacity 1`；跳过提示条软入场（不从 `opacity:0` 起步）。
- **验收**：并发下先完成者变绿条延迟淡出；失败者红条停留；跳过者有灰条；`test_r162` 更新全绿；`verify.sh` 全绿。详见 `requirements/R-219-sync-progress-visibility.md`。

### 3.15 素材库切页同步遮罩必现（R-220 ✅）
- **背景**：博主管理点「同步」后切素材库，卡片同步遮罩时有时无——根因是恢复扫描与 `/api/library` 竞速：冷缓存时扫描先回、卡片为空，任务匹配不到卡片被**静默丢弃且永不重试**；热缓存才有动画。叠加跨页 SSE 丢失、恢复查询只筛 running。
- **规则**：恢复扫描/SSE 的未匹配任务进「未认领池」，**卡片数据每次变化（首帧到位/翻页加载）自动重映射补挂遮罩**；恢复查询纳入 `pending`；终态/已认领出池。
- **范围不变**：后端零改动（`/api/tasks` 已支持多值 status）；不做服务端 SSE 回放；「作品列表未拉完前素材库无卡片可显示」的空窗由顶栏「进行中 N」负责（数据依赖，非 bug）。
- **验收**：冷缓存切页遮罩必现、翻页补挂、pending 恢复、无幽灵转圈；vitest 纯函数单测 + headless r220 竞速点检；`verify.sh` 全绿。详见 `requirements/R-220-library-sync-mask-recovery.md`。
