## 一、需求背景

### 1.1 现在的情况（小白也能看懂）

素材库每张卡片现在只显示一行「平台色点 + 最大播放量 + 最大点赞 + 日期」——把各平台的数据混在一起，看不出**哪个平台**的数据是多少。作者截图圈出的就是这一行。

实际数据（现有接口 `GET /api/library` 的 `cloudPosts[].latest_stat`）已经**按平台**返回了播放、点赞、收藏、评论、转发的数值，只是前端没有逐个平台展示。

另外有些平台接口本身拿不到某些字段（实测）：

| 平台 | 播放量 | 点赞 | 收藏 | 评论 | 转发 |
|---|---|---|---|---|---|
| 抖音 | ✅（创作者中心/统计接口可信；公开接口恒 0 视为未知） | ✅ | ✅ | ✅ | ✅ |
| B站 | ✅ | ✅ | ✅ | ✅ | ❌ 接口不返回 |
| 小红书 | ❌ 接口播放量恒 0（408 条里 405 条为 0） | ✅ | ✅ | ✅ | ✅ |

### 1.2 想解决什么

- 一张卡里**按平台分行**展示三个平台的数据：抖音 / B站 / 小红书各一行；
- 每行展示 5 个指标：**播放量、点赞、收藏、评论、转发**；
- **没有发布视频的平台不出现对应行**（只显示已发布的平台）；
- **接口没有的字段置灰显示「-」**（例如 B站转发量、小红书播放量）；
- 原有日期、标签、封面、操作按钮都保留。

## 二、想要实现的目标

| 目标 | 可验收标准 |
|---|---|
| 逐平台分行 | 卡片信息区显示一张小表：表头「播放 / 点赞 / 收藏 / 评论 / 转发」，下面每个**已发布平台**一行；3 平台卡 3 行、2 平台卡 2 行、1 平台卡 1 行 |
| 5 项指标 | 每行 5 个数：播放、点赞、收藏、评论、转发；大数字沿用现有缩写（1.8w / 1.2k / 388） |
| 未发布平台不出现 | 卡片没有某平台作品时，该平台行不渲染（例：只有抖音的卡不出现 B站/小红书行） |
| 缺数据置灰 | 接口没有的指标显示灰色「-」：B站行「转发」、小红书行「播放量」；抖音播放量在公开接口未知（`plays_known=false` 且为 0）时也置灰「-」；其余真实 0 显示「0」 |
| 不破坏卡片 | 封面 4:3、平台/云端/广告角标、标题两行、标签、操作行、hover 播放、多选、点击进详情、换批动画全部不变；卡片高度仍由内容决定（瀑布流自动适配） |
| 不引入新问题 | 1280/1440/1920 桌面与 768 平板无文字溢出、无横向滚动、0 console error；<768 手机保留原聚合行（表格放不下） |

## 三、页面数据来源（本次不改接口）

| 展示项 | 数据来源 | 原始字段 | 更新时机 | 缺失/失败表现 |
|---|---|---|---|---|
| 平台行 | `GET /api/library` 卡片 `cloudPosts[].platform` | `platform` = douyin / bilibili / xiaohongshu | 随卡片数据（进入/筛选/查询/触底加载） | 平台无作品 → 不渲染该行 |
| 播放量/点赞/收藏/评论/转发 | 同一接口 `cloudPosts[].latest_stat` | `plays` / `likes` / `favorites` / `comments` / `shares` | 平台数据同步后（卡片缓存 20s） | 无 `latest_stat` → 该行全部「-」；平台接口无该字段 → 该列「-」 |
| 播放量可信标记 | `latest_stat.plays_known` / `plays_source` | `plays_known`（抖音公开接口为 false） | 随数据 | false 且值为 0 → 「-」 |
| 日期 | 卡片 `date` | 作品发布时间 | 随数据 | 空 → 不显示日期 |

前端只做展示，**不新增/修改任何接口、请求参数或数据库字段**。

## 四、功能需求

### 4.1 卡片信息区新增逐平台指标表

- 位置：标题下方（原「平台色点 + 播放 + 点赞 + 日期」聚合行所在位置）；
- 表格：表头一行（播放 / 点赞 / 收藏 / 评论 / 转发，浅灰小字）；每行开头是平台色点 + 平台名（抖音 / B站 / 小红书），后面 5 列数值右对齐；
- 平台行顺序固定：**抖音 → B站 → 小红书**；只显示卡片已发布的平台；
- 数值格式沿用全局 `fmtNum`（17621 → 1.8w、1184 → 1.2k、42 → 42）；
- 日期移到标签行最右侧（没有标签时该行只显示日期）。

### 4.2 缺数据置灰「-」

| 场景 | 表现 |
|---|---|
| B站「转发」 | 置灰「-」（接口不返回转发；若个别作品有值 >0 仍展示数字） |
| 小红书「播放量」 | 置灰「-」（接口播放量恒 0；若个别作品有值 >0 仍展示数字） |
| 抖音「播放量」 | `plays_known=false` 且值为 0（公开接口拿不到）→ 置灰「-」 |
| 某平台没有 `latest_stat`（还没同步到数据） | 该平台整行 5 列全部置灰「-」，但行仍显示（说明已发布、暂无数据） |
| 其他真实 0 值 | 正常显示「0」（不置灰） |

置灰样式：`text-muted-foreground/40`；正常数值 `text-foreground/80`。

### 4.3 边界与不做

| 项 | 处理 |
|---|---|
| 本地素材（无云端作品数据） | 不显示指标表，保留原「平台色点 + 播放/点赞」聚合行 + 日期 |
| 移动端（<768px） | 卡片宽度放不下 6 列表格 → 保留原聚合行（色点 + 最大播放 + 最大点赞）+ 日期；桌面与平板（≥768）显示表格 |
| 同平台多条作品（异常/手动合并） | 取互动（赞+藏+评+转）最高的一条展示 |
| 不改 | 封面比例/兜底、平台角标、标题、标签、操作行、筛选/分页/排序、换批动画、后端与表结构 |

## 五、用户故事

1. **作为** 同时把视频发到抖音/B站/小红书的作者，**我希望** 在素材库卡片上按平台看到播放、点赞、收藏、评论、转发的具体数字，**这样** 不用逐个平台切后台就能比较哪边数据好。
2. **作为** 只发抖音的作者，**我希望** 卡片只显示抖音那一行，**这样** 不会看到一堆空行或别的平台数据。
3. **作为** 知道 B站接口没有转发量的作者，**我希望** 那一格显示灰色的「-」，**这样** 我不会把 0 误当成真的没人转发。
4. **作为** 在户外偶尔用手机翻素材的作者，**我希望** 手机版仍保持原来的紧凑信息行、不挤成一团，**这样** 卡片依然好读。
