## 1. 需求背景

后端已做过两轮性能优化，但前端仍是「慢、卡、闪」的主要来源。三路独立审计（只读 + Playwright 生产构建实测）确认：

1. **全站无 gzip/br 压缩，hashed 静态资源无长期缓存**：首屏 JS+CSS 740KB（gzip 后 228KB，-69%）；`/api/works` 1.6MB（-87%）、`/api/benchmark/top` 302KB（-62%）。
2. **封面/头像原图直出**：对标页 44 张封面合计 4.25MB（显示仅 255×191）、博主管理图片约 4.2MB（46×46 时间线也用原图、40px 头像单张 301KB）；后端已有缩略图能力但前端未用。
3. **首屏布局乱动**：侧栏 `motion.aside` 无 `initial={false}`，每次刷新内容从 ~135px 被动画推到 216px，四页 CLS 0.045~0.056；用户描述的「组件乱动」即此。
4. **persona 页 46 行标签每次父级渲染全部卸载重挂**：`TagRow` 定义在页面组件内部（每次渲染都是新组件类型），点「多选」正常 CPU 长任务 83~97ms、弱机 358ms；后台任务 SSE 每来一条就 46 add/46 rem。
5. **脚本工作台首屏重**：进入页面即加载 tiptap+markdown 约 600KB（编辑器未打开）；列表 `/api/drafts?limit=500` 483KB，其中 118 条已删除占约 79% 字节；每次按键两次全量 markdown 序列化 + 每键同步写 localStorage。
6. **chat 流式卡顿**：后端约 66 次/s 下发 chunk，前端每 chunk 全量 setState + 全文 markdown 重解析 + 滚动计算；弱机（4× CPU 节流）13 个长任务/最大 155ms。
7. **其他**：素材库无限滚动追加时尾部提示被顶出视口（滚动 CLS 合计 0.237）；对标页 90 个 `backdrop-filter` 合成层；博主管理每 4s 拉 44KB jobs；视频复盘首屏 3 个请求串行；视频编辑抽屉两请求串行、转写轮询不随关闭停止。

## 2. 想要实现的目标

### 2.1 核心目标（可验收）

| 项 | 目标 | 验收 |
|---|---|---|
| 传输压缩 | 全站 JSON/HTML/JS/CSS 走 gzip（SSE 除外）；hashed 静态资源 immutable 长期缓存 | 响应头有 `content-encoding: gzip`；同一 API 传输字节对比基线下降 ≥60%；`/assets/*.js` 有 `cache-control: ...immutable` |
| 图片缩略 | 所有 `/covers/` 图片按显示尺寸走 `?w=`（卡片 400、时间线/头像 160） | 对标页图片传输 4.25MB→≤1.2MB；博主管理≤1.5MB；thumbnail 生成不可用时回退已预热 w400，不回落原图 |
| 首屏不横向乱动 | 侧栏首帧不再播放宽度动画 | 四页 CLS 从 0.045~0.056 降到 <0.02；首屏主内容 x 坐标稳定 |
| persona 列表稳定 | 标签行不再因父级渲染而卸载/重挂 | 点击「多选」/SSE 事件不再整列表重建（DOM 节点 0 added 或仅变动行）；长任务 <20ms（本机） |
| 草稿页首屏 | 未打开编辑器时不加载 tiptap/markdown；列表默认不含已删除草稿 | 草稿页首开传输 1.14MB→≤250KB；`/api/drafts` 默认响应 483KB→≤120KB（132→14 行） |
| 编辑不卡键 | 打字每键只做一次 markdown 序列化；localStorage 写放在防抖后 | 每键 JS 工作量减半（实测 11~48ms→<10ms，dev 口径） |
| 素材库滚动 | 追加批次时尾部提示/计数不再引起视口位移 | 连续滚 10 批 CLS <0.02（基线 0.237） |
| chat 流式 | 每帧最多一次状态更新，最终内容与现在逐字一致 | 4× CPU 节流 974 字回复长任务 ≤2 个（基线 13 个）；最终消息文本/格式不变 |
| 少量请求串行 | 视频复盘首屏、chat 切会话、视频编辑抽屉改为并行请求 | 请求瀑布中无互相等待的独立请求；数据与错误语义不变 |

### 2.2 明确不做（保持逻辑/动画不变）

- 不改任何动画参数/曲线/时长/编排（侧栏收起 spring、卡片入场、页面转场 blur 淡入、列表换批动画全部保留）；只修「非设计意图的首帧误播」与组件身份不稳定。
- 不改页面路由、交互流程、字段契约；不做虚拟列表（会改变滚动锚点与 popLayout 动画观感）。
- 不做需要产品确认的视觉改动：骨架屏只对齐真实高度，不改布局结构；对标页徽标仅去掉 `backdrop-blur`（底色不变，可读性不变）。
- 不调整页面转场 blur 动画（需作者确认后才可改）。
- 不合并接口（如 `/api/active-work`）、不做 prompt keys lite、不做 benchmark/top 文案懒加载（列入后续批次）。
- 不动后端业务逻辑/数据库结构；只有传输中间件、静态缓存、列表默认过滤、只读接口可选瘦身参数。

## 4. 功能需求（行为不变，性能变化）

1. **传输**：所有浏览器可接受的响应自动压缩（图片/视频等已压缩格式不重复压缩）；SSE `/api/events` 不压缩、保持逐事件推送；静态 hashed 资源带长缓存，`index.html` 必须每次回源校验（发版即时生效）。
2. **图片**：
   - 素材卡（已有）继续 400 宽缩略图；博主对标封面 400；时间线 46px 封面与 40px 头像 160；
   - 添加 `loading="lazy"`（已有保持）、`decoding="async"`；
   - 后端缩略图生成失败时回退已预热的 400 宽缩略图（仍无则原图），不报错。
3. **persona 页**：标签行组件提升为模块级稳定组件；所有按钮/选择/编辑/删除行为、`layout` 动画与入场动画不变。
4. **脚本工作台**：
   - 编辑器组件按需加载（进入页面不加载 tiptap/markdown；空闲时预取，点开秒开）；编辑器视觉/动画/自动保存逻辑不变；
   - 列表接口默认排除 `status=deleted`（逻辑删除不再出现在工作台；需要时 `include_deleted=true` 可查）；
   - 打字：过滤「自己刚发出的 markdown」避免重复序列化；本地副本/指纹计算放入 900ms 防抖，不改变自动保存触发与落库语义。
5. **素材库**：无限滚动提前一屏预取，减少尾部被顶出视口的位移；`content-visibility` 的预估卡高修正为真实高度（视觉/滚动行为不变）。
6. **chat**：流式 chunk 合并到每帧最多一次渲染；会话切换两个只读请求并行 + 过期响应丢弃；最终消息内容、打字机观感、消息动画不变。
7. **其他页面**：
   - 对标页徽标去掉 `backdrop-blur`（不改变文字/底色）；
   - 博主管理 jobs 轮询：无进行中任务时降低频率（4s→15s），有进行中保持 4s；
   - 视频复盘首屏 references 与 review 并行；视频编辑抽屉详情与关联草稿并行、转写轮询仅抽屉打开时进行。

## 5. 用户故事

1. 作为作者，我刷新任何页面时，主内容不应先窄后宽地横向滑动；侧栏收起/展开的动画要保留。
2. 作为作者，我打开「人设档案」点几个标签或后台任务在跑时，页面不应整片闪烁/卡顿，标签列表不应重放入场动画。
3. 作为作者，我打开「脚本工作台」时页面应很快可交互，不必等编辑器代码加载；点开草稿后编辑器仍按原有动画滑出、自动保存照旧。
4. 作为作者，我在长稿里连续打字应跟手，不应每键明显停顿；断网时本地副本仍会保留（最多延迟到自动保存防抖窗口）。
5. 作为作者，我滚动素材库加载更多时，底部提示/计数不应突然跳走；滚动过程要顺。
6. 作为作者，我在 AI 聊天的流式回复中不应看到卡顿掉帧，消息内容和打字机效果保持原样；快速切换会话不应先显示上一个会话内容或串会话。
7. 作为作者，我打开对标/博主管理页时图片应快速出现，不因加载几十张几 MB 原图而白屏/卡顿。
