## 反问与澄清（8 项清单）
作者确认按推荐默认实现：
1. **范围**：「一键拒绝」= 待确认建议区加「一键拒绝建议」按钮（与一键确认并列），全部待确认建议标为已拒绝（留痕，不彻底删除）；已确认档案多选只做删除，不做合并/同步。
2. **场景**：待确认建议量大（当前 521 条）需批量拒绝；已确认档案（当前 226 条）需批量清理。
3. **数据**：无新数据；只更新 status 与删除 PersonaTag 行。
4. **边界**：空列表隐藏按钮/不操作；一键拒绝与删除所选均有确认弹窗；批量删除只删当前主博主标签，忽略不存在/他人标签。
5. **验收**：UI 可一键拒绝并提示条数；多选悬浮条同素材库样式（右侧中间），可勾选/删除所选/取消；verify 全绿 + 接口冒烟。
6. **成本**：无外部 API 成本，批量单接口完成。
7. **依赖/风险**：无外部服务依赖；删除不可恢复（弹窗提示）。
8. **优先级**：现在做。

## 处理方案（已实施）
- 后端：`POST /api/persona/reject-all`（suggested → rejected）；`POST /api/persona/tags/batch-delete`（按 ids 只删当前博主标签，返回 deleted 数）。
- 前端 PersonaView：「待确认建议」标题旁加「一键拒绝建议」（type=error + 确认弹窗 + loading）；「已确认档案」加多选模式——右侧中间悬浮按钮（同素材库 .merge-float 样式），进入多选后点行/勾选框选择，悬浮条显示已选数量，支持「删除所选」「取消」；多选时隐藏单行编辑/删除按钮。
- 文档：里程碑/CHANGELOG/API.md（92→95 路由）已同步；新增 test_persona_bulk 4 用例。
