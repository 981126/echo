## 反问与确认结论（2026-09-29）
1. **范围**：所有「非实时返回 / 耗时」功能（后端异步任务 + 同步慢接口）都要有可见「进行中」动效；覆盖全部页面。
2. **场景**：发起后切页/刷新回来，只要后端仍在跑，页面必须仍显示「进行中」。
3. **数据**：复用 `background_tasks`（无需新表）；同步慢接口改为后台任务，结果落 `task.result`。
4. **边界**：SSE 断线不重放事件 → 需「挂载回扫 + SSE 增量 + 10s 轮询兜底」三段式；重复点击同 scope 任务直接复用，不重复烧 LLM。
5. **验收**：headless 实测「发起 → 切页 → 回来仍有动画 + 顶栏计数 → 完成出结果」；动效美观流畅、无空白闪帧。
6. **成本/性能**：任务体系已有；轮询仅在有进行中任务时开启。
7. **依赖/风险**：SSE 是既有通道（`/api/events`），单进程；不引入 WebSocket。
8. **优先级**：现在做，拆 M191 / M192。
9. **动效（R-175/R-202）**：本条本身就是动效硬性规范。

### 作者拍板
- 同步慢接口：**改成后台任务**。
- 全局指示器：**要**（顶栏「进行中 N」）。
- 覆盖范围：**一次性全部页面**。
- 推送机制：**沿用 SSE**（非 WebSocket）；指示器近实时 + 轮询兜底。

## 规范（写入 AGENTS）
- 凡「非实时返回 / 耗时」功能，必须给出可见「进行中」动效（spinner/进度条/覆盖层/顶栏计数），完成/失败干净落定。
- 切页/刷新回来后，只要后端仍在跑，页面**必须**仍是进行中动效——绝不允许卸载即消失造成「已完成」错觉。
- 动效统一用 `lib/motion.ts` 令牌，禁止从 `opacity:0` 起步（R-175），收口 `opacity 1 / transform none`。
- 红线：不满足 = 功能不算完成。

## 做法
- **M191**：后端 `/api/tasks` 多状态过滤 + `TaskOut.label/target`（抽 `core/task_meta.py`）；前端 `ActiveWorkProvider`（回扫+SSE+10s 兜底）+ 顶栏「进行中 N」；对标/AI设置/人设/灵感随手记恢复进行中态。
- **M192**：8 个同步慢接口转后台任务（`benchmark_prepare`/`opportunity_clusters`/`opportunity_weekly`/`opportunity_gap`/`draft_angles`/`prompt_optimize`/`hot_refresh`/`publish_backfill`），结果落 `task.result`、去重；前端按 scope 消费并切页恢复。
