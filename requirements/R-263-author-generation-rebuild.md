## 一、需求背景

### 1.1 作者遇到的问题

现在的生成文案看似有开头、论点、案例和结尾，但没有先想清楚「这篇到底要说什么、为什么这么说、建议在这个场景下是否可行」。因此会出现正确但无用的套话、前后矛盾、常识错误和强行吸引人的标题。

作者给出的说明例子是：**「我要洗车，洗车店距离我 50 米，我开车去还是走路去？」** 这个例子仅用于说明系统必须先识别真实目标和必要条件，不能只按距离套「近距离就走路」的模板，不是固定验收场景。

同时，文案没有充分吸收作者自己的表达、经历、观点和真实改稿，导致不像作者本人，也无法直接录制。

### 1.2 已核实的现状

以下是对当前开发库与代码的只读排查结果，不是猜测：

- 当前主博主为「陈皮的使用手册」（`creator_id=1`），有 77 个非广告视频、71 篇可用 ASR，合计约 39,909 字。
- 系统**没有训练或微调模型**。现有做法主要是统计语言风格，再在每次生成时检索若干 ASR 片段。
- 最近生成每篇大约使用 5 篇 ASR 的开头各 400 字，加 4 个相关片段、每段最多 400 字，合计约 3,296～3,491 字。内容存在重复，也会召回与主题无关的片段。
- 这相当于「临时给模型看几段文字」，并没有把 ASR 整理成可检索、可引用、可持续更新的作者知识。
- 现有生成方与评审方都配置为 `model2 = kimi/kimi-k2.6`，讨论轮次为 3；`model1 = deepseek-flash`。
- 最近 6 篇非 mock 生成中，4 篇 `rounds_done=0` 却仍显示 `passed=true`，质量通过与实际执行不一致。
- 现有评审主要检查口吻、AI 感、论点数量、案例和空话，不检查目标约束、常识、因果与建议可执行性。
- 模型全部失败时会留下固定三点式 mock 文案；它不是作者内容，不应作为正常生成结果。
- R-254 允许把参考素材中的经历、数字等写成作者本人并继续扩写。本次明确收回这项规则在**普通生成**中的权限：可以参考和作者化表达，但不能虚构作者经历、数字与因果。

### 1.3 为什么保留人设档案

人设档案和内容资产不是一回事，二者都保留：

- **人设档案**回答「我是谁、相信什么、不能说什么」：稳定身份、价值观、立场、表达边界和红线。
- **作者内容资产**回答「我说过什么、经历过什么、怎样论证、怎样组织内容」：事实、观点、经历、结构和表达经验。

只有人设，容易写成「像某类博主」；只有 ASR，又容易随单篇素材漂移。两者结合才更接近作者本人。

## 二、想要实现的目标

| 目标 | 可验收结果 |
|---|---|
| 先想明白再写 | 每篇先形成唯一核心承诺、受众、切入角度、推理步骤和证据，再写正文；不能直接套三点式模板 |
| 符合常识与目标约束 | 建议必须满足用户真正目标、对象、前提和物理条件，且能由目标对象实际执行 |
| 真正利用 ASR | 把主博主 ASR 自动整理成事实、观点、经历、结构、表达五类可引用资产；生成时能说明用了哪些内容，不再只截取文章开头 |
| 像作者本人 | 使用作者真实观点、经历和表达习惯；不机械塞口头禅，不把对标或网络素材冒充作者经历 |
| 有吸引力且兑现承诺 | 开头提出具体矛盾、结果或问题，正文必须兑现；不为点击而夸大，不承诺必爆款 |
| 事实可信 | 作者经历只能来自作者 ASR、作者输入或作者确认过的改稿；数字与外部事实可追溯；禁止虚构因果 |
| 质量结果真实 | 未执行评审、评审失败、模型失败、mock、无合格角度均不得显示「质量通过」；正式结果中不再出现 mock 稿 |
| 少操作、少菜单 | 默认自动推荐最佳角度并一键生成；需要时才展开角度、素材依据和评审细节；不新增一级菜单，不增加必选步骤 |
| 越用越像作者 | 作者改稿、完成/不采用、发布后的真实 ASR 与表现进入后续学习；事实与人设不能因一次反馈被自动篡改 |
| 老实现彻底退出 | 普通生成旧链路、旧页面状态与废弃代码全部删除；确认废弃的表通过 Alembic 删除；有效数据先迁移、备份并核对，共享表不误删 |

### 2.1 明确不做

- 不顺带重建洗稿，不能为了删旧代码破坏对标洗稿与历史原文讨论。
- 不新增「事实库、观点库、经历库、结构库、表达库」五套页面，也不要求作者手工维护素材。
- 不引入新一级菜单、模型训练平台、向量数据库或复杂任务编排框架。
- 不保留「新旧生成随意切换」开关，不写兼容包装继续调用旧算法。
- 不用模型自评分代替作者验收，不把「生成了文字」当成「质量通过」。

## 四、功能需求

### 4.1 自动建设作者内容资产，不增加维护负担

系统在后台把 ASR 和有效反馈整理为五类**逻辑资产**，不是五个菜单：

1. **事实**：作者的身份背景、稳定偏好、已发生事实及适用条件。
2. **观点**：作者对事情的真实判断、理由、边界与例外。
3. **经历**：发生了什么、当时目标、采取的行动、结果与复盘。
4. **结构**：作者怎样开头、提出承诺、推进论证、转折与收尾，不保存成死模板。
5. **表达**：句长、节奏、称呼、比喻方式、情绪变化与口语习惯，不等于口头禅清单。

每条资产必须能回到原始 ASR 或作者输入的原文证据。系统按当前主题检索最相关的内容，不再默认塞入多篇 ASR 的开头。作者不需要手工整理。

### 4.2 一键生成的内部顺序

普通生成统一按以下顺序执行：

**整理作者资产 → 生成并筛选角度 → 制作内容蓝图 → 作者化写作 → 逻辑/事实、吸引力、作者感评审 → 必要的一次或两次针对修订 → 真实质量门禁。**

具体要求：

- 一篇只围绕一个核心承诺，不强制 2～4 个论点。
- 默认自动选最佳角度，作者仍可展开查看或换角度，不是必选项。
- 写作前先检查：目标是什么、对象是谁、前提是什么、证据是否支持、建议是否可执行。
- 没有合格角度或缺少决定结论的信息时，可以不生成正文，直接说明原因并询问最关键的信息，不能硬写通用稿。
- 不再以固定「初稿→N 轮互评」为质量目标；评审发现问题才针对问题修订，最多 2 次，避免越改越平。

### 4.3 事实与常识硬规则

- 作者第一人称经历只能来自主博主 ASR、作者本次输入、作者确认过的改稿或明确授权的信息。
- 对标与联网素材只能作为外部案例、事实或观点参考，不能换成人称后冒充作者亲身经历。
- 数字必须来自证据或能展示计算过程的简单计算；禁止为了「具体」而补数字。
- 因果关系必须有证据；只有相关性或个人判断时，正文必须明确说「我认为/可能/在这个条件下」，不能写成确定事实。
- 每条建议必须说明适用对象和关键前提；存在相互冲突的目标时先指出冲突。
- 必须识别达成真实目标所需的对象、状态和必要条件；不能为特定生活例子编写专门答案规则。
- 红线、事实、关键逻辑错误为硬失败，不能靠语言润色覆盖。

### 4.4 吸引力与作者感

- 开头可以使用真实矛盾、具体结果、反常识判断、场景冲突或作者经历，但必须与正文核心承诺一致。
- 标题与封面字可以抓人，不得正文无法兑现，不得制造不存在的结果、身份、收益或恐惧。
- 每一段都要服务于核心承诺；删除不影响意思的套话和重复句。
- 学习作者的组织与表达经验，不机械复制旧稿，不强行加入高频词、口头禅或固定「三个点」。
- 不保证所有话题都具备同等素材基础；素材不足时应补证据或说明，而不是用夸张掩饰空洞。

### 4.5 页面、按钮与字段

本次**不新增一级菜单**，主要改造现有「脚本工作台」和各生成入口。

| 位置 | 功能/按钮/字段 | 用途与表现 |
|---|---|---|
| 所有现有生成入口 | 「生成文案」「生成」「采用」「重新生成」等现有按钮 | 入口和名称尽量不变；全部调用同一新链路，不再进入旧讨论生成 |
| 脚本工作台生成中卡片 | 「整理素材/确定角度/搭建内容/撰写正文/检查质量」阶段 | 显示真实阶段与动效；切页、刷新后恢复；无固定假进度 |
| 草稿抽屉 | 「创作思路」折叠区 | 展示核心承诺、推荐角度、为什么这样切入；默认收起，不增加生成前操作 |
| 草稿抽屉 | 「素材依据」折叠区 | 展示使用的作者资产摘要、原 ASR 出处和外部来源；可区分作者素材与外部素材 |
| 草稿抽屉 | 「质量检查」折叠区 | 展示逻辑与事实、吸引力、作者感三项结果及问题；未执行就是未执行 |
| 草稿抽屉 | 「重新生成」 | 保留当前版本，基于原选题重新运行；作者已手动修改的内容不能无提示覆盖 |
| 无合格角度 | 「补充信息」提示区 | 说明缺什么，最多提出 3 个能改变结论的问题；作者可修改选题后重试 |
| 人设档案 | 现有身份、立场、边界、红线与证据 | 页面保留；补充可追溯证据和适用条件，不变成五类素材管理页 |
| AI 设置 | 新链路所需提示词与实际模型记录 | 沿用现有提示词管理；普通生成的「讨论轮次」设置退出，洗稿设置不被误删 |
| 历史草稿 | 「历史讨论」 | 仅用于已有历史留痕和洗稿；新普通生成展示新创作过程，不再伪造旧讨论格式 |

字段含义：

- **核心承诺**：看完这篇，观众能获得的一个明确结果或判断。
- **推荐角度**：系统认为最值得写、且现有证据能支撑的切入方式。
- **内容蓝图**：正文写作前的推理与结构计划，不是最终文案。
- **素材依据**：某个事实、观点或经历来自哪里；没有出处的内容不得冒充事实。
- **质量通过**：所有硬检查完成且通过、吸引力和作者感达到门槛；不是模型说「可以」就算通过。
- **待补信息**：缺少会改变角度或结论的关键信息，本次没有强行生成。
- **待作者修改**：已有正文，但仍有未解决的质量问题；不能当作正式合格稿推荐。

### 4.6 作者改稿与发布反馈学习

- 保存现有草稿版本，比较 AI 原稿与作者定稿的差异。
- 作者标为完成、实际发布并产生新 ASR 的内容，是学习作者写法的强证据。
- 作者不采用、删除或明确写下的评价，是避免同类问题的依据；不能仅凭一次表现差就推断作者人设改变。
- 播放、点赞等表现只用于辅助排序，必须考虑选题、平台与样本量，不能把高播放直接等同为事实正确或作者偏好。
- 新学习结果不得自动覆盖已确认的人设、事实和红线。

### 4.7 老代码、废弃表与数据删除要求

作者要求本次淘汰的老代码、废弃表全部删掉。执行必须同时满足「删干净」和「不误删」：

1. 先盘点普通生成、洗稿、人设、提示词、历史草稿的依赖，形成确定删除、迁移后删除、共享保留三张清单。
2. 先备份数据库，再迁移有效 ASR 资产、历史草稿、版本、反馈和需要保留的生成留痕，核对数量与抽样内容。
3. 普通生成旧入口、旧讨论链路、mock、自由编造规则、旧质量通过与旧前端状态全部删除，不保留新旧算法切换开关。
4. `draft_discussions` 仍被洗稿和历史讨论使用，`ai_prompts/ai_prompt_defs` 与 `prompt_evals` 被多模块共享，不能整表删除；只清理其中已被替换的普通生成数据与注册项。
5. `videos/transcripts`、`persona_tags`、`drafts/draft_versions/feedback`、有效发布数据必须保留，不能当作旧表误删。
6. 只有确认不再被任何模块使用的物理表，才通过 Alembic 在迁移验证后删除；同步更新 `docs/DATABASE.md`。
7. 删除后全仓搜索旧类、函数、路由、提示词 key、表名和前端字段，除历史需求文档外不得存在运行时代码引用；洗稿回归必须通过。

## 五、验收标准

### 5.1 功能与质量硬门槛

- 所有普通生成入口使用同一新链路；洗稿与共享功能不回归。
- 正式生成结果中 mock 数量为 0；模型失败、0 次评审、阶段缺失均不能 `passed=true`。
- 对 20 个不同领域主题进行真实模型测试，覆盖日常决策、职场、关系、健康常识、消费、财务常识、科技、出行、饮食、教育、家居、数码工具、汽车、运动、法律常识、亲子、时间管理、情绪、公共热点与创作者经营。
- 每篇检查：真实目标、对象、关键前提与物理条件识别正确，核心承诺唯一、开头承诺被正文兑现、推理无关键跳跃、建议满足前提且可执行、事实有出处、无虚构第一人称经历/数字/因果。
- **事实编造为 0，关键常识错误为 0，开头承诺未兑现为 0**；任何一项出现都不能交付为「质量通过」。
- 洗车与只咨询仅是帮助理解目标约束的说明案例，不是单独新增的业务场景或固定交付测试项；不为特定例子编写专门答案规则。
- 无合格角度、缺关键信息、模型失败时，页面状态与提示准确，不生成固定通用稿。

### 5.2 作者盲评

将新稿与现有旧稿混排，隐藏生成方式，由作者按 1～5 分评价：

- 「像不像我本人写的」；
- 「开头和正文是否让我愿意继续看」；
- 「能不能基本直接拿去录」。

目标：20 篇新稿三项平均分均达到 **4/5**，且「能直接录」不得低于 3 分的篇数超过 2 篇。该目标由作者评价确认，不能用模型自评分替代，也不宣称保证爆款。

### 5.3 工程与清理验收

- 数据库有备份、迁移前后计数、证据抽样与回滚方案；共享数据零误删。
- 被替换的普通生成代码和页面无残留；确认废弃的物理表有 Alembic 删除记录，无废弃表仅为「不用了」而继续留库。
- `scripts/verify.sh` 全绿；新增常识、事实证据、质量门禁、资产检索、迁移与洗稿回归测试。
- 真实后端接口冒烟与前端关键交互点检通过；进行中状态切页/刷新可恢复，新交互无空白闪帧。
- 后端 `http://127.0.0.1:8000` 与前端 `http://127.0.0.1:3000` 加载最新代码并可访问。

## 六、用户故事

1. **作为** 输入一个生活问题的作者，**我希望** AI 先理解我的真实目标和限制，**这样** 它不会写出「洗车却把车留在家里」这种没有常识的建议。
2. **作为** 已积累大量 ASR 的博主，**我希望** 系统自动整理并正确使用我的观点、经历和表达，**这样** 新稿不是只学几句口头禅，而是真的像我在思考。
3. **作为** 时间有限的创作者，**我希望** 仍然一键得到推荐稿，需要时才展开思路和依据，**这样** 功能变强但操作不变复杂。
4. **作为** 对内容真实性负责的作者，**我希望** 每个经历、数字和结论都有依据，**这样** 我不会把别人的经历或 AI 编造的内容说成自己的。
5. **作为** 想提高完播和关注的作者，**我希望** 开头有吸引力且正文兑现，**这样** 文案既让人愿意看，也不会变成空洞标题党。
6. **作为** 会亲自改稿的作者，**我希望** 系统学习我最后的改法和真实反馈，**这样** 下一次生成能更接近我的最终作品。
7. **作为** 缺少某些领域素材的作者，**我希望** 系统坦诚告诉我缺什么，**这样** 我得到的是可补全的方向，而不是看似完整的废话。
8. **作为** 继续使用洗稿、人设和历史草稿的作者，**我希望** 清理旧实现时不误删共享数据，**这样** 新系统变干净，已有工作也不丢失。
