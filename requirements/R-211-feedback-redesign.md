# R-211 反馈体系重构（去打分/四维/快速反馈，文本评价 + 状态流转触发学习）

- **日期**: 2026-09-29
- **状态**: ✅ 已完成（M203）
- **关联**: `backend/app/api/drafts.py`、`services/feedback.py`、`services/feedback_analysis.py`（新）、`services/prompt_service.py`、`services/generation.py`、`services/prompt_eval.py`、`models/feedback.py`、`db.py`、`frontend_v2/src/pages/drafts/`；R-020/R-022/R-129/R-131/R-184/R-202/R-209/R-210

## 原文（作者原话，未改动）
> 还有个问题，打分和记反馈也会反馈给ai是吗，关于快速反馈、打分、记反馈是怎么工作的，这些都是只对终稿来评分的是吗，ai它会分析初稿到终稿的改变吗

> 1.打分、钩子、节奏、结尾、像我这些都去掉，改成一个文本框，我可以评价，ai可以学习评价，2.快速反馈点击后，好和差被点过的应该高亮回显，3.ai学习稿子的节点是，当待制作的稿子点击完成，或者快速反馈点击差，都会去分析学习正文以及反馈的文本为什么这篇是是好或者差

> 1.快速反馈功能去掉吧，我想了一下，触发时机应该改成不采用、待制作点击完成，因为点击不采用就表示这篇不好 2.纯人工写的点击不采用不触发学习

> 弃用，并且快速反馈功能也不要了

> 也需要分析，触发节点变了

## 现状排查（重构前事实）
- 反馈绑草稿不绑版本；学习时读草稿**当前正文**（非评分时快照）。
- 快速反馈「差」（`liked=False`）是死信号：没有任何学习通道消费。
- 记反馈的文字留言（`comment`）是死字段：只存库没人读。
- 四维分只在生成上下文当标注；星级 ≥4/≤2 是黄金样本/负向块的主要过滤条件。

## 反问与确认结论（2026-09-29）
1. **卡片控件**：删掉星级打分、四维细分（钩子/节奏/结尾/像我）、快速反馈好/差；改成一个「记反馈」文本框（行内展开，AI 学评价文本）。
2. **学习触发节点**（挂在 `PATCH /api/drafts/{id}` 状态流转上，不阻塞返回）：
   - 进入 `done`（待制作点完成）→ 结论=好 → 后台 LLM 分析「正文+版本链+评价文本」为什么好；
   - 进入 `archived`（不采用/移入废稿）→ 结论=差 → 分析为什么差；**纯人工写的稿点不采用不触发**（复用 R-210 判定）；
   - 没写评价文本也分析（触发的是状态流转本身）；
   - 从废稿恢复为草稿 → 负向信号随 status 自然消失（status 即事实源）。
3. **分析心得落地**：**注入生成上下文**（不做的人设建议那套确认流程）。
4. **历史评分数据**：**弃用**——学习通道改为 status 驱动（正向=done，负向=archived 且非纯手写），不再查 rating/liked。
5. **成本**：每次完成/不采用一次 LLM 调用（模型1，失败降级模型2），成本可忽略；分析失败不阻塞状态流转，留「中断」标记（R-173 机制）。
6. **非实时（R-202）**：分析为后台任务，卡片复用 `draft_status` 状态条显示「学习分析中」，切页/刷新可恢复。
7. **动效（R-175）**：文本框行内展开/收起有动画，收口 opacity 1。

## 做法
- `feedback` 表加 `insight` 列（手写 `_migrate_feedback_insight`）：存 LLM 心得。
- 新服务 `services/feedback_analysis.py`：触发时 upsert 该稿 Feedback 行（结论快照 + 最新 comment），入队分析任务；心得写回 `insight`。
- 学习通道改 status 驱动：`feedback_context`（认可=done / 避免=archived 非纯手写，附作者原话+心得）、`generation` 黄金样本与结构模板、`_rewrite_examples` 打分映射、`prompt_eval` 高/低分稿、`version_effect` 统计口径。
- 前端：`Draft` 类型与列表接口带 `pure_manual`（R-210）与最新评价文本（textarea 预填）；删除 rate/like/dims 相关代码；`draft_status` kind 加「学习分析中」。
