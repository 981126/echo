# R-237：抖音视频复盘、涨粉与下一步主题

- **日期**：2026-10-29
- **提出渠道**：对话
- **状态**：代码完成；本人创作者私有字段待 Cookie 联调
- **开发设计**：`development-design/R-237-douyin-video-review.md`（八段完整设计，代码完成）

## 1. 需求背景

作者已经在抖音发布过多条视频，也能看到播放、点赞等数据，但目前有三个最直接的问题：

1. **看不懂数据为什么好或差**：知道播放量高低，却不知道是主题、封面、开头、内容节奏还是其他原因造成的。
2. **看完数据仍不知道下一条拍什么**：现有数据和同行榜单没有变成一个明确、具体、适合作者的主题建议。
3. **播放和涨粉之间没有关系判断**：不知道哪些视频真正带来关注，也不知道观众进入主页后为什么不关注。

作者不是没有运营经验也应能使用本功能。页面不能堆专业词和图表，必须先给出直白结论，再允许查看依据。

本功能只支持抖音，不改变系统已有的 B站、小红书功能。

## 2. 想要实现的目标

### 2.1 核心目标

打开一条自己的抖音视频后，页面依次回答：

1. **这条视频为什么好、为什么差**：最重要的结论直接显示，并能查看真实依据。
2. **怎样让看过的人愿意关注**：区分播放表现和涨粉表现，找出真正带来关注的内容。
3. **下一条最应该拍什么**：明确给出 1 个首选主题和 2 个备选主题。
4. **后续可以连续讲什么**：首选主题附带 3 条相关内容，让观众有持续关注的理由。
5. **修改有没有效果**：每次重点改 1～2 项，发布后对比结果。

### 2.2 完成后的可见结果

- 小白打开页面，不需要自己研究指标，也能先看懂“好在哪里、差在哪里、下一条拍什么”。
- 每条结论都能展开查看数据、视频内容或原评论依据。
- 每个建议都具体到可以执行，不出现没有做法的空话。
- 页面明确区分“播放变好”和“涨粉变好”。
- 数据不足时说明缺什么，不编造完整分析。

### 2.3 明确不做

- 不做 B站、小红书复盘。
- 不自动发布或剪辑视频。
- 不在本需求内自动生成完整脚本。
- 不只凭热点推荐主题。
- 不猜测同行的完播率、单条涨粉等私有数据。
- 不把相关关系说成确定因果，不替作者编造经历或素材。

## 3. 页面数据来源

### 3.1 数据来源总表

| 数据类别 | 从哪里来 | 用途 | 权限与限制 | 拿不到时怎么显示 |
|---|---|---|---|---|
| 自己的作品列表 | TikHub 提供的抖音创作者数据接口 | 选择要复盘的视频 | 需要本人或已授权账号的有效抖音创作者平台 Cookie | 提示更新 Cookie，不显示假数据 |
| 播放、点赞、评论、收藏、转发 | 抖音创作者数据接口及公开作品数据 | 判断内容表现 | 以平台实际返回为准 | 对应字段显示“暂无数据” |
| 2 秒跳出率、5 秒完播率、完整完播率 | 抖音创作者数据接口 | 判断开头和整条的观看情况 | 只能获取本人或已授权账号的数据 | 不用播放和点赞推算 |
| 平均播放时长 | 抖音创作者数据接口 | 判断观众平均看到多久 | 平台未返回时不能估算 | 显示“暂无数据” |
| 封面点击率 | 抖音创作者数据接口 | 判断封面和标题的吸引情况 | 只用于自己的视频 | 显示“暂无数据” |
| 主页访问量 | 抖音创作者数据接口 | 判断看完后是否愿意了解账号 | 只用于自己的视频 | 显示“暂无数据” |
| 单条视频粉丝增量 | 抖音创作者数据接口 | 判断该视频实际带来多少关注 | 不用账号当天总涨粉替代 | 显示“暂无数据” |
| 播放来源、搜索关键词 | 抖音创作者数据接口 | 判断观众从哪里来、搜什么找到视频 | 以平台返回为准 | 显示“暂无数据” |
| 观看趋势 | 抖音创作者数据接口 | 找出观众流失位置 | 没有趋势时不能声称知道具体流失秒点 | 只分析已有指标，并注明限制 |
| 视频标题、封面、发布时间、时长、原视频链接 | 已同步的抖音作品数据 | 公平比较、内容分析和跳转原视频 | 公开或本人数据 | 缺字段时显示“未记录” |
| 视频具体内容 | 视频转写；没有转写时可用标题和已有文本 | 分析开头、铺垫、重复和结尾 | 没有转写时不能做精细内容定位 | 提示“转写后可分析具体内容” |
| 评论原文和点赞数 | 已同步的作品评论 | 归纳赞同、反对、问题和需求 | 只分析实际入库评论，不代表全部观众 | 显示已分析评论数量 |
| 自己的历史表现 | 本地已保存的本人视频和按天数据 | 寻找相近视频，与平时表现比较 | 默认参考最近 30 条，实际数量如实显示 | 数据太少时注明“比较样本较少” |
| 同行爆款 | 已添加抖音对标账号的公开视频数据 | 为主题和修改建议提供参考 | 不需要同行 Cookie，不获取同行私有数据 | 显示公开字段，不猜私有指标 |
| 低粉爆款 | TikHub 抖音低粉爆款榜或带该标签的视频搜索 | 寻找低粉账号中表现突出的相关内容 | 默认近 7 天，按类别、关键词和时长筛选 | 无结果时显示“当前条件下暂无相关视频” |
| 主页简介、近期作品、置顶作品 | 能获取的本人主页公开信息；缺失时由作者补充 | 分析观众进主页后是否有关注理由 | 未获取的信息不能编造 | 标明“需要作者补充” |
| 作者采用的主题和修改计划 | 作者在页面主动保存的选择 | 发布后检查修改效果 | 只保存作者明确点击采用或记录的内容 | 未保存时不自动认定已经执行 |
| 后续发布结果 | 后续关联的本人抖音作品及创作者数据 | 检查上次修改是否有效 | 尽量按相同发布天数比较 | 未达到可比较时间时提示稍后再看 |

### 3.2 更新与展示规则

- 页面展示“最近成功更新时间”，不能把上次保存的数据说成此刻实时数据。
- 平台不同指标的更新速度不同，页面以实际同步时间为准。
- 点击“更新数据并分析”后显示进行中状态；切页或刷新后仍能恢复。
- Cookie 缺失、过期或接口失败时，说明哪一步未完成，并保留上一次成功数据及更新时间。
- 所有推测都标记为“结合内容推测”；数据能直接证明的标记为“数据直接显示”；无法判断的明确写“目前无法判断”。

## 4. 功能需求

### 4.1 新增「视频复盘」页面

**页面用途**：集中查看一条抖音视频的原因、涨粉表现、下一条主题、同行参考和修改结果。

**页面入口**：在现有主导航增加“视频复盘”；进入后默认使用当前主博主已绑定的抖音账号，不提供 B站、小红书切换。

**页面内容顺序**：

1. 选择视频与数据状态
2. 这条视频为什么好或差
3. 下一条最推荐拍什么
4. 怎样让观众愿意关注
5. 具体修改方法
6. 数据与评论依据
7. 同行爆款与低粉爆款
8. 账号可以尝试的新话题
9. 修改后的效果

#### 顶部字段

| 字段 | 意思 | 来源与显示规则 |
|---|---|---|
| 当前抖音账号 | 正在分析哪个账号 | 显示昵称和头像；未绑定时引导先去博主管理添加 |
| 选择视频 | 当前要复盘的视频 | 下拉可搜索，显示封面、标题和发布时间；默认选最近一条已发布视频 |
| 最近成功更新时间 | 页面数据最近一次成功获取的时间 | 显示真实时间；同步失败时保留上次成功时间 |
| 对比范围 | 用哪些历史视频判断“比平时好或差” | 默认最近 30 条，显示实际参与比较的数量 |
| 分析状态 | 当前是否可以查看结果 | 未开始、进行中、已完成、部分数据缺失、失败五种状态 |

#### 顶部按钮

| 按钮 | 点击后做什么 | 异常与限制 |
|---|---|---|
| 开始分析 | 使用已保存的数据生成当前视频的复盘 | 数据不足时仍可展示已有事实，但明确缺少的部分 |
| 更新数据并分析 | 先获取最新抖音数据，完成后重新生成复盘 | 进行中禁用重复点击；失败时保留旧结果并说明原因 |
| 抖音数据设置 | 打开本人创作者数据 Cookie 的设置弹窗 | 不在聊天中收集 Cookie，页面不显示完整 Cookie |
| 查看原视频 | 打开当前视频在抖音的原始页面 | 没有链接时禁用并说明 |

### 4.2 「这条视频为什么好或差」区域

**用途**：先给结论，再提供指标和证据，不让作者自己从图表里猜原因。

#### 顶部结论文案

| 字段 | 意思 | 显示规则 |
|---|---|---|
| 一句话结论 | 这条最主要好在哪里、差在哪里 | 最多先说最重要的 1～3 点，不堆所有指标 |
| 最值得保留 | 下一条应继续使用的主题或做法 | 必须有数据或内容依据 |
| 最优先修改 | 当前最影响目标的问题 | 与后面的修改建议对应 |
| 主要目标结果 | 这条在播放、点赞、完播、涨粉中哪项表现突出或不足 | 不用播放量代替全部评价 |

#### 数据字段

| 字段 | 小白能看懂的含义 | 显示规则 |
|---|---|---|
| 播放量 | 这条视频被观看了多少次 | 同时显示与相近视频相比高或低 |
| 点赞量 | 有多少人点赞 | 不单独用来代表内容质量 |
| 评论量 | 有多少人留下评论 | 可点击查看已分析评论 |
| 收藏量 | 有多少人收藏 | 没有数据时显示“暂无数据” |
| 转发量 | 有多少人分享 | 没有数据时显示“暂无数据” |
| 2 秒跳出率 | 开始播放后 2 秒内离开的人占比 | 越高通常越需要检查开头，但原因仍需结合内容 |
| 5 秒完播率 | 播放超过 5 秒的人占比 | 用于判断开头留人情况 |
| 完整完播率 | 完整看完整条视频的人占比 | 显示平台返回值，不自行估算 |
| 平均播放时长 | 平均每人看了多久 | 与视频总时长一起显示，方便理解 |
| 封面点击率 | 看到封面的人中点击观看的人占比 | 没有曝光或点击数据时不计算 |
| 主页访问量 | 看完视频后进入作者主页的次数 | 用于涨粉分析 |
| 粉丝增量 | 观众观看这条视频后新增关注的数量 | 不能用账号当天总涨粉替代 |
| 每 1000 次播放带来的关注 | 粉丝增量 ÷ 播放量 × 1000 | 播放量为 0 或缺数据时不计算 |
| 播放来源 | 观众主要从推荐、搜索、主页等哪里来 | 按平台返回来源显示 |
| 搜索关键词 | 观众搜索哪些词找到了视频 | 可查看各词对应数据，没数据则提示 |

#### 每条原因卡片字段

| 字段 | 意思 |
|---|---|
| 原因标题 | 用一句直白中文说明发现的问题或优点 |
| 判断方式 | 数据直接显示、结合内容推测、目前无法判断三者之一 |
| 数据依据 | 支持该结论的真实指标及其比较结果 |
| 内容依据 | 对应的标题、开头、转写片段、封面或评论 |
| 比较视频 | 用来得出“比平时好或差”的相近历史视频 |
| 影响的目标 | 主要影响播放、点赞、完播还是涨粉 |
| 建议动作 | 下一条具体保留、删除或调整什么 |

#### 按钮

| 按钮 | 点击后做什么 |
|---|---|
| 查看依据 | 展开该原因对应的数据、内容片段和评论，不跳走当前结论 |
| 查看对比视频 | 打开参与比较的视频列表，能看到选择它们的原因 |
| 查看评论 | 打开评论归纳和原评论，标明实际分析的评论数量 |
| 查看内容位置 | 有转写和观看趋势时，显示流失位置对应的内容；无数据时不显示该按钮 |

### 4.3 「怎样让观众愿意关注」区域

**用途**：帮助作者找出真正带来关注的内容，并理解主页为什么没有留住观众。

#### 字段

| 字段 | 意思 |
|---|---|
| 涨粉较好的主题 | 按实际粉丝增量和每千次播放关注表现找出的内容方向 |
| 高播放但不涨粉的内容 | 播放较高，但关注没有同步提高的视频及可能原因 |
| 观众可能关注的原因 | 内容持续有用、经历相近、观点一致、表达易懂等；证据不足时标为推测 |
| 主页检查 | 简介、近期内容方向、标题、置顶内容和当前视频之间是否一致 |
| 需要作者补充 | 平台没有提供、但完成主页判断所需的信息 |
| 涨粉结论 | 明确说明本次内容或修改是改善播放、改善涨粉，还是两者都有或都没有 |

#### 按钮

| 按钮 | 点击后做什么 |
|---|---|
| 查看涨粉依据 | 展开带来关注较多的视频、主题和对应数据 |
| 查看主页问题 | 展开主页检查项；未获取的信息显示“需要作者补充” |
| 查看相关评论 | 查看观众表达持续关注、追问或期待的原评论 |

### 4.4 「下一条最推荐拍什么」区域

**用途**：直接解决作者不知道下一条做什么的问题，同时给后续连续内容。

#### 推荐规则

- 显示 1 个首选主题和 2 个备选主题，首选在页面最突出。
- 推荐依据优先顺序：已证明带来关注的内容 → 观众持续追问的问题 → 已证明有人感兴趣的内容 → 同行近期有效内容 → 低粉爆款 → 相关热点。
- 首选主题附带后续 3 条相关内容，不自动生成完整脚本。

#### 每个主题的字段

| 字段 | 意思 |
|---|---|
| 主题名称 | 下一条具体讲什么，不能只写宽泛领域 |
| 首选或备选 | 表明推荐顺序，首选只能有一个 |
| 推荐理由 | 为什么现在最值得拍 |
| 适合作者的原因 | 与作者已有内容、人设、经历或素材的关系 |
| 数据依据 | 自己的视频、评论、同行或低粉爆款中的真实依据 |
| 主要目标 | 主要改善播放、点赞、完播还是涨粉 |
| 内容顺序 | 先讲什么、再讲什么、最后讲什么，只给简要方向 |
| 开头第一句 | 可以用于拍摄思考的第一句建议 |
| 参考视频 | 可打开查看的相关同行或低粉爆款 |
| 后续 3 条内容 | 与首选同方向、可连续发布的 3 个具体主题 |
| 后续内容作用 | 每条分别解决什么问题，是吸引新观众、帮助了解作者还是加强关注理由 |

#### 按钮

| 按钮 | 点击后做什么 | 结果 |
|---|---|---|
| 采用首选主题 | 保存当前首选及后续 3 条为作者选择的创作方向 | 出现在“本次修改与发布检查”，不自动生成脚本 |
| 采用这个备选 | 将指定备选改为作者选择的主题 | 保存作者真实选择，不覆盖原推荐记录 |
| 查看推荐依据 | 展开该主题对应的视频、评论和公开数据 | 作者能判断推荐是否可信 |
| 查看后续内容 | 展开首选后面的 3 条连续主题及衔接关系 | 不需要离开当前页面 |

### 4.5 「具体修改方法」区域

**用途**：把分析转成下一条真正要执行的 1～2 项改变。

| 字段 | 意思 |
|---|---|
| 本次保留 | 下一条不要改掉的有效做法 |
| 本次修改 | 作者准备重点执行的 1～2 项调整 |
| 为什么这样改 | 修改对应的问题和依据 |
| 主要观察指标 | 发布后主要看播放、点赞、完播、主页访问还是粉丝增量 |
| 执行状态 | 未记录、已记录、已关联发布视频、已检查 |

| 按钮 | 点击后做什么 | 异常与限制 |
|---|---|---|
| 记录本次修改 | 保存作者确认的修改项 | 最多重点记录 2 项；超过时提示删减，不强制自动选择 |
| 修改已记录内容 | 在发布前调整准备执行的内容 | 保留上次推荐，不把作者修改写回成 AI 原建议 |

### 4.6 「同行爆款与低粉爆款」区域

**用途**：为原因和主题推荐提供公开参考，不取代自己的核心结论。

#### 筛选字段

| 字段 | 意思 | 默认值 |
|---|---|---|
| 内容类别 | 只看与作者方向相关的类别 | 当前账号相关内容类别 |
| 关键词 | 搜索指定主题 | 空，可输入 |
| 发布时间 | 只看最近一段时间的视频 | 低粉爆款近 7 天；同行近期视频 |
| 视频时长 | 寻找与作者口播长度相近的视频 | 不限，可选择 |
| 榜单类型 | 同行爆款或低粉爆款 | 同行爆款 |

#### 视频列表字段

| 字段 | 意思 |
|---|---|
| 封面和标题 | 这条参考视频讲了什么 |
| 作者与粉丝数 | 谁发布的，发布时可见的粉丝规模 |
| 发布时间 | 判断数据积累了多久 |
| 播放、点赞、评论等公开数据 | 只展示平台实际返回字段 |
| 值得参考的原因 | 主题、开头、内容或评论中的具体优点 |
| 与作者的关系 | 哪点适合借鉴，哪点不适合照抄 |
| 是否持续同方向 | 同行是否持续讲相关内容，爆款后是否继续延伸 |

#### 按钮

| 按钮 | 点击后做什么 |
|---|---|
| 查询 | 按当前筛选条件获取并展示结果，无结果时明确提示 |
| 查看分析 | 展开开头、内容、评论和可借鉴点 |
| 查看原视频 | 打开抖音原视频 |
| 查看推荐中的用途 | 显示这条参考被哪条主题或修改建议引用；未被引用时不显示 |

### 4.7 「账号可以尝试的新话题」区域

**用途**：在不影响当前方向的前提下，寻找可以扩充账号内容的 3 个话题。

| 字段 | 意思 |
|---|---|
| 新话题 | 可以尝试的具体话题 |
| 与现有内容的关系 | 为什么不会让账号突然变成无关方向 |
| 观众可能关心的原因 | 评论、搜索或已有内容中的依据 |
| 作者可讲依据 | 作者已有经历、知识或素材；没有时明确说需要补充 |
| 建议先拍的小主题 | 用来试水的第一条具体内容 |
| 主要观察指标 | 发布后判断该话题是否适合继续的重点数据 |

| 按钮 | 点击后做什么 |
|---|---|
| 查看话题详情 | 展开关系、依据和建议先拍的小主题 |
| 查看参考内容 | 打开支持该话题的自己或公开参考视频 |

### 4.8 「修改后的效果」区域

**用途**：发布后检查上次修改是否有效，避免每次复盘都从零开始。

| 字段 | 意思 |
|---|---|
| 原视频 | 上次被分析、发现问题的视频 |
| 新发布视频 | 作者实际执行修改后发布的视频 |
| 上次重点修改 | 当时记录的 1～2 项修改 |
| 对比时间 | 两条视频用于比较的相同或相近发布天数 |
| 修改前后数据 | 播放、点赞、完播、主页访问和粉丝增量的变化 |
| 检查结论 | 哪些改善、哪些未改善、哪些暂时不能确定 |
| 下一步决定 | 继续保留、再次调整或停止该主题或方法 |
| 连续主题表现 | 首选及后续同方向内容是否逐步带来更稳定的主页访问和关注 |

| 按钮 | 点击后做什么 | 异常与限制 |
|---|---|---|
| 关联已发布视频 | 选择实际执行本次修改的新视频 | 只有作者确认关联后才建立关系 |
| 更新检查结果 | 获取新数据并重新比较 | 数据积累不足时提示稍后再看 |
| 查看详细对比 | 展开相同或相近发布天数下的数据和原因 | 不能拿累计总量直接判断修改有效 |

### 4.9 「抖音数据设置」弹窗

**用途**：让作者管理本人或已授权账号的创作者数据访问，不接触同行私有数据。

| 字段 | 意思 | 显示规则 |
|---|---|---|
| 创作者平台 Cookie | 获取自己的创作者数据所需的登录凭证 | 密码式输入，页面和日志不显示完整内容，不写入需求文档 |
| 当前状态 | Cookie 是否可用 | 未设置、可用、已过期、验证失败 |
| 最近验证时间 | 上次确认可用的时间 | 显示真实时间 |
| 最近成功同步时间 | 上次成功获取创作者数据的时间 | 验证成功但无数据时不混为一谈 |
| 失败原因 | 无法获取数据的直白解释 | 不显示 Cookie 或敏感请求内容 |

| 按钮 | 点击后做什么 |
|---|---|
| 保存并验证 | 保存凭证并尝试获取自己的创作者数据，明确成功或失败 |
| 更新 Cookie | 替换过期凭证并重新验证 |
| 关闭 | 关闭弹窗，未保存的输入不生效 |

### 4.10 通用界面、加载与异常要求

- 使用常见图标并同时显示中文名称，例如“播放”“点赞”“完播率”“涨粉”，不创造新词。
- 图表只用于支撑结论，不能把核心结论藏在图表里。
- 所有长任务有进行中动效，切页和刷新后恢复；完成、失败、部分缺失状态明确。
- 空数据、接口失败、Cookie 过期、无转写、无评论、无同行结果分别给出对应提示，不能统一写成“分析失败”。
- 旧结果保留时显示其数据时间，不能伪装成最新结果。
- 手机和电脑浏览器均可阅读和操作；切换视频、展开依据或切换榜单时无空白闪帧。
- 所有外部跳转明确打开抖音原页面；所有“采用”“记录”“关联”只有作者点击后才生效。

### 4.11 图表与可视化要求

**不是不要图标或图表。** 本需求需要常见图标、直接数字和清楚详细的图表共同表达，让没有运营经验的人也能一眼看懂。图表标题直接写它回答的问题，关键数值直接标在图上，不能只有颜色和装饰。

| 图表 | 回答的问题 | 必须展示的内容 |
|---|---|---|
| 核心指标卡 | 这条视频各项表现怎么样 | 常见图标、中文名称、当前值、与平时比较的箭头、百分比或差值、比较样本数 |
| 当前与平时对比条形图 | 哪项明显高于或低于平时 | 当前值与平时中位数两根横条、具体数值和单位；“跳出率越低越好”必须写明 |
| 观看趋势折线图 | 观众在哪些时间点继续看或离开 | 横轴为视频时间、纵轴为留存/跳出比例；当前视频与平台同类参考两条线；异常点标时间和下降幅度 |
| 播放来源条形图 | 观众主要从哪里来 | 每个来源的次数和占比，推荐/搜索/主页等使用平台原文名称 |
| 搜索关键词条形图 | 哪些搜索词带来观看 | 关键词、对应次数；没有数据时不显示虚构词语 |
| 评论问题条形图 | 观众反复在问什么 | 问题、不同评论者人数、评论点赞数；可展开原评论 |
| 主题涨粉对比条形图 | 哪类内容更容易带来关注 | 每个主题的粉丝增量、每1000次播放关注、样本数；样本少时明确标记 |
| 同行爆款对比条形图 | 这条同行视频比平时好多少 | 本条播放与该同行平时中位数、播放倍数和比较样本数 |
| 修改前后对比图 | 上次修改有没有效果 | 每项指标单独展示修改前后数值、差值和“改善/未改善/暂时不能确定”，不同单位不放在同一坐标轴 |

图表统一规则：

- 图表上方先有一句中文结论，下方可以展开真实依据；图表不能替代结论。
- 当前数据与对比数据使用不同颜色，同时配“当前/平时”文字、箭头和数值，不能只靠红绿区分。
- 条形图从 0 开始；折线图横轴从 `00:00` 开始、纵轴明确是百分比，不能通过截断坐标夸大差异。
- 关键数字直接显示，悬浮或点按可查看更详细解释；手机上点按也能使用。
- 数据缺失时不画成 0；样本不足时显示“样本较少”并减少结论；趋势播放量少于 200 时显示“趋势仅供参考”。
- 图表与表格可切换，方便查看精确数值；动画只用于数据更新过渡，不能影响读数。
- 主题推荐和原因仍以文字卡片为主，不为了显得复杂而增加雷达图、仪表盘或难懂的综合评分图。

## 5. 用户故事

### 故事 1：看懂一条表现不错的视频

**作为**一个不懂运营的博主，  
**我希望**打开最近一条视频后直接看到它好在哪里以及依据，  
**以便**我知道下一条应该保留什么，而不是只看到一个高播放量。

**可见结果**：页面先显示最重要的优点，点击“查看依据”能看到对比视频、真实数据和对应内容。

### 故事 2：看懂一条表现不好的视频

**作为**一个不知道问题出在哪里的博主，  
**我希望**系统告诉我最值得优先修改的一个问题，  
**以便**我不用同时改标题、封面、开头、时长和发布时间。

**可见结果**：页面给出 1 个最优先问题和具体改法，并标明这是数据事实还是内容推测。

### 故事 3：理解高播放却不涨粉

**作为**一个想更快涨粉的博主，  
**我希望**看到这条视频的播放、主页访问和粉丝增量之间的关系，  
**以便**我知道问题是没有吸引人看，还是看完以后没有关注理由。

**可见结果**：页面明确写“改善了播放，尚未解决涨粉”或其他符合数据的结论，并显示主页检查项。

### 故事 4：不再纠结下一条拍什么

**作为**一个经常没有选题的博主，  
**我希望**系统直接给我一个首选主题和两个备选，  
**以便**我可以马上决定下一条讲什么。

**可见结果**：首选包含具体内容、推荐理由、依据、内容顺序和开头第一句；点击“采用首选主题”后保存我的选择。

### 故事 5：让观众有持续关注的理由

**作为**一个希望持续涨粉的博主，  
**我希望**首选主题后面还有三条相关内容，  
**以便**观众看完一条后还能在主页找到同方向视频。

**可见结果**：后续三条分别写清解决什么问题、如何衔接以及各自作用。

### 故事 6：判断 AI 的建议是否可信

**作为**一个不愿意被 AI 忽悠的博主，  
**我希望**每条原因和主题推荐都能查看真实依据，  
**以便**我能区分事实、推测和无法判断的内容。

**可见结果**：依据可以展开；缺少数据时显示限制，不生成看似确定的解释。

### 故事 7：参考同行而不是照抄

**作为**一个寻找内容方向的博主，  
**我希望**看到同行爆款和低粉爆款为什么值得参考，  
**以便**我能换成适合自己的角度，而不是只复制标题。

**可见结果**：每条参考说明适合作者的部分、不适合照抄的部分，以及它被哪条建议引用。

### 故事 8：发布后知道修改有没有用

**作为**一个正在持续改进的博主，  
**我希望**把新视频和上次记录的修改关联起来，  
**以便**我知道这次调整是否值得继续。

**可见结果**：系统按相近发布天数比较数据，说明改善、未改善或暂时不能确定，并给出下一步决定。

### 故事 9：数据或登录状态异常时仍能理解页面

**作为**一个不熟悉接口和 Cookie 的博主，  
**我希望**页面用直白中文告诉我缺少什么、怎样处理，  
**以便**我不会把旧数据或部分结果误认为最新完整分析。

**可见结果**：Cookie 过期、无转写、无评论、同步失败分别提示；旧结果带最近成功更新时间。

### 故事 10：在手机上也能使用

**作为**一个会随时查看复盘的博主，  
**我希望**在手机上阅读结论、采用主题和查看依据，  
**以便**我不必坐在电脑前才能决定下一条内容。

**可见结果**：文字不挤成竖排，按钮可点击，展开和切换流畅，后台分析离开页面后仍能恢复。
