> 1.ai提示词 菜单 改为 ai设置，里面其他功能不改
> 2.ai设置第一个tab页可以让我配置项目中的主模型、副模型、asr模型
> 3.应用后实时生效

## 后续修订（作者原话，未改动）
> 1.主模型和副模型改为，模型1、模型2，可以分别配置模型厂家、模型、key
> 2.脚本生成模型策略： 改为两个下拉框，分别是生成方、评审方，两方可以选不一样的模型也可以选一样的
> 3.除了脚本生成需要双模型参与讨论，其他关于ai的功能默认使用模型1、出现问题在降级成模型2，确保模型1、2都深度学习了该系统数据，不要降级之后模型2像是退化了
> 4.脚本生成里面的讨论轮次是控制了，所有自动生成脚本的讨论轮次

## 澄清与确认结论（2026-09-11，作者逐项选择）
1. **模型槽位**：改为 **模型1 / 模型2**，各自可配 **厂家（DeepSeek / Kimi）+ 模型 + API Key**。
2. **Key 存储**：**存本地 DB 且允许回显明文**（作者明确选择，接受"备份会带明文 Key"的代价；界面加醒目提示）。
3. **脚本生成**：**去掉随机/轮流策略**，改为「**生成方**」「**评审方**」两个下拉，各自选模型1或模型2（**可相同**）。
4. **其它 AI 功能**：默认用**模型1**；出现"报错/超时/空正文/输出不合法"时**降级模型2**（详见 R-139）。
5. **讨论轮次**：统一控制**所有**脚本生成（含每日自动生成）的双模型讨论轮次（详见 R-139）。
6. **降级可见**：日志 + 站内通知 + 稿子标记（详见 R-139）。
7. **原工具栏**：「生成模型策略」下拉迁入新 tab（工具栏只留讨论轮次）；**路由保持 `/prompts`**，不打断通知深链。

## 范围（本需求只做"配置界面 + 存储"）
- 菜单与页面标题「AI 提示词」→「**AI 设置**」。
- 新增**第一个 tab「模型设置」**：
  - 模型1：厂家（下拉）/ 模型（按下拉）/ API Key（明文，可回显）
  - 模型2：同上
  - 脚本生成：生成方（模型1 / 模型2）、评审方（模型1 / 模型2）
  - ASR：服务商（阿里云 / 硅基流动 / 模拟）+ 模型（仅硅基流动需要）
  - 讨论轮次（自工具栏迁入）
  - 保存即生效；Key 明文回显处附风险提示
- 存储用 `app_kv`（无需迁移）；厂家+模型目录写在代码里，后续加供应商只加一行。
- 旧 `generation_model`（kimi/deepseek/random/alternate）自动映射为「生成方=旧值、评审方=另一个」，作者无需重设。

## 不包含
- 模型路由、降级、参数归一化、自动生成双模型讨论 → 属 **R-139**；
- 不改提示词各 key 的既有 tab 与功能；不改 `.env` 白名单校验（启动仍校验，防 R-068 静默回退）。

## 验收标准
1. 菜单/标题显示「AI 设置」；路由与原有提示词功能、通知深链不受影响。
2. 「模型设置」为第一个 tab，可配置模型1/2（厂家+模型+Key）、生成方/评审方、ASR（服务商+模型）、讨论轮次并保存。
3. 保存后**立即生效**（不重启）——配置读写走 `app_kv`。
4. 模型1与模型2可分别指向不同厂家/模型/Key；生成方与评审方可相同。
5. 旧 `generation_model` 值无感迁移；`verify.sh` 全绿；接口冒烟；前端点检；服务保持运行。
