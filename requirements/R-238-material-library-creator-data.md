# R-238：素材库本人抖音作品数据改用创作者中心接口（含播放量）

- **日期**：2026-10-30
- **提出渠道**：对话
- **状态**：⛔ 已并入 R-239（2026-10-30 作者确认合并），不再单独实施；内容保留作历史记录
- **开发设计**：`development-design/R-238-material-library-creator-data.md`
- **依赖**：R-237（抖音创作者中心真实取数、`douyin_creator_sync.py`，当前在 `feat/r237` 工作区、尚未提交）

## 1. 需求背景

作者在素材库查看自己发布的视频时，最关心的「播放量」一直是 0 或没有，导致素材库数据无法用来判断哪条内容有效，也会影响依赖这些数据的 AI 对话、生成权重、人设金句和提示词样本。

真实接口对比确认了原因：

1. **抖音公开接口拿不到播放量**：素材库现在用抖音公开单条/列表接口取数。实测本人 415 条抖音作品中 414 条播放为 0；`platform_post_stats` 里来自公开接口的 4696 条抖音统计行，没有一条播放大于 0。点赞/评论/收藏/转发是真实的，只有播放缺失，且缺失被写成了 0。
2. **创作者中心接口能拿到播放和更细的观看数据**：R-237 已接入抖音创作者中心（TikHub `creator_v2`）。同一条作品 1902：公开接口播放 0，创作者接口播放 3587，同时还有 2 秒跳出率、5 秒完播率、完整完播率、平均播放时长、主页访问量、吸粉量、流量来源、搜索词。本人全部 426 条作品用 12 次请求即可覆盖。
3. **素材库页面目前只显示点赞**：卡片只渲染 👍 点赞，前端类型里连播放字段都没有；后端 `/api/library` 其实已经返回 `plays`，但没有展示。
4. **存在“真实值被 0 覆盖”的风险**：同一天里公开同步会无条件写 `plays=0`。今天创作者接口写进去的 3587，只要之后点一次公开「同步数据」或跑一次每日同步，就会被改回 0。
5. **历史数据陈旧**：`metrics_snapshots` 只有 80 行、停留在 2026-09-05（旧库迁移数据），之后没有新的自动写入；本人抖音 385/415 条作品的最近统计停在 2026-09-05/06。

## 2. 想要实现的目标

### 2.1 核心目标

1. **本人抖音作品的指标改以创作者中心为主数据源**：播放、点赞、评论、收藏、转发取真实值，并额外入库完播率、2 秒跳出率、5 秒完播率、平均播放时长、主页访问量、吸粉量。
2. **素材库卡片能看到播放量**：自己抖音作品显示「▶ 播放」和「👍 点赞」，真实 0 显示 0，拿不到显示「暂无」，不再把“未知”显示成 0。
3. **公开同步不再覆盖真实播放**：同一天多来源写入时按可信度合并，公开接口的 0 不覆盖创作者接口的真实值。
4. **历史一次补齐、之后自动保鲜**：首次上线自动回填本人全部抖音作品当天统计；每日两轮平台同步后自动刷新最近 90 天作品。
5. **失败可理解、旧数据不丢**：Cookie 缺失/失效时明确提示并回退公开接口，保留上一次真实值，不写 0。
6. **其他数据链路保持不变**：评论正文、视频下载、B 站、小红书、对标/低粉爆款仍然使用现有公开接口。

### 2.2 完成后的可见结果

- 素材库打开就能看到自己每条抖音作品的真实播放量和点赞量（如「▶ 3,587 👍 46」）。
- 点「同步数据」后播放/点赞更新，提示数据来源（创作者中心/公开接口）。
- 历史作品不需要逐条手动同步，首次回填后绝大多数作品都有真实播放。
- Cookie 过期时提示「创作者数据需要重新设置」，页面仍显示上次成功的数据，不会变成 0。
- 后台回填进行中时页面有进行中提示；切页或刷新回来仍能恢复「进行中」。

### 2.3 明确不做的范围

- 不新增/修改表结构，不新增列。
- 不用创作者中心替换：评论正文、视频下载地址、B 站、小红书、对标账号、低粉爆款/搜索。
- 不补历史每日播放快照（平台只给当前累计值，无法回推过去每一天）。
- 不在素材库展示完播率等私有指标（只入库，供视频复盘/学习使用）。
- 不把播放量做成独立趋势图（本次只保证数值正确可见）。
- 不改变素材库卡片墙的布局和筛选方式。

## 3. 页面数据来源

## 4. 功能需求

### 4.1 素材库卡片显示播放量

- **影响页面**：素材库（云端卡、本地卡、合并作品卡）。
- **新增展示字段**：播放量，格式「▶ 3,587」；保留点赞「👍 46」。
- **取值规则**：
  - 一条本地素材可能绑定多条平台作品（合并作品），取各平台中**可信来源**的最大播放量展示。
  - 本人抖音作品播放来自创作者中心接口；B 站播放来自公开接口（可信）；抖音公开接口的 0 和缺失都视为「未知」，不展示。
  - 真实 0（创作者中心明确返回 0）显示「0」。
- **空数据表现**：没有统计行、来源未知或不支持播放的平台，不显示播放数字（不显示 0、不显示「—」）。
- **失败表现**：接口失败时保留上一次成功值，数字旁边不新增错误文案（错误通过「同步数据」的提示/通知给出）。
- **动效**：沿用现有卡片入场与「同步数据」中的加载动画，不新增复杂动画；数字刷新时使用轻量过渡，避免闪烁。

### 4.2 「同步数据」按钮

- **入口**：素材库本地卡「同步数据」、合并作品「同步数据」、单条云卡「同步数据」。
- **本人抖音作品**：
  1. 优先调用创作者中心单条作品接口（1 次请求），取播放、点赞、评论、收藏、转发及完播类数据。
  2. 写入当天平台统计（`platform_post_stats`）与当天创作者指标（`douyin_post_metrics`）。
  3. 评论正文继续用现有公开评论接口（不变）。
  4. 返回信息说明数据来源为创作者中心。
- **其他平台、对标账号**：完全沿用现有公开接口逻辑，行为不变。
- **失败与降级**：
  - Cookie 未配置/已失效/接口业务错误：自动回退公开接口，返回提示「创作者数据不可用，本次使用公开数据」，页面保留上次真实播放值。
  - 公开接口失败：保留旧值，提示具体失败原因。
  - 不把「拿不到」写成 0。
- **进行中**：沿用卡片同步中的旋转/进度动效；单次同步约 1~2 次请求，通常数秒内完成。

### 4.3 每日自动保鲜

- 每日两轮平台同步完成后，对当前主博主的本人抖音账号，用创作者中心列表接口拉取**最近 90 天**作品（1~2 次请求），更新这些作品当天的播放/点赞/评论/收藏/转发及完播类指标。
- 不阻塞公开同步：创作者接口失败只记录日志/通知，不影响其他账号与平台。
- 与公开同步同一天先后执行时，按 4.5 的来源优先级合并，最终保留真实播放。

### 4.4 首次历史回填

- 上线后**自动执行一次**，不需要作者逐条点击。
- 按 90 天时间窗向前分页，约 12 次请求覆盖本人全部 426 条抖音作品（实测）。
- 只写「当天」的平台统计行与创作者指标行，不伪造历史日期。
- 后台任务进行中在任务中心/通知可见；失败可重试；达到单次请求上限时记录剩余数量，下次继续。
- 幂等：回填完成后打标记，不重复执行；作者手动点「同步数据」不受影响。

### 4.5 同一天多来源合并规则

- 可信度顺序：**创作者中心 > 公开作品统计（`fetch_video_statistics`）> 普通公开接口**。
- 普通公开接口返回的播放 0（平台不返回播放量）不得覆盖已有的真实播放（>0）。
- 每条统计行记录来源，便于区分「真实 0」和「平台不返回的 0」。
- 同一天重复同步幂等，结果不因执行次数变化。

### 4.6 接口与字段变化

- `GET /api/library` 的 `latest_stat` 增加播放可信标记与来源字段，供前端决定是否显示 0（具体字段见开发设计）。
- 同步类接口（本地卡/作品/单帖）的响应增加 `warnings`（失败/降级原因）与数据来源说明。
- 不新增页面、不新增页面路由；如实施时确需回填触发接口，必须在开发设计中列明并同步 `docs/API.md`。

### 4.7 字段逐项说明

| 字段 | 中文含义 | 来源 | 空值表现 |
|---|---|---|---|
| `latest_stat.plays` | 播放量 | 创作者中心（本人抖音）/公开（其他平台） | 未知不显示；真实 0 显示 0 |
| `latest_stat.plays_known` | 播放量是否可信（新增） | 程序根据来源计算 | false 时页面不显示播放数字 |
| `latest_stat.plays_source` | 播放量来源（新增） | 程序记录 | 空字符串表示未知 |
| `latest_stat.likes` | 点赞量 | 创作者中心/公开 | 0 或空则不展示（保持现状风格） |
| `latest_stat.favorites` | 收藏量 | 创作者中心/公开 | 一期素材库不展示，仅接口返回 |
| `latest_stat.shares` | 转发量 | 创作者中心/公开 | 同上 |
| `latest_stat.comments` | 评论量 | 创作者中心/公开 | 同上 |
| `douyin_post_metrics.*` | 完播率、2 秒跳出、5 秒完播、平均播放、主页访问、吸粉量 | 创作者中心 | 缺失存空，不估算 |

### 4.8 空数据与失败表现汇总

| 情况 | 页面/接口表现 |
|---|---|
| 没有绑定平台作品 | 保持现状：本地卡、无点赞/播放 |
| 有平台作品但没有统计行 | 显示「暂无」，不显示 0 |
| 抖音公开接口返回播放 0 | 视为未知，不显示 0 |
| 创作者接口返回播放 0 | 显示 0 |
| Cookie 未配置/失效 | 「同步数据」提示需要重新设置创作者数据；旧值保留 |
| 公开接口失败 | 保留旧值，提示失败原因 |
| 回填任务进行中 | 任务中心/通知显示进度；切页/刷新可恢复 |
| 回填达到请求上限 | 记录剩余数量，不重复扣额度，下次继续 |

## 5. 用户故事

1. **作为**一个会经常回看自己数据的博主，**我希望**打开素材库就能看到每条抖音视频的真实播放量和点赞量，**以便**快速判断哪条内容真正有效。  
   **可见结果**：卡片显示「▶ 3,587 👍 46」；未知时显示「暂无」。
2. **作为**作者，**我希望**点「同步数据」后播放量更新，并知道数据来自哪里，**以便**确认数据可信。  
   **可见结果**：数字更新，提示「数据来自创作者中心」或「本次使用公开数据」。
3. **作为**作者，**我希望** Cookie 过期时页面明确告诉我，且不要把我之前看到的数据清空，**以便**我重新登录后继续使用。  
   **可见结果**：出现「创作者数据需要重新设置」提示，旧播放量仍在。
4. **作为**作者，**我希望**历史作品不用一条条点同步，**以便**一次补齐后所有素材都有播放数据。  
   **可见结果**：首次回填后台自动完成，历史卡片陆续出现真实播放。
5. **作为**作者，**我希望**回填/同步过程中切到别的页面再回来仍能看到「进行中」，**以便**不会误以为已经失败。  
   **可见结果**：任务中心有进度，重进素材库仍显示进行中。

## 6. 验收标准

- [ ] 素材库自己抖音作品卡片显示真实播放量（例如作品 1902 显示 3,587）；未知时不显示 0。
- [ ] 「同步数据」对本人抖音作品使用创作者中心接口（响应/日志可确认来源），同一条作品播放与创作者中心一致。
- [ ] 之后运行公开每日同步/单帖同步，不会把已写入的真实播放覆盖为 0。
- [ ] 首次回填完成后，本人抖音作品当天统计播放 >0 的比例从 1/415 提升到 ≥95%（播放确实为 0 的作品除外）。
- [ ] Cookie 失效：同步返回明确提示、保留旧值、不写 0，恢复 Cookie 后自动恢复真实数据。
- [ ] 评论、媒体下载、B 站、小红书、对标作品行为与现在一致。
- [ ] 无新增表/列；`scripts/verify.sh` 全绿；真实接口冒烟与素材库页面点检通过。
