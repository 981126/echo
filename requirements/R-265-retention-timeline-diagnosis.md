## 一、需求背景

视频复盘的定位是「有依据地解释好/差 + 告诉作者下一条怎么改」。目前它能做的只有「把这条的指标和你自己近 30 条同题作品的中位数比一比」，然后说「5 秒完播低于平时」「中后段留人偏弱」。

三个断点导致这个结论**无法落到具体内容**：

1. **曲线缺失**：255/259 条作品没有留存曲线，复盘连「第几秒掉」都不知道；
2. **曲线对不上句子**：转写没有时间轴，即使有曲线也只能指到时间点，不能指到「00:04 那句」；
3. **基线不分场景**：10 条同题作品的中位数，不分时长、不分流量来源，2 分钟视频和 40 秒视频直接比，推荐流量 20% 和 90% 的作品直接比，容易把「时长/流量结构」误判成「文案差」。

作者已确认：先补这三条信号（P0-1/2/3），并把时长、流量来源纳入复盘分诊。

## 二、想要实现的目标

让复盘从「5 秒完播偏低」升级为「**00:04–00:06 这句掉了 12.4 个百分点，对应的原话是「……」**」，并且这个结论在页面上可核对、可证伪。

可量化的目标（验收口径见第七节）：

1. 主博主有 5 秒完播的作品，平台返回趋势的全部入库；平台不返回的 243 条标 `unsupported` 且不再重复请求（当前 16 条有曲线）；
2. 有句子时间轴的复盘，流失点能指到具体句子，抽检 **10 条至少 8 条正确**；
3. 时长、流量来源进入判断：低推荐流量的作品，结论不得写成「文案/开头差」；
4. 旧复盘不被覆盖，可用新口径重跑。

## 三、口径与边界

### 3.1 作者已确认

1. 本期只做数据侧与复盘侧，**不改生成侧**（开头库注入、吸引力门禁重写留到 R-266）；
2. 时长、流量来源纳入复盘分诊；
3. 170 篇删稿含测试数据，**不作为「作者不采用率」指标**。

### 3.2 默认取值（上轮建议值，作者可直接改）

| 项 | 默认值 | 说明 |
|---|---|---|
| 句子时间轴来源 | **腾讯按需重转**（`ECHO_TIMELINE_ASR_MODE`，默认 `tencent`） | DeepSeek 当前无分句；只为复盘对象补时间轴，不覆盖已校对正文 |
| 曲线补齐范围 | **主博主 259 条全量一次补齐 + 每日增量（发布 7 天内）** | 每条 1 次 TikHub 请求，共约 255 次 |
| 掉点判定 | 相邻点跌幅 **≥5 个百分点 且 相对跌幅 ≥8%** | 两个条件同时满足才算掉点 |
| 掉点合并 | 相邻两段都满足时合并为一段，跨度 ≤4 秒 | 避免同一处流失被拆成 3 条 |
| 流失点数量 | 最多 **3 条**，按跌幅降序；一句话只出现一次 | 防止同一句重复 |
| 流量分诊阈值 | 推荐流量占比 **<50%** 判为「流量结构受限」 | 低于一半时不把完播归因为文案 |
| 时长分桶 | <30s / 30~60s / 60~120s / >120s | 同桶样本 <5 时退回全量并标注 |

### 3.3 边界与降级

1. **没有时间轴就不指认句子**：只能给时间点，页面明确写「本条没有句子时间轴」；不估算、不硬凑；
2. **数据不可靠就不给结论**：播放 <200 或曲线点数 <5 → 显示「样本不足」，不做句子级归因；
3. **不批量重转 728 条**：只在复盘时按需补，避免一次性成本；
4. **不覆盖已有正文**：补时间轴只写 `transcripts.sentences`，不改 `transcript_text` / `corrected_text`；
5. **旧复盘不自动重跑**：只给按钮，作者点了才生成新复盘。

## 五、功能需求

### 5.1 转写结果带句子时间轴（数据侧，无独立页面）

- 腾讯 / 阿里云转写：解析分句时间戳，落 `transcripts.sentences`（JSON 数组，毫秒），`timeline_precision=sentence`；
- DeepSeek：落每片窗口（每片 60~118 秒），`timeline_precision=chunk`，不用于句子引用；
- 硅基流动 / mock：`timeline_precision=none`；
- 已有 728 条不批量重转；页面不新增入口。

### 5.2 留存曲线补齐

**入口**：数据看板顶栏「更新数据」旁新增按钮 **「补齐留存曲线」**（次要按钮，带数量角标，如「补齐留存曲线 · 待补 255 条」）。

- 点击 → 后台任务（`retention_backfill`），进行中显示「补齐留存曲线 X/Y」，切页/刷新回来仍显示；
- 完成 → 站内通知「留存曲线补齐完成：成功 251、失败 4」+ 失败明细（最多 5 条，含标题与原因）；
- 预算不足 → 停止并提示「TikHub 今日剩余额度不足，已完成 X 条，明天可继续」；
- 待补数量为 0 → 按钮置灰，tooltip「已全部补齐」；
- 每日 09:10 自动补「发布 7 天内且缺曲线」的作品，失败走既有告警。

### 5.3 复盘时自动补句子时间轴

**入口**：复盘页「更新数据并分析」（既有按钮，无新增按钮）。

- 流程中新增一步进度「补齐句子时间轴（约 30~60 秒）」；
- 只在「该作品有本地视频 + 已有转写文本 + 时间轴精度不是 sentence」时触发；
- 补成功 → 结论可引用句子；
- 补失败（未配置腾讯、任务超时、文件缺失）→ **不阻断复盘**，warning 写「本条没有句子时间轴，只能指出时间点，原因：…」；
- 不覆盖 `transcript_text` / `corrected_text`。

### 5.4 留存流失点（新增板块）

**位置**：复盘页「这条视频为什么好或差」之后、「按指标优化建议」之前。

**板块标题**：**留存流失点**。

每条展示：

| 字段 | 示例 | 规则 |
|---|---|---|
| 时间区间 | 00:04–00:06 | 曲线相邻点 |
| 跌幅 | 下降 12.4 个百分点（相对 31%） | 程序计算 |
| 对应句子 | 「……」 | 仅 `timeline_precision=sentence` 且时间窗有重叠 |
| 类型标签 | 开头 / 中段 / 结尾 | 按区间位置（≤10 秒=开头，≥80% 时长=结尾） |
| 置信度 | 句子级 / 仅时间点 | 无时间轴时显示「仅时间点」 |

- 最多 3 条，按跌幅降序；
- 无曲线 → 板块不渲染；有曲线但不可靠（播放 <200 或点数 <5）→ 渲染空态「这条的播放量/曲线点数不足，先不做流失点定位」；
- 「为什么好/差」与「按指标优化建议」引用句子时，**只能引用本板块列出的句子**。

### 5.5 分诊：时长 + 流量来源

**位置**：复盘页顶部作品信息行下方，一行小字 + 条件提示条。

- 常显：`这条 85 秒 · 推荐流量 43% · 搜索 12%`（缺失项显示「时长未知 / 流量来源未知」）；
- 条件提示（黄色/中性色提示条，非报错）：
  - 推荐占比 <50%：**「推荐流量偏低，这条的完播/留存不能单独归因于文案」**；
  - 时长 >120 秒且「5 秒完播正常、完整完播低」：**「长视频完播天然更低，建议同时看平均播放占比」**；
- 触发提示时，「为什么好/差」里涉及完播/留存的结论，判断类型由「事实」降为「推测」。

### 5.6 历史复盘重跑

- 复盘页头部：若 `rule_version` 不是当前版本，显示 **「用新口径重跑」** 按钮（次要按钮）；
- 点击 = 走既有分析流程（`force`），生成**新复盘**；旧复盘与其快照保留、可回看；
- 重跑中按钮转圈禁用；完成后新结论替换当前展示。

## 六、用户故事

**故事 1（定位到句子）**
作为博主，我打开一条 85 秒的视频复盘，看到「留存流失点」：00:04–00:06 下降 12.4 个百分点，对应原话「很多人以为简历改得越漂亮越好」。我知道不是开头第一句的问题，而是第二句开始讲背景，下一条直接把结论提到第 4 秒前。

**故事 2（不被误判）**
作为博主，我这条视频推荐流量只有 43%，其他来自关注和主页。复盘提示「推荐流量偏低，不能单独归因于文案」，完播低的结论标为「推测」。我不会因为这条结论去大改文案，而是先看选题和粉丝结构。

**故事 3（补齐数据）**
作为博主，我看到数据看板显示「待补 255 条曲线」，点一次补齐，去忙别的；回来通知告诉我成功 251、失败 4 并列出失败作品名。之后每一条老作品的复盘都能看到曲线。

## 七、验收标准

1. **曲线覆盖**：平台实际返回趋势的作品 100% 入库；实测平台只对**部分**作品返回（主博主 259 条里 16 条有曲线，243 条平台无数据），无数据的作品标记 `unsupported`、7 天内不重复请求，`coverage` 分别展示 covered / pending / unsupported；
2. **句子对齐**：抽 10 条有句子时间轴的复盘人工核对，**≥8 条**「展示的句子确实是该时间区间说的那句」；
3. **不硬指认**：无时间轴或 `reliable=false` 时，页面不出现任何句子引用，且有空态说明；
4. **分诊生效**：推荐占比 <50% 的作品出现提示条，涉完播结论 `judgement_type=hypothesis`；时长 >120 秒的作品出现时长提示；
5. **基线分桶**：同桶样本 ≥5 时，页面展示「同类（60~120 秒）样本 N 条」，切换/不满足时退回全量并标注；
6. **重跑**：旧复盘不被覆盖，重跑生成新的 `video_review`，`rule_version=2`；
7. **非实时**：补齐任务有进行中动效，切页/刷新回来仍显示进行中，完成后通知；
8. **工程**：`scripts/verify.sh` 全绿（ruff/mypy/pytest/前端 lint+vitest+build/文档一致）+ Playwright 桌面 1440、1280 与移动 390 点检 0 console error、0 横向滚动；
9. **成本**：一次补齐 ≤ 当日 TikHub 剩余额度；不超发（沿用预算原子扣减）。
