## 一、需求背景

### 1.1 现在的情况（小白也能看懂）

R-257 之后脚本工作台是「一行 4 个」的卡片网格。网格有一个默认行为：**同一行的卡片会被强行拉成一样高**（高度取这一行最高的那张）。

作者截图里的例子：

- 有一张卡片带「上次双模型讨论中断…」的黄色提示条，内容多、高度更高；
- 它右边的卡片内容少很多，却也被拉到同样高，下面留出一大块空白；
- 整面墙看起来一排一排很整齐，但空白多、不紧凑，也不像小红书那样有错落感。

实测（1440 宽、4 列）：

| 行 | 改前卡片高度 | 说明 |
|---|---|---|
| 第 1 行 | 全部 216px | 最高卡决定 |
| 第 2 行 | 全部 **327px** | 含 AI 讨论中断提示的卡最高，其余 3 张也被拉到 327px（各有约 111px 空白） |
| 第 3 行 | 全部 216px | 最高卡决定 |

### 1.2 想解决什么

- 每张草稿卡**按自己的内容高度**显示，不再被同行卡片拉高；
- 多列之间像小红书一样**错落排列**（下一张卡紧接在本列上一张卡下面，不等其它列）；
- 标题仍然**最多两行**，超出部分省略，避免长标题把卡片撑太高。

## 二、想要实现的目标

| 目标 | 可验收标准 |
|---|---|
| 卡片高度不固定 | 同一屏内卡片高度可以不同（实测 1440 下出现 147 / 195 / 196 / 215 / 306px 等多种高度）；内容少的卡片下方不再出现被拉高的空白 |
| 小红书式瀑布流 | 1440 宽 4 列、1920 宽 4 列、1280 宽 4 列、1024 宽 3 列、768 宽 2 列、390 宽 1 列；每列独立上下排列、列底参差；各列卡片数量尽量均衡（12 条草稿在 4 列下为 3/3/3/3） |
| 标题最多两行 | 每张卡标题 `line-clamp: 2`，超过两行显示省略号；1 行标题的卡片比 2 行标题的卡片更矮（不再强制占两行高度） |
| 删除/改状态不整墙跳 | 删除一张草稿或点「采用」让卡片离开当前 tab 时，**其余卡片不换列**，只在本列内平滑上移；删除卡原地淡出（不飞到别处） |
| 不引入新问题 | 卡内「记反馈」展开时卡片在本列内变高、其余列不受影响；切换 tab / 空 tab / 加载骨架屏正常；六档宽度均无横向滚动、0 console error |

## 三、页面数据来源（本次不改数据）

| 页面/区域 | 数据来源 | 更新时机 | 缺失/失败表现 |
|---|---|---|---|
| 草稿卡列表 | 现有 `GET /api/drafts?limit=500`（按 `updated_at` 倒序；tab 在前端按 `status` 过滤） | 进入页面 / 切 tab / 新建 / 删除 / 改状态后刷新 | 空 tab 显示既有占位文案；请求失败显示既有错误态 |
| 草稿卡内容 | 标题、来源、生成模型、像作者占比、状态、反馈等既有字段 | 随列表数据 | 无标题显示「（无标题）」；反馈未写显示「记反馈」 |
| 每列列数 | 浏览器视口宽度 + 断点（640 / 1024 / 1280） | 窗口尺寸变化实时重算 | 非数据项，无空值 |
| 卡片列位置 | 前端按「各列卡片数最少优先」分配，并记住每篇草稿所在列 | 新增草稿时分配；删除/改状态不重排 | 非数据项，无空值 |

不新增/修改任何接口、字段或数据库表。

## 四、功能需求

### 4.1 卡片高度按内容自适应

- 草稿卡高度由卡片内容（标题行数、来源／模型／占比徽标、AI 讨论状态条、已发布链接、表现数据、操作按钮、记反馈区）自然决定；
- 同一列内下一张卡片紧接上一张卡片下方（间距 12px），不同列互不影响；
- 卡片不再被同行最高的卡「拉伸」，移除原来的固定行高/拉伸行为。

### 4.2 小红书式瀑布流排列

- 列数断点与 R-257 一致：**<640px 1 列 / 640~1023px 2 列 / 1024~1279px 3 列 / ≥1280px 4 列**；
- 新加入的草稿放到「当前卡片最少的那一列」，尽量让各列高度/数量接近；
- 每列内部保持「最新在上」的原有顺序；
- 删除、采用、不采用等让卡片离开列表的操作，**其余卡片保持原列**，只在各自列内上移（不重新洗牌）；
- 窗口宽度变化导致列数变化时，重新分配到新列数（一次重排可接受）。

### 4.3 标题最多两行

- 每张卡标题最多显示 **2 行**，超出省略（浏览器标准 `line-clamp` 行为，悬停可看浏览器 title 提示由既有编辑抽屉承担）；
- 标题 1 行时卡片更矮（取消原先强制 2 行标题高度的 `min-h-10`），让瀑布流更自然；
- 标题字号、粗细、行高、颜色不变。

### 4.4 边界与不做

| 项 | 处理 |
|---|---|
| 空 tab | 保持既有「暂无草稿…」占位，不渲染空列 |
| 加载中 | 骨架屏按当前列数渲染等宽骨架（每列至少 2 张），数据到达后不横向跳版 |
| 卡内「记反馈」展开 | 只在卡片所在列内变高，其余卡片不发生换列 |
| 其它页面 | 素材库、看板、复盘、对标等页面列数/布局不动 |
| 不做 | 不改卡片字段、按钮、tab、筛选、删除确认、编辑器；不改接口/后端/数据库；不引入第三方瀑布流库 |

## 五、用户故事

1. **作为** 每天在脚本工作台找稿的作者，**我希望** 每张草稿卡按自己的内容显示高度，**这样** 不会因为旁边有一张带提示条的卡就多出一大块空白。
2. **作为** 有 12 条以上草稿的作者，**我希望** 卡片像小红书一样一列一列错落排下来，**这样** 一屏能看到更多草稿标题，找稿更快。
3. **作为** 经常写长标题的作者，**我希望** 标题最多两行自动省略，**这样** 卡片不会被超长标题撑高，整面墙保持整齐。
4. **作为** 会删稿的作者，**我希望** 删除或采用一张草稿后其它卡片不要整面墙乱跳，**这样** 我能继续在原位置找回刚才看的稿。
