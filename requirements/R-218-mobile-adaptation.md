## 现状排查（实施前，Playwright 实测 320 / 390 / 412px）
**页面级几乎没有横向溢出**，问题不是「撑破屏幕」，而是**桌面布局被硬挤**，个别页面是真坏：

| 页面 | 实测结果 |
|---|---|
| 主页 | 基本可用（顶栏偏挤：通知 +「进行中 N」+ 主题挤在一行） |
| 人设档案 | 基本可用 |
| 灵感随手记 / AI 对话 | 基本可用 |
| 脚本工作台（列表+抽屉） | 可用但挤：表单单行两列、**tab 栏「版本」被右边缘裁掉**、底部「保存/定稿」遮住正文 |
| AI 设置 | 挤：`Kimi（月之暗面）` 折成「月之暗／面」、API Key 输入框与占位文字被裁、底部一行被裁 |
| **博主管理** | **真坏**：账号数据行被挤成**一行一个字**竖排（「抖／音」「粉／丝／5.4w／·／作／品／410」），时间线是 **7768px** 的横向长条 |
| 素材库 | 列表基本可用，抽屉未逐项展开（本轮一并细查） |
| 登录页 | 基本可用 |


**系统性问题**：① 触控目标普遍 `h-9`（36px，低于 44px 建议值）；② 局部字号低至 10px；③ 抽屉 `width=min(680px, 96vw)` 在手机上留 4vw 缝、非全屏；④ 无 `env(safe-area-inset-*)` 处理（iPhone 底部横条会压住底栏）；⑤ 移动端导航仍是「汉堡 + 侧滑抽屉」（R-205 只修了它的退出动画）。

## 反问与确认结论（2026-09-30）
1. **使用场景（决定优先级）**：作者在手机上要干四件事——**① 看数据/看概览**（主页、博主管理、博主对标）、**② 看稿背稿**（脚本工作台）、**③ 随手记灵感/写草稿**、**④ 审核与改稿**（抽屉里改正文、定稿）。
   **明确不包含**：用手机录像（R-215 的录像不手机化）、「只是应急看一眼」的低要求档。
2. **适配深度**：作者选**最深一档——「连导航一起做移动端重构」**：不只是让桌面布局收缩，而是**导航结构本身移动端化**（底部 Tab 栏 + 「更多」）。
3. **底部 Tab 栏内容（定型）**：**主页 / 素材库 / 脚本工作台 / 灵感 / AI 对话**（5 个）；
   **其余全部收进「更多」**：博主对标、博主管理、人设档案、AI 设置。
4. **最小适配宽度**：**320px 起**（iPhone SE / 老机型也不横向溢出）。
5. **提词器**：作者明确**本期先不管提词器**（`#/prompter/:draftId` 不做手机适配，也不手机化录像）。**但「脚本工作台看稿」在范围内**。
6. **验收方式**：作者选**「模拟视口 + 截图 + 探针，我自验」**——我无法真机验证（只有 Playwright 模拟视口），故以 320/375/390 三档逐页探针 + 截图矩阵自验，真机由作者抽空复验。
7. **动效（R-175 / 反问清单第 9 项）**：底部 Tab 选中态用共享 layout 滑块（比照 R-204 的 `ui/tabs.tsx`）；**断点切换（桌面↔移动）不得闪白**——用 CSS 断点控制显隐而非 JS 条件渲染，避免挂载抖动与首帧空白；页面转场保持现状；**不从 `opacity:0` 起步**；尊重 `prefers-reduced-motion`。
8. **非实时返回（R-202 / 反问清单第 10 项）**：**适用**——移动端顶栏的「进行中 N」指示器必须保留且可点开（现顶栏空间紧张，需改为紧凑形态而非砍掉）。
9. **成本与性能**：零 API 成本、零 LLM 成本；纯前端；**后端零改动**。移动端首屏资源已按路由懒加载（`React.lazy`），本次不新增依赖（不引入 UI 框架，继续 Tailwind v4 + 现有 shadcn 组件）。
10. **依赖与风险**：无外部服务依赖。风险=「导航重构」会改动所有页面的外层容器，需回归全部现有 headless 点检（r206/r212/r213/r214/r217）防回归。
11. **数据**：无需新表、无需新接口、无数据迁移。
12. **优先级**：现在做。

## 范围（本期）
### A. 基座与导航（M218）
- **底部 Tab 栏**（`< md` 显示）：主页 / 素材库 / 脚本工作台 / 灵感 / AI 对话；选中态共享 layout 滑块；`env(safe-area-inset-bottom)` 留白。
- **「更多」入口**：博主对标 / 博主管理 / 人设档案 / AI 设置（底部 sheet，带入场/退出动画，遵守 R-205 的「受控 animate + 延迟卸载」）。
- **桌面侧栏保留**（`md+`）；移动端不再以侧滑抽屉为主导航路径（保留与否在实施时定，但以底部 Tab 为准）。
- **顶栏移动端瘦身**：页面标题 + 通知 + 「进行中」（紧凑形态，**不砍功能**）+ 主题；搜索框在移动端已是 `hidden sm:block`，保持。
- **抽屉/弹窗移动端全屏化**：`Drawer` 在 `< md` 时 100vw（去掉 4vw 缝）；弹窗 `< md` 近全屏、底部操作区固定且不遮内容。
- **系统基线**：移动端触控目标 ≥44px、字号下限 12px、`env(safe-area-inset-*)`、移动端不依赖 hover。
- **断点约定**：`md = 768px` 为「移动 / 桌面」分界，全站统一。

### B. 逐页适配（M219）
按作者场景排优先级：
- **P0（看数据）**：**博主管理**（修账号数据行「一行一字」竖排 → 卡片/网格；时间线移动端改纵向或滑动容器 + 渐隐提示）、主页、博主对标。
- **P0（看稿/改稿）**：**脚本工作台**（列表卡片化、tab 栏不裁切、底部操作条不遮正文、抽屉全屏化后表单改**单列**）。

- **P1**：素材库（列表与抽屉）、AI 对话（输入框 + 键盘遮挡）、人设档案、AI 设置（标签不折字、输入框不裁）、登录页复核。
