## 背景与根因

以 draft 128 留痕为例：初稿（deepseek-flash）谈自由职业/兴趣驱动，评审方 kimi-k2.6 三轮批评把稿子拉回求职主线——方向对，但评审在"修改建议"里直接发明了第一人称素材（公司倒闭欠薪、投递转化数字、简历造假操作），生成方照单全收。终稿全是作者没说过的话、没做过的事，还含教唆简历造假这种不能播的内容。

机制根因：
1. `debate.py` 评审/修订提示词只禁"编造数字/人名/机构"，**没禁"替作者发明亲身经历"**；
2. 联网证据 + 站内素材只在**初稿那一轮**注入（`generation_user_message(..., evidence_block)`），第 1~N 轮 critique/revise 都看不到证据块——评审想让论据"具体"时只能凭想象编，越编越真；
3. 生成后自检（`_self_check`）只查红线，对"第一人称经历是否来自素材"零校验。

作者 feedback insight（id 91~95）已反复毙掉"教造假/灰产/不可验证个例"，但机制上没有堵住。

## 作者确认的边界

1. 事实只能来自：**注入的联网证据 / 站内素材 / 作者上下文（人设、ASR 转写、范本、金句锚点）里已有的内容**；修订轮与评审轮都必须能看到同一份证据块。
2. 缺支撑时的正确姿势：建议"这里需要作者的真实经历补充（标注【需作者补充】）"，**而不是编一个填上**。
3. 不新增"编造检测"的机械校验（做不到可靠，只会误伤）；靠提示词硬规则 + 证据可见性解决。

## 实施

- `debate.py`（普通选题讨论 + 参考改写讨论两条链路）：
  - 评审 system / 修订 system 各加一条硬规则：**严禁替作者发明第一人称经历、具体数字、公司/人名；事实只能用注入证据与作者上下文里已有的；缺素材就标【需作者补充】**；
  - `evidence_block`（联网证据 + 站内素材）从"仅初稿"改为**每轮 critique / revise 都注入**（洗稿链路已是每轮注入，对齐之）。
- `generation.py` 的 `GENERATION_SYSTEM` 默认提示词同步补一句同等硬规则（DB 无启用版时兜底的就是它）。
- 测试：构造假 LLM 捕获各轮 messages，断言 ①修订/评审消息含证据块；②两个 system 均含禁编造经历规则。

## 验收
