# R-143 各功能 LLM 预算做成可配置（AI 设置内，保存即生效）

- **日期**: 2026-09-12
- **状态**: ✅ 已完成（2026-09-12，M132）
- **关联**: R-139（模型路由/降级）、R-142（推理预算定标与校准护栏）、`services/budget_settings.py`、`api/settings.py`、`PromptsView.vue`

## 原文（作者原话，未改动）
> 要

（上下文：作者选定「保留显式上限、按实测定标」方案 A 后，AI 追问「要不要把各功能预算也做成可配置项（放进 AI 设置，
像讨论轮次那样保存即生效，不用改代码就能调）」，作者答「要」。）

## 范围
1. 新增 `services/budget_settings.py`：**各功能预算**的唯一定义与读写
   - `SLOTS`：可配置项（key / 中文名 / 默认值 / 说明），覆盖脚本生成各步与长输出功能；
   - `budget_for(db, key)`：生效值 = `max(用户设置, 厂家下限)`；`db=None` 时自己开短连接（线程池场景）；
   - `save_budgets(db, {...})`：校验「未知 key / 非整数 / 越界」并给出可读原因；
   - `reset_budgets(db)`：清空覆盖、回到代码默认。
2. 调用点全部改为读配置：脚本初稿/评审/修订、对标洗稿、对标可讲分析、人设归纳合并、转写校对、提示词优化、AI 对话。
3. 接口：`GET/PUT /api/settings/models` 增加 `budgets`（**不新增路由**，仍是同一个「保存即生效」按钮）；
   PUT 支持 `reset_budgets: true`。
4. 前端「AI 设置 → 模型设置」新增「推理预算（高级）」区块：每项一个数字输入 + 默认值/下限提示 + 恢复默认。
5. 保留 R-142 的护栏：`max_tokens` 仍是上限、厂家下限仍由校准护栏测试保护；
   用户把值设到下限以下时，界面显示的是**实际生效值**（会被抬到下限），不制造错觉。

## 不包含
- 不允许把预算调到厂家下限以下（那正是「思考吃光正文」的成因，护栏不放行）；
- 不暴露「短 JSON」类调用（广告判定 300、语义复核 500 等）——它们故意很小，暴露只会被改坏；
- 不改讨论轮次 / 每日篇数（已在同一页，各自独立）。

## 实施补充（2026-09-12）
- 实施中发现「厂家下限 12000」会把所有小功能的配置压平（默认 4000 的项生效值全变 12000，
  界面上「默认 4000 / 生效 12000」自相矛盾）。已把下限退回 **4000** 定位为安全网，
  按任务标定交给 `SLOTS`；校准护栏相应拆成「下限是合理安全网」+「长输出功能默认值覆盖实测最坏值」两条。

## 验收标准
1. 设置页能改各功能预算，保存后**立即生效**（无需重启），返回体带生效值；
2. 非法输入（未知 key / 非整数 / 越界）返回 400 且原因可读；
3. 生效值不低于厂家下限（设小了会被抬高，界面显示真实生效值）；
4. 「恢复默认」可一键回到代码默认值；
5. 有测试覆盖（默认值 / 保存回读 / 下限抬升 / 非法拒绝 / 调用点确实用了配置）；
6. `scripts/verify.sh` 全绿；接口冒烟；前端点检；服务保持运行。
