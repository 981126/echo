# R-148 需求管理页 UI 溢出修复（标题 slug 残渣 + 表格长串不换行）

- **日期**: 2026-09-12
- **状态**: ✅ 已完成（2026-09-12，M137）
- **关联**: `core/requirement_file.py`、`styles.css`、`RequirementsView.vue`

## 原文（作者原话，未改动）
> 需求管理这个页面，ui都超出了浏览器边界了

## 复现与根因（2026-09-12 实测，非推测）
- 需求列表有 145 条，其中 **108 条标题被文件名 slug 污染**，形如
  `-HISTORY-IMPORT: 历史内容导入与转写、人设初始化`（H1 原文是 `# R-001-HISTORY-IMPORT: …`）。
  原因：解析器 `^#\s+(R-\d{3})[::\s]*(.*)$` 只剥掉 `R-001`，把紧随其后的 `-SLUG` 留在了标题里。
- 这些 slug 是 **33 字符无断点的 ASCII 串**（`-DOWNLOAD-TIMEOUT-ASR-FAIL-NOTIFY`）。
  表格是 `width:100%` + `table-layout:auto`，单元格又没有 `overflow-wrap`，
  于是「min-content 宽度」被长串撑大 → 表格比 `.page`（`max-width:920px`）还宽 → **整页横向溢出**。

## 范围
1. **解析层清洗标题**（不改需求文档 —— `requirements/*.md` 是事实源，原文不可改）：
   - 老式 `# R-094-DOWNLOAD-TIMEOUT-ASR-FAIL-NOTIFY: 中文标题` → 标题取 `中文标题`；
   - 新式 `# R-110 博主页同步按钮防重复入队` / `# R-141: 邮件是次要通道…` → 原样保留；
   - 保守规则：只有当 ID 后面**紧跟 `-` 且 slug 以 `:`/`：` 结尾**时才剥（实测 108/108 条都带冒号，
     避免把 `# R-148-API 接入…` 这类正常标题误伤）；剥完为空则回退原值。
2. **样式兜底**（换个字段也可能再有长串，得让表格永远撑不破容器）：
   - `.table th/td` 加 `overflow-wrap: anywhere`（**关键**：影响 min-content 宽度计算）+ `word-break: break-word`；
   - 新增 `.table-wrap { overflow-x: auto; }` 工具类，需求页表格包一层做横向滚动兜底。

## 不包含
- 不改写任何 `requirements/R-*.md` 的原文（含标题）；
- 不重构需求页 UI（列表/筛选/编辑等）；
- 不引入前端测试框架（沿用契约断言 + 渲染宽度不能自动测，见验收说明）。

## 第二轮修正（作者指出「只是把溢出藏起来了」之后）
第一版只加了 `.table-wrap{overflow-x:auto}`，`pageOverflow` 确实变 0，但用 headless Chrome 量出来
**表格宽度恒为 1067px**（1440 视口的容器只有 878px），仍要横向滚动 —— 作者说得对，那是**圈起来**不是修好。
续查各列宽度发现真凶：`编号 54 / 标题 180 / **状态 805** / 摘要 29`，即 `table-layout:auto` 把剩余空间
全给了「状态」下拉列，加上单元格内联 `min-width` 一起把表格撑宽。
最终改为 **`table-layout: fixed` + 显式列宽**（去掉内联 min-width、下拉框 width:100%），
实测表格宽度跟随容器（878/775/575/675）、**表格内溢出 0**。

## 验收结果（2026-09-12）
- 接口返回的标题已全部人类可读：`R-001 → 历史内容导入与转写、人设初始化`；`R-094 → 下载卡住兜底 + 转写原因/通知`；
  新式标题（`R-110`、`R-141`）保持不变。
- 全量护栏测试通过：`requirements/` 下所有 H1 解析后**无 slug 残渣、无 slug 形态长串**
  （护栏先抓到 `DeepSeek-V4.1-Flash` 属误判，已把判据收紧为「slug 形态」+「≥30 字符极长串」）。
- 样式契约测试通过（`overflow-wrap: anywhere` + `.table-wrap` + **固定列宽布局**，且禁止内联 `min-width` 回潮）。
- **headless Chrome 实测**（1440/1100/900/760 四档）：需求页 `页面溢出=0`、`表格内溢出=0`；
  全站 9 个路由扫描 `页面溢出=0`（首页时间线与提示词 tab 条为设计上的内部滚动）。

## 验收标准
1. 需求接口返回的 145 条标题里，**不再有以 `-SLUG` 开头的残渣**，也没有 15 字符以上的不可断 ASCII 片段（有测试，直接对真实 `requirements/` 目录跑）；
2. 新式标题（`R-110 xxx` / `R-141: xxx`）解析结果保持不变（有测试，防误伤）；
3. `styles.css` 里表格已有长串换行规则（有契约测试）；需求页表格有横向滚动兜底；
4. `scripts/verify.sh` 全绿；接口冒烟确认标题为人类可读。
