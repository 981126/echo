## 原文（作者原话，未改动）
> 先别做，提词器还需要一个视频录像功能，可以让我直接录视频

（上文背景：作者已确认要提词器，且确认可把笔记本摆到镜头正下方；现场用 Insta360 Ace Pro 录到卡里、后期剪映。）

## 现状排查（实施前）
- **后端已具备接收能力，零改动**：`backend/app/api/videos.py:28` 的 `VIDEO_EXTS` 已含 `.webm`；`POST /api/videos/upload`（:75）落盘到 `videos_dir` 并建 `Video` 记录（R-058 改名为「标题-视频」）；`inbox` watcher 同样识别 `.webm`。
- **相机可作 UVC**：Ace Pro 官方支持「连接电脑作为 Webcam」（Insta360 官方教程 / Webcam 模式），浏览器 `getUserMedia` 可直接取流，无需驱动。
- **浏览器录制格式事实**：`MediaRecorder` 在 Chrome 稳定支持 **WebM（VP8/VP9 + Opus）**；MP4/h264 部分版本支持但存在**产出损坏文件**的已知缺陷（Chrome bug/社区报告）→ 因此**以 WebM 为可靠基线，MP4 仅在 `isTypeSupported` 通过时才尝试，不做承诺**。
- **UVC 输出即相机内部已压缩画面（通常 1080p）**，浏览器无法提升画质上限。

## 反问与确认结论（2026-09-29）
1. **画质取舍**：作者选择**「1080p 够用，要浏览器直接录最快路径」**（已看过 macOS Photo Booth 的相机模式画质）→ 不再要求 4K，录像功能成立。
2. **收音**：**先用笔记本内置麦克风**（先跑通；设备选择器保留，随时可换 USB/无线麦接收器）。**不新增依赖、不接外部服务**。
3. **文件去向**：**直入素材库 + 同时可下载**（推荐项）→ 录完一键 `POST /api/videos/upload` 入库（单用户局域网，无隐私顾虑），随后可走现有转写/复盘链路；同时给【下载】留一份本地文件。
4. **录制控制**：**倒计时 + 空格开始/停止 + 重录**（不做分段重录拼接、不做录后强制回放关卡）。
5. **与提词器同页**：录像与提词**同一个全屏页面**（本次与 R-214 合并为一批交付）——录制中要能一边看字一边看状态，切页会打断。
6. **只读稿子**：录制不修改草稿（不回写、不标记已用；是否「采用」仍由作者在草稿页决定）。
7. **动效（R-175）**：录制中**只允许必要的状态动效**（REC 红点呼吸、时长跳动），提词正文区**零动画**；停止/重录的状态切换用 `softIn`（不从 `opacity:0` 起步）。
8. **后端零改动**：复用既有上传接口与表结构；**不新增接口、不新增表、不新增定时任务、无 LLM 成本**。

## 交互/技术规格（本期）
- **页面**：`#/prompter/:draftId`（顶层路由，无导航/顶栏）；顶部一条状态带（REC 红点 + 已录时长 + 剩余预估 + 输入设备），右侧小窗实时预览（**不遮挡正文**，可开关）；正文区同 R-214。
- **设备**：`getUserMedia({ video: {width:1920,height:1080,frameRate:30}, audio: {echoCancellation:false, noiseSuppression:false} })`；进页面先列 `enumerateDevices()`，默认选**内置麦克风**与 UVC 相机；无权限/无设备给明确文案与【重试授权】。
- **格式协商**：依次探测 `video/mp4;codecs=avc1.42E01E,mp4a.40.2` → `video/webm;codecs=vp9,opus` → `video/webm;codecs=vp8,opus` → `video/webm`；**当前实际使用哪种格式在状态带明示**（避免作者以为拿到 mp4）。MP4 若录制后校验异常（时长为 0/无法解码）→ **自动退回 WebM 重录**并提示。
- **录制**：3 秒倒计时（`Esc` 可跳过，`-`/`+` 可调）→ `MediaRecorder` 以 1s `timeslice` 持续收块；同时**所有块留内存**（1–2 分钟 1080p WebM 约 50–100MB，安全）；若浏览器支持 File System Access API 且作者愿意，可选择落盘句柄**边录边写**，避免长录占内存（内存副本仍保留，保证中途出问题也不丢）。
- **键盘**：录制前 `空格`=开始；录制中 `空格`=停止（**停止优先于播放/暂停**，避免录制时误暂停提词）；`Esc`=停止并退出；其余提词快捷键同 R-214。
- **录制中**：提词自动开始匀速滚动（滚动速率与「中文约 4 字/秒」的语速预估联动）；已录时长累加；停止时提词暂停。
- **录后**：内联回放（`<video>`）+【重录】（丢弃当前块并复位）/【下载】（`<a download>`，文件名 `<草稿标题>-YYYYMMDD-HHmm.webm`）/【存入素材库】（`uploadFile('/api/videos/upload')`，成功后 toast + 【去素材库】，**不自动转写**，与 R-033 口径一致）。
- **上传**：`FormData` 单文件，与素材库上传同一接口；失败给明确错误 + 【重试】（**已录内容不丢**）。
- **安全阀**：单次录制超过 **5 分钟**提示并自动停止（内存与上传体积护栏）。
- **不做**：分段重录/拼接、云转码、自动发布、提词页内改稿、多机位、滤镜/美颜。
- **已知限制（对作者明示）**：① WebM 在剪映/PR 里不如 MP4 顺（本期不做云转码；如需 MP4 可后续加一条本地 ffmpeg 转码任务）；② 笔记本内置麦面向键盘与房间噪音，正式录制建议后续换 USB/无线麦；③ 画质上限=相机 UVC 输出（1080p）。

## 实施记录（2026-09-29）
- **新增文件**：`frontend_v2/src/pages/prompter/recorder.ts`（纯逻辑）+ `recorder.test.ts`（20 例）+ 页面内录制部分（`pages/prompter/index.tsx`）+ 点检脚本 `frontend_v2/r214-prompter.mjs`。
- **格式协商与降级**：`pickRecorderMime` 按 `mp4/avc1 → webm/vp9 → webm/vp8 → webm` 逐个问 `MediaRecorder.isTypeSupported`（抛错视为不支持），
  状态带显示 `formatLabel(recorder.mimeType || 协商值)`；录后用 `validateRecording(size, duration, mime)` 校验——**MP4 读不出有限时长即判损坏**
  （`probeDuration` 用「大步 seek」逼出 WebM 的真实时长），失败则 `forceWebmRef = true` + 提示重录，符合规格的「自动退回 WebM」。
- **状态机**：`idle → countdown → recording → recorded`（`reset` 回 idle），`spaceAction` 把「停止优先」写成可测的纯函数。
- **内存与安全**：块留内存（1s timeslice），5 分钟自动停；未落地 File System Access 边录边写（规格里是「可选」，本期不做，已在此记录）。
- **预览不遮挡正文**：预览小窗打开时给滚动容器加右侧 316px 空带（`paddingRight`），正文列随之左移，点检用几何断言锁死（预览左沿 ≥ 正文右沿）。
- **Esc 语义**：按规格「停止并退出」——录制中按 Esc 会停止录制并回草稿列表（本次录制不自动入库）。
