# R-128 AI提示词候选版：逐篇提取人设 → AI 归纳去重 → 增量与全量 5% 对齐

- **日期**: 2026-09-08
- **状态**: ✅ 已完成
- **排期**: M110 / M111 / M112（已完成）
- **关联**: R-021（提示词版本）、R-022（自动优化候选）、R-002（人设档案）、R-057（风格学习）、R-126（逐篇喂 AI）、PersonaService / ingest.persona_init_task / prompt_service.optimize

## 原文（作者原话，未改动）
> 【ai提示词】每次自动生成的候选版本感觉对我的人设分析的不到位
> 1.应该分析我的每一篇文案，从每篇文案中提取我的人设，然后总结去重
> 2.主博主每次有新的已发布素材，对人设进行增量操作，确保每次增量操作后产生的候选版，要和从头开始分析每一篇提取总结去重得出的结果相差不超过百分之5%
> 3.确保提示词高质量符合人设，提示词不应该限制ai的深度学习，只是为了让他有个大概的方向盘。

## 反问与确认结论（2026-09-08，作者逐项选择）
1. **需求对象（范围）**：指 `PromptsView`「AI 基于最新素材优化（候选）」产出的**候选提示词版本**（vN candidate）。
   第 1、2 条是手段：把「人设分析」做扎实（逐篇提取 → AI 归纳合并 → 增量校验），让候选提示词真正带上作者人设。
2. **逐篇 → 总结去重落到哪一层**：在现有「逐篇提取 + 标签字符串去重」之上**新增一层「AI 归纳合并」**
   （逐篇提取 → AI 聚类归并 → 总结成结构化人设档案），而不是只删同名标签。
3. **5% 如何量化**：**混合口径**——先算标签集合覆盖率（增量档案覆盖全量档案的比例），再用 LLM 做语义复核打分（0-100）；
   两者都 ≥95% 视为达标。
4. **不达标的动作**：**自动回退为全量结果**（覆盖本次增量建议）并**通知作者**（失败/降级通知，可点进人设页）。
5. **成本与频率**：**每次新增已发布素材都实时全量重算对照**（最忠于原话，成本最高）。
   已知代价：全量重算 = 每篇一次 LLM 调用（当前约 65 篇）→ 约 65+ 次调用/次新增；按作者选择执行。
6. **提示词放开（第 3 条）**：**放开内容维度 + 保留 JSON 骨架**——人设维度由 AI 自定
   （语气/价值观/口头禅/选题偏好/受众/禁忌/内容结构…），程序只解析固定字段（tags/redlines 等）。
7. **验收展示**：**要界面展示**——人设页展示「本次增量 vs 全量基准」差异百分比与差异明细（缺哪些标签/维度）。
8. **优先级**：**现在做**，作为 R-128 立即排期。

## 现状与差距（代码事实）
- R-126 已实现 `persona_init_task` 逐篇调 AI（4 路并行）+ 标签字符串去重；但**没有 AI 归纳合并**这一层，
  不同措辞的同一特质（如「犀利敢说」vs「说话直接不绕弯」）会重复残留。
- 增量 `suggest_persona_updates`（import_video_task 内）只拿「已确认标签 + 单条新稿」让 AI 建议新标签，
  **不与全量重算结果做任何比对**，长期会漂移。
- `prompt_service.optimize` 的语料 `learning_material` 注入的是 `_persona_context`（仅 confirmed 标签），
  人设档案质量差 → 候选提示词人设味差。
- 现有默认提示词（`PERSONA_INIT_SYSTEM` / `PERSONA_UPDATES_SYSTEM` / `OPT_SYSTEM`）极简、硬约束，
  只要求「2-6 字标签」，限制 AI 归纳深度。

## 需求边界
- **包含**：人设逐篇提取 + AI 归纳合并档案；增量更新与全量重算的 5% 对齐校验与自动回退；候选提示词生成注入归纳后档案；
  人设提示词/优化提示词放开改写；人设页差异展示；新增任务与通知。
- **不包含**：对标博主人设；广告素材；改写生成/复盘/校对等其它功能提示词的硬约束（第 3 条只落到人设类 + 优化类提示词）；
  历史人设数据的自动回溯清洗（仅从本次实施后生效）。

## 验收标准
1. 「逐篇提取 → AI 归纳合并」产出结构化档案（维度自由、字段固定解析），同名/近义特质被合并，不再重复堆标签。
2. 新增素材触发增量：增量档案与实时全量重算结果做「集合覆盖率 + LLM 语义复核」，两者均 ≥95% 视为通过；
   <95% 自动回退为全量结果并发通知。
3. 人设页可见最近一次校验的差异百分比与差异明细。
4. 候选提示词（PromptsView 的 optimize 候选）语料注入归纳后的人设档案，候选版人设贴合度可感知提升。
5. 人设类/优化类提示词改为「给方向盘、不锁死思路」且仍输出可解析 JSON。
6. `scripts/verify.sh` 全绿；后端接口冒烟通过；前端关键交互点检通过；服务保持运行。
