## 澄清与确认结论（2026-09-12）
- **每日队列同步要写灵感池**：确认要（这才是 R-028/R-072 的本意）。
- **进池要限量**：确认限量，避免一天几百上千条灌进池子。
- **每日篇数口径对齐**：确认做（组候选与生成切片统一用「AI 设置」的每日篇数）。
- **端到端验证**：确认由 AI 手动触发一次每日流水线并实测灵感池。

## 背景（已查证的根因，非猜测）
1. **灵感池「评论」半边从 2026-09-06 起再无数据**（`topic_ideas` 787 行：09-05 81 条、09-06 706 条、之后 0 条），是 **R-093 的回归**：
   - 全项目只有 `_collect_comments()` 会写 `topic_ideas`；
   - 它只在 `with_comments=True` 时被调用，而 `queue_mode = with_media and scope == "daily"` → `with_comments = not queue_mode`；
   - 所有每日同步路径都是「daily + 带媒体」（定时 `run_daily_sync_all`、博主页「同步前15条」），于是全部走队列模式，
     队列里的 `sync_post_comments()` **只写 `platform_post_comments`、从不写选题池**；
   - 今日同步日志显示「采集评论 124/163 条」，灵感池却是 0 条 —— 注释「评论也由队列逐条采集」只兑现了「入库」，漏了「进池」。
2. **灵感池「热榜」半边为空**：热榜靠每日流水线的 `fetch_and_store()` 或首页「抓取更新」刷新；该库 `pipeline_runs` / `topic_candidates` 均为 0 行
   （每日流水线从未成功跑过），`hot_topics` 最后一批是 09-08，而接口只查当天 → 空。手动 `POST /api/topics/refresh` 实测可恢复（fetched 161）。

## 范围
1. **进池路径统一**：把「评论 → 选题池」抽成一个共享函数，`_collect_comments()`（非队列：全量/每周）与
   `sync_post_comments()`（队列/单帖）都调用它，保证任何同步方式都能填充灵感池。
2. **进池限量**（默认值，可用 `.env` 覆盖）：
   - 每条作品最多进池 **8** 条（按点赞降序取）；
   - 每个博主每天最多进池 **40** 条；
   - 仍沿用「标题 ≥4 字」与「(source, title, snapshot_date) 去重、点赞取大」的既有口径。
3. **可观测**：同步任务说明里汇报「灵感池新增 N 条」，不再只有「采集评论 N 条」。
4. **每日篇数口径对齐**：`run_daily_pipeline` 里组候选与生成切片统一用 `app_kv` 的每日篇数
   （现在组候选用的是 `.env` 的 `pipeline_topics_count`，会出现「候选 3 条、实际生成 1 条」的显示不一致）。
5. **端到端验证**：手动触发一次每日流水线，确认出稿 + `topic_candidates` 落库 + 灵感池有数据。

## 不包含
- 不改「灵感池」的读取与前端展示（仍按当天 + 当前主博主 + 未使用）；
- 不改热榜抓取本身，也不新增定时任务（流水线没跑是运行环境问题，不是代码问题）；
- 不做「灵感池自动清理/过期」策略（后续需要再单独立项）；
- 不改 `_collect_comments` 的「每条作品 Top50 评论」抓取量（抓取量影响预算，本次只限定「进池」条数）。

## 验收标准
1. `sync_account(..., scope="daily", with_media=True)`（队列模式）跑完后 `topic_ideas` 当天有新增 —— 有测试覆盖；
2. 限量生效：单帖最多 8 条、单博主当天最多 40 条 —— 有测试覆盖；
3. 非队列路径（全量/每周）行为不回退，原有「评论区选题进池」测试仍通过；
4. 同步任务说明含「灵感池新增 N 条」；
5. 每日流水线的组候选条数与实际生成条数一致（都取设置值）；
6. `scripts/verify.sh` 全绿；接口冒烟；前端点检；服务保持运行。
