> 设置粉丝专属福利引导关注：你视频里分享的转转筛选九成新手机、查看验机报告的干货内容价值很高，但目前没有给用户提供关注你的专属理由，你可以在展示验机报告的环节口播说明，你整理好了一份《二手手机线下验机避坑10条清单》，只有点关注成为你的粉丝之后，才能在评论区找你领取这份独家资料，同时承诺所有粉丝私信咨询二手购机的问题你都会逐一回复，让感兴趣的用户为了拿到专属权益主动关注你，有效拉高吸粉率。
> 如何优化完播率
> 开篇前置强悬念钩子，压缩无效铺垫时长：目前你的视频完播率比同赛道二手数码测评的平均水平低26.80%，核心原因是开篇铺垫太拖沓，前30秒都在讲背景介绍，没有第一时间抓住观众注意力。你可以把大家最关心的“1400元淘到原价5千多的小米14Pro有没有踩坑”的核心冲突直接放在视频前3秒，一开场就举着刚拆封的手机说“我自费在转转买的二手小米14Pro，刚拆箱就发现了个意料之外的问题”，直接把观众好奇心拉满，大家为了看后续的结果自然会留到视频最后，大幅拉高完播率。
> 拆分干货节点搭配即时收益反馈，避免内容拖沓：你视频后半段的选机操作教程部分连续时长超过1分钟，没有拆分节奏，很多观众看到一半会觉得内容太啰嗦直接退出。你可以把选机的4步操作拆成3个独立小节点，每讲完一个操作步骤就立刻给观众对应的正向收益提示，比如讲完筛选成色的步骤后，立刻展示你手里这台9成新小米14Pro几乎零划痕的实拍画面，告诉观众按这个方法挑到手的机器几乎和准新机没差，让观众每看十几秒就能拿到实打实的干货收获，不会觉得内容冗余，能有效把中途退出的用户留住，完播率至少能提升20%以上。

## 现状核对（2026-11-02 代码检查）

1. **分析文字只做了润色**：`video_review_llm.enhance_findings()` 只把规则引擎生成的 findings 交给 LLM「整理成小白能懂的中文」，输入里**只有规则结论，没有文案原文**，所以现在页面上的原因/建议无法引用视频里具体说了什么。
2. **指标维度缺两个关键项**：`video_review_comparison.SPECS` 有完播率、5 秒完播率、2 秒跳出率、封面点击率、粉丝增量等，但**没有「平均播放占比」和「收藏率」**，因此无法按这两个指标给差距。
3. **规则引擎是通用建议**：`video_review_rules.build_findings()` 输出的是「下一条先给结果」「检查中段是否重复解释」这类通用句，没有「前 3 秒甩什么画面 / 每 15~30 秒怎么拆 / 结尾加什么 CTA / 引用文案哪一句」这种可直接照做的动作。
4. **对比基准是本地历史**：系统里没有「同赛道大盘」数据源（TikHub 不提供），现有可算的基准是「发布者自己近 30 条相近作品在相同发布天数的中位数」。

## 一、需求背景

视频复盘的定位是「有依据地解释好/差 + 告诉作者下一条怎么改」。作者给出的期望示例（见原文）证明：**只有指标数字或只有通用建议都不够**，必须把「这条视频的指标差距」和「这条视频文案里具体讲了什么」结合起来，给出针对每个核心指标的、落到时间点和画面的改法。

## 二、想要实现的目标

视频复盘新增「**按指标优化建议**」，针对 4 个核心指标各生成 1 张建议卡：

1. **完播率**
2. **平均播放占比**
3. **收藏率**
4. **吸粉率**

每张卡必须同时包含：

| 字段 | 含义 | 要求 |
|---|---|---|
| 指标差距 | 当前值 vs 对比基准，差多少 | 数字必须来自程序计算的真实数据 |
| 原因分析 | 为什么低：指标层面 + 内容层面 | 内容原因必须引用该视频文案原句；内容推测要标明「推测」 |
| 具体动作 | 3~4 条可直接照做的改法 | 必须落到具体位置（前 3 秒 / 每 15~30 秒 / 结尾 CTA 等），禁止空话 |
| 文案依据 | 引用该视频文案原句 | 必须是转写稿的真实子串 |

## 三、页面数据来源

| 页面字段 | 数据来源 | 更新时机 | 缺失/空值表现 |
|---|---|---|---|
| 当前指标值（完播率、平均播放占比、收藏率、吸粉率） | 本地已同步的 `douyin_post_metrics`、`platform_post_stats`（数据本身来自 TikHub 创作者中心/公开接口） | 生成复盘时读取；点「更新数据并分析」先刷新再生成 | 该指标为空 → 不生成该指标卡，不显示 0 充数 |
| 对比基准（中位数） | 程序计算：该账号最近 30 条相近作品、相同发布天数时的中位数 | 生成复盘时计算 | 可比样本 <5 → 指标卡标「参考样本较少」；无样本 → 不显示该卡 |
| 差距百分比 | 程序计算：当前值 − 基准值 / 基准值 | 生成复盘时计算 | 基准为 0 时不显示相对百分比 |
| 文案原句 | 本地 `transcripts`（ASR 转写，优先校对稿 corrected_text，否则 transcript_text） | 生成复盘时读取 | 无转写 → 只给指标建议，并提示「转写后可结合文案分析」 |
| 原因分析/具体动作 | 规则引擎兜底 + LLM 生成（基于上述真实数据） | 生成复盘时 | 模型不可用/输出校验不过 → 用程序规则生成；不阻塞复盘 |

## 四、口径与边界（作者已确认的默认结论）

1. **对比口径**：由于没有同赛道大盘数据，一律使用「**你自己近 30 条相近作品、同发布天数的中位数**」作为基准；页面/文案中**禁止**出现「同赛道/行业平均/同类账号平均」等无数据来源的表述。
2. **禁止承诺提升幅度**：不写「能提升 X%/至少提升 X%」，只写目标与动作。
3. **建议卡位置**：放在现有「这条视频为什么好或差」结论**之后**，作为新板块「按指标优化建议」，不改动现有内容。
4. **维度范围**：先做上述 4 个指标；2 秒跳出率、互动率等不单独出卡（保留在原有 findings 里）。
5. **文案缺失**：只给指标建议 + 一句提示；不编造文案。
6. **不做「一键采纳为改进计划」**：本期只展示建议，采纳仍走现有「改进计划」流程。
7. **判断类型**：指标差距是事实（fact）；从文案推断原因属于推测（hypothesis），页面要标注，避免让作者以为绝对成立。

## 五、功能需求（页面/字段/空数据/失败表现）

### 5.1 视频复盘页新增板块

- 位置：视频复盘页「这条视频为什么好或差？」结论列表**之后**、主题推荐之前（具体以页面最终排版为准）。
- 板块标题：**按指标优化建议**。
- 每张建议卡展示：
  1. 标题：`如何优化完播率` / `如何优化平均播放占比` / `如何优化收藏率` / `如何优化吸粉率`；
  2. 差距行：如「当前完整完播率 7.4%，你自己近 30 条相近作品在同发布天数的中位数是 12.1%（低 4.7 个百分点，样本 10 条）」；
  3. 判断标记：事实 / 推测；
  4. 原因：2~3 条，既讲指标层面，也引用文案原句（原句用「」标出）；
  5. 具体动作：3~4 条，每条以动作开头（如「把最冲突的结果前置到前 3 秒」），包含具体画面/时间点/话术建议；
  6. 文案依据：展示引用的原句。
- 顺序：按「完播率 → 平均播放占比 → 收藏率 → 吸粉率」固定顺序，只显示本次可生成（有指标值且状态偏低）的卡片；若一张都生成不了，展示空状态「这条视频暂无可用的按指标建议（指标或可比样本不足）」。

### 5.2 空数据/失败表现

| 情况 | 表现 |
|---|---|
| 无转写稿 | 只生成指标建议；卡片底部提示「没有文案转写，本次建议只基于指标；转写后可结合文案分析」 |
| 可比历史 <5 条 | 卡片标「参考样本较少，建议仅供方向参考」 |
| 某指标无值 | 不出该指标卡 |
| LLM 不可用/输出不合规 | 自动用程序规则生成（仍含真实数字与文案引用），页面不报错；复盘整体照常生成 |
| 复盘生成失败 | 沿用现有失败逻辑与提示，本功能不新增失败分支 |

## 六、不造假校验（必须满足）

1. 建议文字中出现的数字，必须是系统计算并传入的真实数字（当前值/基准值/差值/样本数/文案里已有的数字），否则该条建议作废；
2. 引用的文案原句必须是该视频转写稿的真实子串；
3. 禁止「同赛道/行业/大盘平均」「提升 X%」等无依据表述；
4. 内容原因必须标注为推测（hypothesis）；
5. 无数据时明确写「暂无数据」，不估算、不用示例值。

## 七、用户故事

作为博主，我打开某条视频的视频复盘，在「为什么好/差」之后能看到「按指标优化建议」：每张卡告诉我这个指标比我自己平时差多少、差的原因（引用我视频里的原话）、下一条具体怎么改（前 3 秒放什么、每 15~30 秒加什么、结尾怎么引导关注/收藏）。我不用自己猜，照着改就行。

## 八、验收标准

1. 用真实作品（如 1952「我真绷不住了」、1902「真实自费测评！转转买手机」）生成复盘后，页面出现「按指标优化建议」板块，至少 1 张指标卡；
2. 每张卡同时含有：真实指标差距数字、原因（含文案原句引用）、3 条以上具体动作、判断类型标记；
3. 全页搜索不得出现「同赛道」「行业平均」「提升 X%」等表述（有则视为不通过）；
4. 引用的文案原句能在该视频转写稿中逐字找到；
5. 无转写/样本不足时按第 5.2 节降级，不报错、不显示假数据；
6. `scripts/verify.sh` 全绿；后端接口冒烟 + 前端浏览器点检通过。

## 九、明确不做

- 不做同赛道/大盘对标（无数据源）；
- 不自动修改视频、不生成文案全文/分镜脚本（只给建议）；
- 不做「一键采纳为改进计划」（后续需求再议）；
- 不改现有复盘结论、主题推荐、同行爆款等既有模块。

## 实施结果（2026-11-02）

1. **页面**：视频复盘「这条视频为什么好或差？」之后新增「按指标优化建议」，作品 1952 真实复盘生成 **4 张指标卡**（完播率/平均播放占比/收藏率/吸粉率），每张卡包含真实差距、原因（引用文案原句）、3~4 条具体动作、文案依据、事实/推测标记。
2. **对比口径**：仍为「你自己近 30 条相近作品同发布天数中位数」；由于私有指标历史从 2026-10-30 才开始记录，同发布天数无快照时**退回最早可用快照作参考**（页面 sample_note 已注明），不写同赛道/行业平均。
3. **指标补齐**：`avg_view_proportion`（平均播放占比，取创作者 raw `metrics.avg_view_proportion`）、`favorite_rate`（收藏率，优先 raw `favorite_rate`，否则 favorites/plays）；公开统计缺计数时用创作者 raw 的 view/like/favorite count 补齐，保证比率型基准可算。
4. **建议口径**：指标低于自己历史中位数 → 标题「如何优化 X」；高于/持平 → 「如何继续提升 X」（差距行如实写「高/持平」，不硬说低）。
5. **校验落地**：LLM 输出经维度白名单、数字白名单（含允许的时间点数字 3/15/30/10 秒）、文案引用子串校验；不合规自动回退程序规则（实测首次生成失败时已正确回退并提示，不阻塞复盘）。
6. **无新表/无新路由**：建议写入 `video_reviews.metrics_snapshot["advices"]`，`GET /api/douyin-review/reviews/{id}` 响应新增 `advices`；旧复盘返回空数组。
7. **测试**：新增 5 个测试（对比指标、规则兜底数字/引用、校验拒绝假数字/假引用、旧快照空数组、标题高低区分），`scripts/verify.sh` 全绿。
