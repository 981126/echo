## 现状核对（2026-11-04 代码检查 + 逐帧复现）

1. `frontend_v2/src/pages/drafts/index.tsx` 中，草稿网格容器是 `<motion.div layout ...>`，每张卡片 `DraftTile` 的根节点是 `<motion.article layout ...>`，且每张卡带 `transition={{ delay: index * 0.03 }}`。
2. **复现**（Playwright 逐帧采样，真实删除一篇测试草稿；非测试数据）：
   - 删除第 1 张卡后，列表刷新；被删卡片先播完 `exit`（淡出+缩到 0.94）再移除，随后网格重排；
   - 剩余卡片的 `layout` 投影动画把「旧位置 → 新位置」做成动画：单帧位移 65~372px，一次删除中多张卡跨列/跨行移动；网格总高度变化时 Framer 的 layout projection 还出现非等比 `scaleY≈1.0757`；
   - 每张卡的 `delay: index*0.03` 叠加到 layout 动画上，导致不同卡片错峰起飞；卡片类名里的 `hover:-translate-y-0.5`（CSS transform）与 layout projection 的内联 transform 互相干扰；
   - 视觉上就是「其他的草稿飞出去」。
3. 该动画并非数据/接口问题：删除后列表数据正确、刷新后位置正确，只是动画呈现异常。

## 一、需求背景

脚本工作台删除草稿时，作者期望「被删的那张消失，其余卡片留在原位/轻微归位」，实际却看到其余草稿大面积飞动（跨列、缩放、错峰），看起来像页面出了 bug。

## 二、想要实现的目标

| 目标 | 可验收标准 |
|---|---|
| 删除时其他草稿不再「飞出去」 | 删除任意位置的一张草稿：被删卡片自身保留短暂淡出+缩小；其余卡片**平滑滑到新位置**，只有位置变化、没有缩放/拉伸变形、没有多卡错峰乱飞 |
| 重排动画可见（v2 作者反馈） | 其余卡片的位置变化能看到（约 0.2~0.3s 平滑滑动），而不是瞬间跳位；所有人同一时刻开始移动，不做 `index*0.03` 错峰 |
| 删除动画仍然存在且流畅 | 被删卡片有 ~0.1~0.2s 的淡出/缩小退场（不是瞬间消失），动画结束后列表稳定 |
| 不破坏其它交互 | 卡片入场动画、tab 切换、记反馈展开、状态变更（采用/完成/废稿）后列表更新均与原来一致；无新的 console error |
| 不改数据语义 | 仍是逻辑删除（`status=deleted`），确认弹窗、toast、列表刷新逻辑不变 |

## 三、页面数据来源

| 页面/字段 | 数据来源 | 更新时机 | 缺失/失败表现 |
|---|---|---|---|
| 草稿卡片列表 | `GET /api/drafts?limit=500`（`drafts` 表，按 `updated_at` 倒序） | 进入页面 / 删除后 `invalidateQueries(['drafts'])` 重新拉取 | 请求失败沿用现有错误提示；无数据展示空态 |
| 删除动作 | `PATCH /api/drafts/{id}` body `{status:"deleted"}`（逻辑删除） | 点击卡片垃圾桶 → 确认弹窗「删除」 | 失败 toast，卡片保留 |
| 退场动画 | 前端 `AnimatePresence` + Framer Motion（**仅被删卡片**） | 列表数据中该 id 消失时 | 无 |
| 其它卡片位置 | CSS Grid 原生布局（**不再用 layout 投影动画**） | 列表变化后浏览器重排 | 无 |

## 四、功能需求

### 4.1 删除草稿时的动画行为

- 点击卡片右下角垃圾桶 → 现有确认弹窗（标题「删除草稿…」、按钮「删除」）保持不变；
- 确认后：列表从服务端刷新，被删卡片从列表移除：
  - **被删卡片**：保留 `exit` 淡出 + 缩放到 0.96 的退场（约 0.16s）；
  - **其他卡片**：**平滑滑到新位置**（`layout="position"`，约 0.26s，只平移、不缩放；同一时刻开始，不做错峰），不再出现整片乱飞/拉伸变形；
- 删除后 tab 计数、空态、toast「已删除」等行为不变。

### 4.2 不改动的部分

- 删除接口、确认弹窗文案、逻辑删除语义不变；
- 卡片入场动画（`itemVariants` 淡入上移 + stagger）、卡片 hover 抬升、AI 状态条、记反馈展开动画不变；
- 「采用/不采用/完成/退回」等状态变更导致的卡片跨 tab 移动，行为不变（同样不做布局投影飞行）；
- 其它页面不动。

## 五、空数据 / 失败表现

| 情况 | 页面表现 |
|---|---|
| 删除成功 | 被删卡片淡出消失，其余卡片一次性归位；tab 计数更新 |
| 删除失败 | 现有 toast 错误，卡片保留，列表不闪动 |
| 删除后该 tab 为空 | 显示现有空态文案（如「暂无草稿…」） |
| 快速连续删除 | 每次删除独立处理，列表不叠加异常动画 |
| 刷新/切页回来 | 与正常列表一致（无残留动画） |

## 六、边界与不做

1. 只改「删除」触发的列表动画；不引入新的列表动画方案、不改其它页面；
2. 不做删除确认弹窗动效调整、不做撤销删除；
3. 不改后端接口/表结构/逻辑删除语义；
4. 不为动画引入 LayoutGroup/共享 layout 等复杂机制（根因就是 layout 投影动画，移除即可）。

## 七、用户故事

1. 作为作者，我删除一篇草稿时，只想看到被删的那张消失，其他草稿不要飞来飞去。
2. 作为作者，删除是破坏性操作，有确认弹窗 + 删除后退场动画就够，不要因为动画让我误以为删错了东西。

## 八、验收标准

1. 逐帧采样（删除第 1 张 / 删除中间一张）：剩余卡片在删除过程中**最多一次**位置变化（瞬间重排），没有连续多帧位置动画；无 `scale`/`translate` 变形飞行；无卡片飞出容器。
2. 被删卡片退场动画仍在（约 0.1~0.2s 淡出+缩小），随后从 DOM 移除。
3. 卡片入场、hover、tab 切换、记反馈、状态变更动画与原来一致；console 0 error。
4. `scripts/verify.sh` 全绿；服务保持运行。

## 九、实施记录与验证（2026-11-04）

- **v1（修复飞行）**（仅 `frontend_v2/src/pages/drafts/index.tsx`）：
  - 移除网格容器 `<motion.div layout>` 的 `layout`（改为普通 `<div>`）；
  - 移除 `DraftTile` 根节点 `<motion.article layout>` 的 `layout`（保留 variants 入场与 `exit` 退场）；
  - 列表 `AnimatePresence` 增加 `mode="popLayout"`，退场卡片不再占位、其余卡片立即重排。
- **v2（作者反馈「重排动画看不到」）**：
  - 重新给卡片加回 **`layout="position"`**（只对位置做布局动画，尺寸变化不缩放，避免旧版 `layout` 的拉伸/错峰飞行）；
  - 卡片 `transition` 显式指定 `layout: { duration: 0.26, ease: EASE_OUT_EXPO }`，让重排可见且克制；入场 stagger 只放在 variants 的 `opacity/y` 上，不再影响 layout；
  - 卡片 `exit` 缩短到 0.16s（scale 0.96），配合 `AnimatePresence mode="popLayout"` 让位；
  - 卡片 hover 从 `-translate-y-0.5`（CSS transform，会与 layout 内联 transform 冲突）改为边框高亮，避免动画互相干扰。
- **v2 逐帧验证**：删除中间一张，剩余卡片移动 12 帧（约 183ms）、总位移 370px（整列归位）、变换矩阵始终为 `1.00x1.00` 纯平移（无缩放）；控制台 0 error。
- **逐帧复现/验证**（Playwright `requestAnimationFrame` 采样，删除前 1 张与中间 1 张两种场景）：
  - 修复前：删除第 1 张后其他卡片单帧位移 65~372px、出现 `scaleY≈1.0757`、多卡错峰移动（t≈1014ms 连续多帧）；
  - v1 修复后：剩余卡片位置变化只发生在同一帧（无连续多帧）；v2 按作者反馈恢复为**可见的平滑重排**（12 帧/183ms/370px、无缩放变形）；
  - 被删卡片：0ms opacity≈0.968 → 60ms opacity≈0.003 + scale ≈0.96 → 160ms 从 DOM 移除（退场可见但快速）；
  - console error 0。
- **门禁**：`scripts/verify.sh` 全绿（前端 lint/vitest/build + 后端 758 项 + 文档 37 表）。
