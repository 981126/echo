## 一、需求背景

### 1.1 现在的情况（小白也能看懂）

- TikHub 账户余额不足后，所有账号同步都失败（接口返回 HTTP 402），数据库里 15 个账号 `sync_status=failed`；
- 但通知中心仍写「**平台数据同步完成**：全量同步：共 12 个博主，**已同步 12 个**（并发 4）；已自动触发「重新对标」」，看起来像成功；
- 「每日同步」自动任务也有同类问题：`run_sync` 内部**单账号失败不会抛异常**，只把错误写进 `accounts[].error`；上层只看「有没有抛异常」就一律算成功，于是全失败也报「完成/已同步」；
- 手动单账号同步同样：全失败时任务仍标「完成」，只在消息末尾带一行「失败账号」。

### 1.2 想解决什么

- 通知里的「成功/失败」必须与真实情况一致：
  - 全部成功 → 说成功；
  - 部分账号失败 → 明确写「成功 X、失败 Y」并列出失败原因；
  - **全部失败 → 任务按失败上报**，通知标题为「平台数据同步失败」，不再出现「同步完成/已同步」；
- 只有**真有数据同步成功**时才自动触发「重新对标」，全失败不再触发；
- 不改同步本身的行为（该失败的还是失败，不重试、不编造数据）。

## 二、想要实现的目标

| 场景 | 目标（可验收） |
|---|---|
| 一键「同步所有博主」（全量同步） | 每个博主按账号结果分为：全部成功 / 部分失败 / 失败；通知消息为「全部同步成功」或「成功 X、部分失败 Y、失败 Z（并发 W）」并附失败/部分失败明细（各最多 5 个 + 「等 N 个」）；**全部博主都没有同步成功 → 后台任务 failed，通知标题「平台数据同步失败」**；`synced` 只统计真有成功的博主 |
| 每日定时同步（06:00/17:00） | 按账号统计：全成功 → 「共同步 N 个账号」；有失败 → 「成功 X、失败 Y 个账号」+ 失败账号明细（最多 3 个）；**全部账号失败 → 任务 failed，通知「平台数据同步失败」，且不自动触发重新对标** |
| 手动单账号/单博主同步 | 全部账号失败 → 任务 failed（通知不再写「平台数据同步完成」）；有成功账号则保持成功并按原消息（含失败账号）展示 |
| 不引入新问题 | 全成功场景的通知文案、任务状态、自动重新对标行为与改前一致；TikHub 调用/预算/数据写入逻辑、接口、表结构全部不变；`verify.sh` 全绿 |

## 四、功能需求

### 4.1 全量同步（同步所有博主）

- 每个博主的同步任务按其账号结果判定：
  - 全部账号成功 → `done`；
  - 部分账号成功、部分失败 → `partial`（任务本身仍算完成，但消息标注「部分失败」）；
  - 全部账号失败 → 该博主的队列任务 `failed`，错误信息带失败平台与原因。
- 汇总消息：
  - 全部成功：「全量同步：共 N 个博主，全部同步成功（并发 W）」；
  - 有失败/部分失败：「全量同步：共 N 个博主，成功 X、部分失败 Y、失败 Z（并发 W）；失败：名字(原因)、…；部分失败：名字(原因)、…」（每类最多列 5 个，超出写「等 N 个」）。
- 全部博主都没有成功 → 外层任务抛错 → 任务 `failed`、通知标题「平台数据同步失败」、不再自动触发「重新对标」。
- `synced` 字段口径改为「至少有一个账号同步成功的博主数」（`done + partial`）。

### 4.2 每日定时同步

- 汇总所有 `run_sync` 返回的账号结果：
  - 全部成功：「每日同步完成：主博主 + N 个对标，共同步 X 个账号，更新作品 P，采集评论 C…」；
  - 有失败：「每日同步完成：…成功 X、失败 Y 个账号，更新作品 P，采集评论 C…；失败账号：平台(原因)、…（最多 3 个 + 等 N 个）」；
  - **全部账号失败**：消息改为「每日同步失败：主博主 + N 个对标，Y 个账号全部同步失败…」并抛错 → 任务 `failed`、通知「平台数据同步失败」。
- 自动重新对标：仅当确有成功同步（成功账号或创作者指标更新）时触发；全失败不触发。
- 返回值补充 `ok_accounts` / `failed_accounts` 计数（供测试与后续排查）。

### 4.3 手动单账号/单博主同步

- 与全量同步同口径：`accounts` 非空且全部带 `error` → 任务抛错（失败通知）；否则保持原行为（消息里仍会带失败账号信息）。

### 4.4 边界与不做

| 项 | 处理 |
|---|---|
| 无账号 / 全部账号被禁用 | 入队阶段即跳过（既有逻辑），不触发「全部失败」判定 |
| 预算耗尽（`BudgetExceeded`） | 保持既有语义：取消后续、任务失败（本次不动） |
| 部分账号失败 | 任务仍算完成（有数据同步），但消息明确「部分失败」并列出 |
| 通知文案长度 | 失败明细限 3~5 个并附「等 N 个」，避免超长；失败通知仍按既有 200 字截断 |
| 不改 | TikHub 客户端/请求/预算、同步数据写入、接口契约、数据库表、前端展示与动效 |

## 五、用户故事

1. **作为** 每天点「同步所有博主」的作者，**我希望** 当 TikHub 全失败时通知直接告诉我「同步失败」而不是「已同步 12 个」，**这样** 我不会以为数据已经更新了。
2. **作为** 会看每日自动同步结果的作者，**我希望** 通知里写清成功几个、失败几个、失败原因是什么，**这样** 我能判断是额度问题还是平台问题。
3. **作为** 只对某个账号手动同步的作者，**我希望** 该账号失败时任务标红而不是显示完成，**这样** 我能立刻知道这次同步没成功。
