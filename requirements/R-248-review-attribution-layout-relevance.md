## 一、需求背景

视频复盘的定位是「解释为什么 + 告诉下一条拍什么」，但作者实际使用时：

1. **解释不了为什么**：页面只告诉作者「留存下降了 15.2 个百分点」，既没有「这条视频哪里做得好/哪里做得差」的判断，也没有把原因和文案内容、评论反馈连起来；展开后还是一块原始 JSON，比不展示还难懂。
2. **版式不整齐**：首选与备选虽然已经同一行，但两卡高度不同、标题行样式不同，看起来「错位」。
3. **阅读顺序反了**：作者想先看「为什么」「怎么改」，再决定「下一条拍什么」，现在「下一条拍什么」排在最前面。
4. **参考视频太占地方**：一行 3 个、封面偏大，一屏看不到几条。
5. **低粉爆款跑题**：拉的是全站低粉总榜，绝大多数和作者方向（求职/面试/赚钱）无关，参考价值低。
6. **菜单顺序**：作者把数据看板当素材库的延伸，但菜单里两者位置相反。

## 四、功能需求

> 页面：**视频复盘**（`/video-review`）、**参考视频区**、**桌面侧栏**。

### 4.1 「这条视频为什么好或差？」改成 AI 归因诊断

- **整体结构**：每张归因卡展示
  - **方向徽标**（新增 `verdict`）：`好在哪`（绿）/ `差在哪`（琥珀）/ `影响有限`（灰）/ `无法判断`（灰）；
  - **一句话结论标题**（title，≤300 字）；
  - **为什么（conclusion）**：必须同时包含「数据依据 + 内容依据」：例如「完整完播率 7.4%，低于自己平时 6.9% 的中位数……结合文案看，中段从亏损细节跳到收入/买车/心态，可能让观众失去继续看的动力」；
  - **判断类型**：数据直接显示 / 结合内容推测 / 无法判断；
  - **下一条怎么改**（suggestion，保留现有位置）；
  - **数据依据**：改成人类可读的逐行文字（例：「完整完播率：7.4%（自己平时 6.9%，样本 4 条）」），不再出现原始 JSON；
  - **内容依据**：展示引用的文案原句/评论原句（带「来源：视频文案/评论」）。
- **生成规则**：
  - 程序先算全部真实指标事实（含样本数）；AI 只能基于这些事实 + 文案 + 评论生成 2~5 条归因，不能新增数字/经历/评论/证据；
  - `verdict` 由**程序**根据该条引用的真实指标状态判定：有指标高于平时 → 好在哪；有指标低于平时 → 差在哪；只引用样本不足/缺失指标 → 无法判断；指标都接近平时 → 影响有限（不让 AI 自己判「好坏」）；
  - 数字校验：输出中的所有数字必须能在输入事实中找到；文案引用必须是转写稿真实子串；不合规的条目丢弃；
  - 样本不足（可比较 <5 条）时：页面顶部提示「可比较样本 N 条（较少），以下原因不能当成整体好坏结论」；AI 不得把「样本少」写成「整体差」；
  - 无转写：只按指标给原因，并在卡片/页面提示「补充转写后可结合文案分析」；
  - 模型不可用/输出全部不合规：回退现有规则结论（数字来自真实指标），并显示「AI 归因暂不可用」；规则也没有结论时，至少给 1 条「数据还不够判断整体好坏」的说明（含可比较样本数与已能看到的最大差异指标）。
- **更新时机**：新分析生成新归因；历史复盘不自动重算——点「更新数据并分析」后生效（验收时对当前作品重跑一次无刷新分析）。
- **空数据/失败**：无复盘 → 现有空状态；模型失败 → 规则兜底 + 提示；一次分析 AI 调用次数不增加（替换原 findings 润色调用）。

### 4.2 首选/备选两卡对齐

- 同一行两卡**等高**（整行拉伸，底边对齐）；窄屏保持堆叠；
- 两卡**标题行统一**：同一高度、同一字号/颜色/图标位（左侧「下一条最推荐拍这个」↔ 右侧「两个备选主题」）；
- 左侧主题大标题与右侧第一张备选卡内容顶部对齐；
- 左侧「采用」按钮贴在卡片底部；右侧 2 张备选卡**等高**、「采用」按钮各自贴在卡底 → 两行按钮位置对齐；
- 单侧缺失时另一侧占整行，不做强行等高。

### 4.3 页面板块顺序

作品分析卡 → **这条视频为什么好或差？** → **按指标优化建议** → **下一条最推荐拍这个 / 两个备选主题** → 平时对比/观看趋势图表 → 流量来源/搜索词 → 评论问题 → 涨粉内容 → 首选之后 3 条 → 新话题 → 同行/低粉爆款。

其余板块内容、空状态、交互不变。

### 4.4 同行爆款/低粉爆款：封面缩小、一行 4 个

- 参考视频网格：宽屏（≥1280px）**4 列**；1024~1280 三列；768~1024 两列；<768 单列；
- 封面仍 4:3 固定框，卡片变窄后封面自然缩小；加载失败 ECHO 占位、不跳高；标题/作者/数据/查看原视频不变；
- 同行、低粉两个 tab 共用样式。

### 4.5 低粉爆款只显示与账号方向相关的内容

**方向词（程序计算）**

- 取当前主博主最近 30 条作品 `videos.main_topics`，排除「其他/知识」这类泛化留存类目后按出现次数排序，取前 **3** 个方向词（当前账号= 求职 / 面试 / 赚钱）；只有泛化类目时回退原始词，保证仍有方向可搜；
- 无作品/无主赛道时兜底 `求职 / 面试 / 赚钱`；
- 每个方向词内置**高信号**同义扩展（实际值）：
  - 求职：找工作、招聘、简历、面试、面经、offer、秋招、校招、跳槽、转行、职场、背调、求职者；
  - 面试：面经、hr、群面、终面、背调、面试官、候选人；
  - 赚钱：收入、工资、月入、副业、搞钱、存钱、存款、理财、薪资、年薪、年终奖、涨薪；
  - 知识：学习、干货、教程（仅当账号只有泛化类目时才用）。
- 泛化词（赚钱/打工/上班/知识/学习/经验等）不作为标题匹配词，避免「乌鸦打工赚钱」「二婚赚钱」这类标题混入。

**刷新（点「更新」）**

- 前端未传关键词（默认）→ 后端按方向词逐个抓「低粉爆款筛选」（每个方向词 1 次 TikHub 请求，最多 3 次），**每个方向词平分名额**（避免第一个词把 20 条占满），合并去重入库，每条记录命中的方向词；
- 前端手填关键词时仍按手填关键词抓（保持现有能力）；
- 失败/预算不足：沿用现有可读提示，不伪造、不清空已有数据；某方向词 0 条不报错，全部 0 条沿用现有 warning。

**展示（`GET /references?kind=low_fan`）**

- 只保留**标题**命中「方向词/高信号同义扩展词」的条目（抓取关键词字段不算命中，避免「按词搜回来但标题跑题」混入）；
- 按（最近出现 → 标题命中词数 → 相关度）排序：点「更新」后新抓、带新封面的条目优先展示；
- 不相关赛道（搞笑/宠物/演唱会/花草/婚姻等）不展示；
- 旧低粉行 `cover_url` 为空时，展示层回退原始响应里的 `thumbnail`（历史指数搜索结果把封面放在该字段），仍加载失败则 ECHO 占位；
- 过滤后为空 → 「当前方向下暂无低粉爆款，点『更新』获取」；同行爆款不受影响（同行=手动添加的对标账号）。

### 4.6 菜单顺序

桌面侧栏：主页 → **素材库 → 数据看板** → 视频复盘 → 脚本工作台 → 灵感随手记 → 博主对标 → 博主管理 → 人设档案 → AI 设置 → AI 对话。路由、页面标题、图标不变。

## 六、边界与默认结论（作者已确认）

1. 「为什么好/差」用 AI 归因诊断（程序算事实、AI 写原因、程序判方向与校验），**不新增 LLM 调用次数**（替换原 findings 润色调用）。
2. 顺序按 4.3；「为什么」与「按指标优化建议」两块都放在首选/备选上方。
3. 两卡等高 + 标题行统一 + 底部对齐。
4. 低粉相关方向 = 主赛道方向词 + 同义扩展 + 展示过滤；**不做手动关键词配置、不做 AI 逐条判断**；刷新最多多 3 次 TikHub 请求。
5. 历史复盘不自动重算，需手动重新分析；历史低粉数据不删除，只做展示过滤。
6. 只改桌面侧栏顺序（当前没有移动端底部导航实现）。

## 七、用户故事

1. 作为作者，我打开复盘页想知道「这条到底哪里好/哪里差、为什么」，而不是只看到一个「留存下降 15.2 个百分点」的数据事实和一块 JSON。
2. 作为作者，我理解不了高低不齐的两张卡；我希望首选和备选一样高、标题在同一行、按钮在同一条线上。
3. 作为作者，我想先看「为什么」和「怎么改」，再决定「下一条拍什么」。
4. 作为作者，我想一行看到 4 个参考视频封面，快速挑重点。
5. 作为作者，我只看和我方向一致（求职/面试/赚钱）的低粉爆款，不看猫狗搞笑视频。
6. 作为作者，我把数据看板当素材库的延伸，希望菜单放在素材库下面。
