## 原文（作者原话，未改动）
> AI 提示词 菜单下 生成脚本 中的【ai基于最新素材优化】 这个功能逻辑，有什么更好的建议吗

（AI 给出 A/B/C 三档建议后，作者选择：**「A：先做最小改动」**。）

## 诊断依据（代码事实，2026-09-10）
- `generation` 提示词本身仅约 260 字（角色 + 一句"模仿作者语气" + JSON 结构）；「像作者」几乎全由运行时注入承担。
- 语料 = `learning_material`（人设+风格画像+加权前 16 条转写稿，每条截 300 字）+ `feedback_context`（**当前 0 条反馈 → 为空**）。
- 评测 = `0.5 格式合法率 + 0.3 无红线 + 0.2 口癖覆盖率`：前两项对 generation 几乎恒为满分，第三项是 2 字二元组命中率，**区分度低且鼓励堆砌口癖**。
- 长度预算 2000 字 vs 当前 260 字：候选极易膨胀。
- 启用后 `_selfcheck_task` 依赖"已评分草稿"找金样本，**0 反馈 → 直接跳过**，没有证据闭环。
- 结论：对 `generation` 而言，"基于最新素材优化提示词"的因果链是断的——素材更新会自动注入、不需要改提示词。

## 本次范围（A 档：最小改动）
1. **定位说清（文案）**：按钮「AI 基于最新素材优化（候选）」→「**AI 基于真实样本优化（候选）**」；
   `generation` 卡片加说明：「素材/反馈更新会自动注入，无需改提示词；此按钮只在你想调整**写法与结构**时使用」。
2. **给优化器正面靶子**：`OPT_SYSTEM` 增加「可改 / 不可改」清单——
   可改：角色设定、写作或判断方法、结构要求（开场钩子/收尾引导）、篇幅与语气方向、需遵守的原则；
   不可改：作者姓名/身份/经历等具体事实、红线与金句清单、程序解析所需的输出格式与字段。
3. **长度约束**：候选总长 ≤ `max(1.5 × (当前提示词 + 契约段长度), 300 字)`，超限按**自检失败**处理（重试 1 次 → 仍超则丢弃并返回原因）；
   并在优化指令里要求"保持简洁"。
4. **变更说明**：要求模型在提示词正文后附「变更说明」（≤3 条：改了什么、依据哪条样本/反馈）；
   程序解析后写进候选 `note`，前端候选面板多行展示——直接回答"这版好在哪"。

## 不包含（B/C 档，留待后续）

- 启用后自动对照评测的闭环补强（依赖反馈数据积累）。

## 验收标准
1. 按钮与 generation 卡片文案已更新，明确"素材更新不需要改提示词"。
2. `OPT_SYSTEM` 含可改/不可改清单；优化指令含"保持简洁"。
3. 超长候选被拦截：单测覆盖（构造超长输出 → 自检失败重试 → 抛 `PromptOptimizeError`）。
4. 候选 `note` 含「变更说明」，前端多行可读。
5. `scripts/verify.sh` 全绿；接口冒烟；服务保持运行。
