> 2.博主对标，对标的数据沿用之前的规则改为两篇，第三篇为对标博主最新的一篇

2. **第三篇（最新一篇）没有 ASR 文案** → 作者选「要，自动补齐它的文案」（沿用现有
   `ensure_top3_with_text` 的下载+转写逻辑；补不出文案则照旧显示「暂无文案」）。

4. **隐藏废稿 tab 后「不采用/移入废稿/删除」按钮** → 作者选「保留按钮，只隐藏 tab」（后端逻辑不动）。

## 范围
### ① 脚本工作台隐藏【废稿/已删除】tab
- `DraftsView.vue` 删除 `archived` 这个 `n-tab-pane`（页面只保留「草稿」「待制作」两个 tab）。
- 保留 `markArchived` / `softDelete` / `restore` 与对应按钮、`list('archived')` 过滤逻辑、
  后端 `drafts.status` 口径与接口，**一律不改**（作者明确「只是不展示」）。
- 深链（`#/drafts?id=X`）打开的是废稿/已删除稿时，不再把 tab 切到已隐藏的 `archived`，
  弹窗仍能正常打开查看（只是列表页看不到该条目）。

### ② 博主对标：旧规则前2 + 第三篇=对标最新一篇
- 旧规则不变（最新 15 条 → 广告/同款漏标过滤 → 互动分 赞1+藏2+评5 → 展示时「有文案优先」）。
- 展示改为 3 条 = **按旧规则取前 2** + **该对标博主最新的一篇**。
- 第 3 位若与前 2 重叠 → 按互动分顺延补下一条（保底 3 条）。
- 第三篇同样纳入「转写补齐」：无文案则下载转写（失败/无声则显示「暂无文案」）；
  广告/商单仍按 R-103/R-106 严格审核排除后顺延。
- 「重新对标」/每日同步后自动重算沿用同一口径；文案与页头提示同步改写。

### ③ 素材库非主博主卡片「同步」旁加洗稿
- 非主博主（当前筛选博主不是当前主博主）的**云端卡与本地卡**，在「同步」旁加「洗稿」按钮。
- 点击行为与博主对标页「洗稿」一致：按当前主博主人设、走双模型多轮讨论洗稿
  （`rewrite_worker` / `run_rewrite_debate`），结果存脚本草稿（草稿/待制作）并弹「原文对照」。
- 文案来源 = 该素材的 ASR 转写稿；无文案时提示先去转写（不静默失败）。

### ④ 编辑页 ASR「已转写」旁加洗稿
- 非主博主素材的编辑页，`TranscribeSection` 的「已转写」标签旁加「洗稿」按钮。
- 行为同 ③（同一后端链路、同一结果弹窗）。

## 不包含
- 不改后端 `drafts.status` 语义，不新增/修改 drafts 表结构（无迁移）。
- 不改博主对标的候选范围（仍最新 15 条）、互动分权重、广告审核口径。
- 不给主博主（当前主博主）自己的素材加洗稿入口。
- 不在素材库新增「AI分析（能不能讲）」入口（仅洗稿；分析仍只在博主对标页）。
- 不改素材库卡片「同步」行为。

## 验收标准
- 脚本工作台只有「草稿 / 待制作」两个 tab；废稿/已删除稿件仍可通过后端接口查到，
  深链打开废稿不报错、不出现空 tab。
- 博主对标每个对标博主展示 3 条：前 2 为旧规则前列、第 3 为最新一篇；
  重叠时顺延补足 3 条；第三篇无文案时「转写补齐 / 重新对标」会补其转写。
- 非主博主素材：云端卡与本地卡「同步」旁有「洗稿」；编辑页「已转写」旁有「洗稿」；
  点击后落脚本草稿并弹出原文对照（与博主对标一致）；主博主素材不出现该按钮。
- `scripts/verify.sh` 全绿（ruff + mypy + pytest + 前端构建 + 文档一致性）+
  后端接口冒烟 + 前端关键交互点检；交付时前后端服务保持运行。
