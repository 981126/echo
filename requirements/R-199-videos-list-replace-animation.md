# R-199 素材库换批结果卡没有入场动画

- **日期**: 2026-09-28
- **状态**: ✅ 已完成（M188）
- **关联**: `frontend_v2/src/pages/videos/index.tsx`、`videos/material-card.tsx`、`lib/motion.ts`（`listReplace`）；R-179/R-175/R-164

## 原文（作者原话，未改动）
> 1.素材库切换博主查询的时候，查询出来之前会把卡片清掉 这个有动画没问题，但查询出来的结果卡片没有动画

## 根因（无头浏览器逐帧实测）
1. **退场与入场同时发生**：结果到达时旧卡 key 全部消失、新卡 key 全部出现，`AnimatePresence mode="popLayout"`
   把退场卡**绝对定位在原来的格子里**，新卡又立刻在自己的格子里从 `opacity: 0` 淡入 —— 两组卡在同一批网格位置上交叉淡入，
   新卡的入场动画被旧卡的退场动画盖住。实测：可见卡片数全程 ≥20，用户看不到「结果飞进来」。
2. **新卡还额外「隐身」**：入场错峰 `delay = index × 0.035`（最多 0.56s），这段时间新卡一直是 `opacity: 0`，
   叠加第 1 点后半屏看起来就是「卡住了 / 没有动画」。
3. **顺带查出的真 bug（同一处）**：查询 key 用了「下拉里选的博主」(`filters.creatorId`)，而请求参数用的是「点了查询才生效的博主」
   (`applied.creatorId`)。只切博主下拉、没点查询时，key 变了 → 发一次**参数没变**的空请求（实测 `?limit=20`，无 `creator_id`），
   并把上一个博主的数据写进新博主的缓存条目。实测：那种情况下卡片完全不重挂，更没有任何动画。

## 做法
- `lib/motion.ts` 增 `listReplace` 令牌（R-175 要求动效令牌统一）：`exitDuration 0.18`（旧卡快退）、
  `baseDelay 0.2`（新卡等旧卡退干净）、`stagger 0.018`（比首屏更紧凑）、`maxItems 20`（一屏 20 张各自错峰，不留整块同时进场）。
- `MaterialCard` 增 `replace` 属性：退场用显式短过渡（原来退场会继承入场 transition，时长/延迟随 index 乱）；
  换批时入场延迟 = `baseDelay + index × stagger`（只对首批新卡，滚动加载的 append 卡仍走 `softIn` 轻淡入）。
- `index.tsx`：用「首卡 key 变了」判定换了一批结果（`replaced`，ref + effect，不参与渲染副作用），下传 `replace`。
- `index.tsx`：查询 key 收敛为只用 `applied`（= 真正的请求参数），key 与请求不再分叉；切博主下拉不再发空请求，
  与其他筛选一致「点查询才生效」。
- 动效收口：序列 = 旧卡 0.18s 退场 → ~50ms 空档 → 新卡 0.3–0.9s 逐张飞入，全部落到 `opacity 1 / transform none`。

## 验收
- 无头实测逐帧（切换博主 → 查询，真实 110 条数据，console 错误 0）：
  - 只切下拉：**无请求**（修前会发 `?limit=20` 空请求）；
  - 点查询：`?limit=20&creator_id=2`，旧卡 0.54→0.01→0 退场（约 0.15s）→ 空档 ~50ms → 新卡可见数 1→4→7→10→12→15→18→20，t≈900ms 全部落定为 1；
  - 首卡与末卡内容确实换成新博主（`云端连七大姑…`）。
- 单测 `lib/motion.test.ts` 3 例（基础延迟 ≥ 退场时长 / 错峰覆盖一屏 / 总时长 <1s）；`tsc` + `eslint` + `vitest`（46 例）全绿。
- `scripts/verify.sh` 全绿。

## 修正（作者第二轮反馈，2026-09-28）

### 原文（作者原话，未改动）
> 不对，素材库切换博主查询的时候，查询出来之前会把老卡片清掉 这个有动画没了，保留之前的老动画

### 问题
第一版把**退场**也一起改了（改成统一的 0.18s 快淡出、scale 0.96），于是「老卡片清掉」那波动画（0.35s 淡出 + 缩到 0.94 +
`index × 0.035` 错峰扫过）被抹掉了 —— 作者要的是**保留老退场动画**。

### 修正
- `listReplace` 拆成 `exit` / `enter`：`exit = { duration: 0.35, stagger: 0.035, maxItems: 16, scale: 0.94 }`
  即换批前的**原值**；`enter = { breathAfterExit: 0.06, duration: 0.35 }`。
- **逐格交接**：新卡 i 的入场延迟 = 本格旧卡的退场延迟（`min(i,16) × 0.035`）+ 退场时长 0.35 + 0.06 呼吸。
  于是「老卡淡出缩小 → 新卡淡入」在同一格里首尾相接，既不互相抵消（两段都看得见），也不会整片网格空掉。
- `MaterialCard`：退场 transition 显式写回「这张卡原本的过渡规则」（首批 40 张 0.35s+0.035i；`append` 卡 softIn；更后面的卡 0.15s），
  入场 transition 仅在换批时按逐格交接加延迟，其余情况与原来完全一致。
- 单测加断言**锁死老动画数值**（`listReplace.exit` 必须等于 `{0.35, 0.035, 16, 0.94}`）+ 逐格交接不变量（入场延迟 ≥ 本格退场结束）。
- 另测得事实（澄清需求描述）：切换博主/查询**期间**旧卡一直留着，不会提前清空（`placeholderData: keepPreviousData`，
  900ms 慢响应实测：`t=11ms` 与 `t=1037ms` 前都是原来那 20 张、无骨架屏）；「清掉」就是结果到达时的退场动画。

## 修正②（作者第三轮反馈，2026-09-28）：新卡进场 = 退场倒放

### 原文（作者原话，未改动）
> 能不能用【旧卡退场】动画，做个相反 的新卡进场动画

### 做法
- `MaterialCard`：换批新卡的 `initial` 改成**退场的镜像** —— `{ opacity: 0, scale: 0.94 }`（原来是自己一套 `{opacity:0, y:18, scale:0.97}`），
  `animate` 仍是 `{opacity:1, scale:1}`；时长/节奏直接复用退场的 `0.35s` + `index × 0.035`（只有方向相反：退场是「淡出 + 缩小」，进场是「显影 + 长大」）。
- 起步 scale 直接引用 `listReplace.exit.scale`，不另立数值；单测加一条「进场时长 == 退场时长」的断言。
- 首屏首次加载的入场（`y 18 + scale 0.97` 那套）与滚动加载的 `softIn` 都不动，只有「换批」这一类用镜像。

| t≈190–353ms | op `0.14/0.28/0.57/1.00 → 0.01/0.02`，scale `0.951/0.963/0.986 → 0.940`（**淡出 + 缩小**，35ms/张扫过） | 仍 `0.00 / 0.940` |

## 真凶（作者第四轮反馈「入场动画一点都不明显」后定位，2026-09-28）

### 原文（作者原话，未改动）
> 入场动画一点都不明显

### 根因（决定性）
`AnimatePresence mode="popLayout"` 是靠**给每个子元素挂 ref、量出它的盒子**，再用
`[data-motion-pop-id] { position: absolute !important; … }` 把「正在退场的子元素」弹出文档流的
（`framer-motion/dist/es/components/AnimatePresence/PopChild.mjs`）。
而 `MaterialCard` 是 `memo(function MaterialCard(props){…})` —— **没有 forwardRef**，framer 传进来的 ref 挂不到根节点 →
`size.width/height` 量到 0 → 那条 `position: absolute` 规则根本不生成。

后果（无头实测 `grid.children` 的 `position/top/opacity`）：
| | 修前 | 修后 |
|---|---|---|
| 退场卡 | `flow@274`（**留在文档流里**，占着前 5 行） | `ABS@274`（被弹出流，不占位） |
| 网格高度 | 20 张时 2367 → 过渡中 **4565**（翻倍、页面跳动） | 2367 → 2196（**稳定不跳**） |
| 新卡位置 | `flow@297…` 其实在第 6–10 行（**屏幕外**，y≈2100+） | `flow@297`（第 1 行、**可视区内**） |
| 新卡入场 | 在屏幕外播完 → 动画结束才「啪」地出现在可视区 | 在可视区内播（op 0.9 / scale 0.95 → 1.03 回弹） |

⇒ 从 R-179 起，**所有「换批」的入场动画都在屏幕外播**，所以作者三次反馈「没有动画 / 不明显」——
不是动画参数的问题，是动画根本不在视野里。

### 修正
- `MaterialCard` 改 `forwardRef<HTMLDivElement, MaterialCardProps>`，把 ref 透传到根 `motion.div`；
  仍用 `memo(forwardRef(...))` 保留 R-179 的渲染性能优化。
- 回归单测：给 `MaterialCard` 传 ref，断言 `ref.current` 是 HTMLElement（去掉 forwardRef 即失败）。
- 同时保留第四轮的手感调整：`fromScale 0.78` + spring 回弹（冲过 1 到 ~1.03 再落回）—— 现在它在可视区里播，能看清了。

### 修后实测（真实数据，console 错误 0）
| 时刻 | 退场卡 | 新卡（可视区 y≈297 起） |
|---|---|---|
| t≈137ms | `ABS@270 op0.3 / ABS@265 op0.6`（弹出流 + 淡出缩小） | `flow@297 op0.0 / sc0.78`（就位等交接） |
| t≈486ms | 全部 `ABS` 且 `op0.0`（清场完成，屏内可见 0 张 = 那一下「清掉」） | `op0.0 / sc0.78` |
| t≈603ms | 同上（不占位、不推挤新卡） | `flow@271 op0.9 sc0.95 / flow@282 op0.6 sc0.88 / flow@293 op0.3 sc0.81`（**屏内长大**） |
| t≈720ms | 同上 | `op1.0 sc1.03`（**回弹峰值，看得见**） |
| t≈953ms | — | `op1.0 sc1.00` 落定；t≈1070ms 退场节点移除 |
