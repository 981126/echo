# R-172 博主对标封面长宽高统一（竖版封面把卡片撑高）

- **日期**: 2026-09-28
- **状态**: ✅ 已完成（2026-09-28，M161）
- **关联**: `frontend_v2/src/pages/benchmark/index.tsx`、`frontend_v2/src/pages/creators/posts-dialog.tsx`；R-164（前端重设计）、R-167（对标封面裂开）

## 原文（作者原话，未改动）
> 博主对标，封面需要限制长宽高，不然有些封面很高

> 博主对标，封面需要统一长宽高，不然有些封面很高

## 澄清
- 反问「统一成哪个比例」→ 作者选择 **4:3**（与素材库卡片、博主管理作品弹窗一致）。
- 范围：博主对标页封面框；顺带修博主管理作品弹窗加载骨架比例（3:4 写成与成品 4:3 不一致）。

## 根因与修复
**可复现**（无头浏览器实测 `/benchmark`，1440 视口）：

- 同一排卡片封面框尺寸实测 **344×194**（B站 16:9 源图）与 **344×459**（抖音/小红书 3:4 源图）、
  个别 344×678 —— 即竖版封面的原始高度把卡片撑高，同排其他卡片被 grid stretch 拉齐，整页高度参差。
- 根因：封面框虽然写了 `aspect-video`，但它是 `article`（`flex flex-col`）的 flex item，
  `min-height: auto` 的自动最小尺寸取内容高度；框内 `<img className="h-full w-full">` 的百分比高度在
  不定高祖先下回退为自身固有高度（344 宽 → 3:4 图即 459 高），于是 `aspect-ratio` 被内容最小高度顶开。
  （素材库 `material-card` 因封面框带 `overflow-hidden`，flex item 的自动最小尺寸为 0，故未出问题——同样写法、差一个类。）
- **修复**（`benchmark/index.tsx`）：封面框改 `relative aspect-[4/3] w-full shrink-0 overflow-hidden`，
  图片 `absolute inset-0 h-full w-full object-cover`（绝对定位不参与内容尺寸计算，比例只由框决定）。
- 附带（`creators/posts-dialog.tsx`）：加载骨架 `aspect-[3/4]` → `aspect-[4/3]`，与加载完成的成品一致，避免加载瞬间跳高。

## 验收
- 无头浏览器实测修复后 `/benchmark` 全部 33 张封面框**唯一尺寸 344×258（=4:3）**，含 B站 16:9 / 抖音·小红书 3:4 / 无封面占位；
  截图复核封面统一、封面字（如「42 分钟揭秘我的内容体系」）仍可读。
- 回归确认无同源问题的页面：博主管理作品弹窗 263×197、素材库卡片 265×199（均 4:3，修复前即正常）。
- `scripts/verify.sh` 全绿；后端(8000)/前端(3000) 保持运行。
