## 原文（作者原话，未改动）
> 这是我平常录视频的样子，还是会挡住，我这个系统，我想要个提词器，让我能很清楚的看着字录视频，眼睛不用乱飘

（随附现场照片：镜头 Insta360 Ace Pro 架在行李箱顶上，稿子显示在镜头后方的墙上大显示器里，行李箱与相机机身挡住屏幕中间的文字区域。）

## 现状排查（实施前）
- 仓库内**没有任何提词器代码**：全仓检索 `提词|teleprompt|prompter` 仅命中文档里「全文提词」（persona stance 关键词）与「口播稿」等无关词。
- 录制现场（照片）根因：**镜头与提词屏不在同一方向**——屏幕在镜头后方约 1 米、位置偏高，行李箱/相机机身挡住屏幕中部文字；看镜头就看不到字、看字眼睛就下垂 → 眼睛必然乱飘。
- 稿子本身已在系统里（草稿 `drafts.script`，Markdown），无需外部粘贴即可提词。

## 反问与确认结论（2026-09-29）
1. **提词屏**：作者选**笔记本屏幕**（放在镜头正下方/斜前方，可贴近），并确认位置上可行 → 版式按「笔记本全屏、纯黑底、大字号、正文贴近屏幕上沿」设计，让「读字方向 ≈ 看镜头方向」。
2. **必备控制项**（多选全选）：字号/行距可调 + 纯黑背景高对比；匀速自动滚动 + 快捷键加速/减速/暂停；**镜像翻转**（留给未来的分光镜式硬件提词器）；分段标记 + 当前段高亮；**语音跟读**；倒计时/录制时长 + 语速预估剩余时间。
3. **范围**：作者选**「先做能立刻用的最小版」**（该选项明确「语音跟读排下一版」）→ 与第 2 条中的「语音跟读」冲突，**按范围选项裁决**：
   - **本期（M214）**：字号/行距/纯黑高对比、匀速自动滚动 + 快捷键、镜像翻转、分段高亮、倒计时/语速预估剩余时长。**全部纯前端、零云服务依赖**，做完即可录。
   - **下一版（R-216）**：语音跟读（浏览器 Web Speech API，需 Chrome/在线，中文识别不稳，且**必须能随时退回手动**）。
4. **稿子来源**：直接用系统里已有草稿的「口播脚本」（草稿页一键进入全屏提词），不做「粘贴任意文字」的独立入口。
5. **只读**：提词页**不改稿、不回写**草稿（改稿仍回抽屉；避免录制中误触改坏稿子）。
6. **动效（R-175）**：提词页是「读字工具」，进入时只做极轻的入场（**禁止从 opacity:0 起步**，用 `softIn` 令牌），且**不得有持续/循环动画**干扰读稿；控制条按需淡入（鼠标移动/按键唤醒，3s 无操作淡出），正文区**不做任何动画**。
7. **不新增后端**：接口复用现有 `GET /api/drafts/{id}`，无表结构、无路由、无 LLM 成本。

## 交互规格（本期）
- **入口**：草稿抽屉「编辑」tab 的「口播脚本」标题行新增【提词器】按钮（与【预览】并列）；仅当稿子已存在（有 `id`）且正文非空时可点。点开跳 `#/prompter/:draftId`。
- **路由**：顶层路由（**不在 `AppShell` 内**，不显示导航/顶栏），保证真正全屏；`Esc` 退出回 `#/drafts`。
- **版式**：纯黑背景（`#000`）、正文区居中、`max-width` 约 60ch、**首行尽量靠屏幕上沿**（减小视线下移角度）、字号默认很大（约 56px，范围 28–120）、行距可调（1.4–2.4）、暖白字色（非纯白，避免眩光发灰）。
- **分段**：按空行分段（Markdown 正文先剥掉格式标记、图片/表格等非口播内容降级为纯文本）；**当前段高亮**（已有字色更亮、其余段略暗），随滚动自动切换当前段（判定=位于屏幕「读字基准线」的段），段间无动画切换（只换颜色，不做滚动位移动画）。
- **自动滚动**：`requestAnimationFrame` 恒速推进（速度单位：像素/秒，快捷键可调），**不依赖任何外部服务**；暂停时可用 ↑/↓（或滚轮/拖拽）手动找位置；到底自动停。
- **快捷键**：`空格` 播放/暂停、`↑/↓` 手动滚动、`+/-` 字号、`[`/`]` 速度、`M` 镜像、`R` 回到开头、`Esc` 退出；快捷键提示可用 `?` 唤起控制条查看。
- **镜像翻转**：`transform: scaleX(-1)`（文字左右翻转），留给分光镜式硬件提词器；设置项持久化。
- **倒计时/进度**：显示已录时长（00:00 起累加，仅播放时走）＋按当前语速（中文约 4 字/秒，复用 `core/transcript.py` 的口径）预估**剩余秒数**与总时长，配合草稿目标「1~2 分钟」；剩余时间为 0 时提示一次（不打断）。
- **设置持久化**：字号/行距/速度/镜像存 `localStorage`（键 `echo_v2_prompter`），下次进入沿用。
- **可见性口径**：「已录时长」只在播放时累加，暂停即停（不假装在录）。

- **读字基准线口径（实施时定的关键决定）**：基准线取「屏幕上沿往下**一个行高**」，不是屏幕高度百分比。理由：正文首行贴屏幕上沿后，作者读的就是最上面那行；
  用固定百分比会出现「一进页面高亮的是第 3 段、第一段永远轮不到高亮」的怪现象，且换视口高度/字号就失效。现口径下「进页面=第 1 段、滚到底=最后一段、段随滚动单调前进」在任意字号/视口都成立。
- **底部占位**：`视口高 − 基准线`，滚动上限再按「最后一段上沿 − 基准线」夹一次 → **停下 = 全部念完**（不是滚过一整屏空白）；稿子短到不用滚时不停表，由作者按空格停。
- **踩坑（已记入 DESIGN §6）**：Chromium 会把小数 `scrollTop` 取整，若每帧从 DOM 读回再累加，13.4px/s 的推进会被永久抹成 0（表现：按了播放、计时在走、正文一动不动）。改为浮点 ref 记账 + `Math.round` 变化时才写 DOM。
- **快捷键细节**：空格在「未开摄像头」时仍是 R-214 的播放/暂停；开摄像头后空闲时空格=开始录制、倒计时/录制中空格=停止（优先）；倒计时中 `-`/`+` 调倒计时秒数，其余时候调字号。
- **自测**：`npx tsc --noEmit` / `npm run lint`（0 error）/ `vitest run`（20 文件 119 例）通过；`frontend_v2/r214-prompter.mjs` 对 dev(3000) 与生产 dist(8000) 各跑一次**全绿**；`scripts/verify.sh` 全绿；后端 `git diff` 无改动。
