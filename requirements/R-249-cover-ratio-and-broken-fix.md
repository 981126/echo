## 现状核对（2026-11-04 代码检查 + 真实浏览器/数据取证）

1. **参考视频比例**：同行爆款/低粉爆款封面目前是 R-247 引入的 `aspect-[4/3]`（横版，1440 宽下 265×199）；抖音主页「视频」网格是 **3:4 竖版**。
2. **裂图排查（真实浏览器逐张加载）**：
   - 素材库 **613 张封面全部加载成功（0 裂图）**——数据本身没问题，但素材库卡片 `<img>` **没有 onError 兜底**，一旦用户侧遇到坏缩略图缓存/网络失败就会直接显示浏览器裂图；
   - 同行爆款 20 张中 **4 张**、低粉爆款 20 张中 **5 张** 的封面是远程抖音签名 URL（历史数据已过期/403），旧实现只在参考卡片里有简单占位，样式与「裂图」观感不一致；
   - 封面缩略图接口 `/covers/<name>?w=400` 返回 `Cache-Control: max-age=604800`（1 周）：历史某次坏缩略图一旦被浏览器缓存，1 周内会持续显示裂图，且同一 URL 不会重新请求 → 需要「缩略图失败 → 换原图 URL 重试 → 再失败占位」的兜底链（换 URL 可绕开坏缓存）。
3. **涉及组件**：`pages/videos/material-card.tsx`（素材库卡片）、`pages/video-review/index.tsx` 的 `ReferenceCover`（同行/低粉共用）。

## 一、需求背景

- 同行/低粉爆款是给作者「参考同方向爆款封面」用的，封面比例应与抖音主页视频（3:4 竖版）一致，才符合作者刷抖音时对封面的认知；
- 素材库、同行爆款、低粉爆款三处封面都出现过「裂开的图」（浏览器找不到/解不开图片），影响浏览体验；不能保证所有历史远程封面都长期有效（抖音签名 URL 会过期），但**页面绝不能出现裂图**：能加载就显示封面，加载不了就显示统一的 ECHO 占位。

## 二、想要实现的目标

| 目标 | 可验收标准 |

| 三处不再出现裂图 | 素材库、同行爆款、低粉爆款中，所有封面 `<img>`：加载成功显示图片；失败后自动换原图 URL 重试一次；仍失败显示 ECHO 占位；**浏览器裂图数量 = 0** |
| 素材库行为不变 | 封面点击播放/编辑、hover 放大与播放按钮、多选、同步任务角标等交互全部保持 |
| 不引入新问题 | `verify.sh` 全绿；1440/900 两档无横向溢出、0 console error；后端/接口/表零改动 |

## 四、功能需求

### 4.1 同行/低粉爆款封面改为 3:4

- 封面框由 `aspect-[4/3]` 改为 **`aspect-[3/4]`**（与抖音主页视频同比例）；
- 参考视频网格断点不变：宽屏 4 列、1024~1280 三列、768~1024 两列、手机单列；卡片变高但列数不变；
- 封面 `object-cover` 裁剪居中；保留懒加载；坏图占位同样在 3:4 框内（不跳高）；
- 标题、结论徽标、作者/粉丝、播放/点赞/评论、查看原视频等字段与位置不变。

### 4.2 封面统一兜底（三处不再裂图）

新增共享组件 `CoverImage`，行为固定为：

1. 先加载**缩略图**（本地 `/covers/*` 追加 `?w=400`；远程 URL 原样）；
2. 缩略图 `onError`（或 `onLoad` 但 `naturalWidth=0` 的坏图）→ **回退原图 URL**（不带 `?w=`，URL 不同可绕开历史坏缓存）重试一次；
3. 原图仍失败 → 渲染统一 **ECHO 占位**，绝不出现浏览器裂图；
4. URL 变化时重置兜底状态（卡片复用不串图）。

接入范围：
- **素材库卡片**（`material-card.tsx`）：替换原 `<img>`，占位用原有渐变 ECHO 样式；点击播放/编辑、hover 放大、多选等外层逻辑不变；
- **同行爆款 / 低粉爆款**（`ReferenceCover`）：内部改用 `CoverImage`，封面框改 3:4，占位用 ECHO。

### 4.3 历史无效远程封面

- 同行 4 张、低粉 5 张已过期的远程签名 URL 无法恢复 → 显示 ECHO 占位（不再是裂图）；
- 低粉点「更新」会重新抓取并获得新签名 URL；同行封面在平台同步时会补下载本地封面；本期不做封面本地化/远程代理。
