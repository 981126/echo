## 一、需求背景

### 1.1 现在的情况（小白也能看懂）

- **脚本工作台**：R-258 改成了瀑布流，但列数是固定 4 列（1440 宽屏幕下每张约 322px），宽屏上卡片还是偏宽、一屏看到的草稿少。
- **素材库**：卡片墙还是「网格」——**同一行卡片会被强行拉成一样高**（高度取这行最高的卡），内容少的卡片底部会出现空白；标题还强制预留两行高度。1440 下实测四行卡片高度分别是 339 / 356 / 360 / 360px（同一行内全部相等），看起来像一排排等高的砖块，没有错落感。

### 1.2 想解决什么

1. **脚本工作台**：卡片宽度不固定（随窗口/列数自适应），**一行最多 5 个**；
2. **素材库**：卡片**宽度固定**（保持现在一行 5 个的等宽），但**高度改成不固定**——像脚本工作台那样每张卡按自己的内容高度、多列错落排列（瀑布流）。

## 二、想要实现的目标

| 目标 | 可验收标准 |
|---|---|
| 脚本工作台最多 5 个/行 | 卡片宽度自适应并**最多 5 列**：≥1400px 视口 5 列（1440 下单卡约 255px、1920 下约 351px）；1280~1399px 4 列（约 282px）；1024~1279px 3 列；<640px 1 列；保持瀑布流错落 |
| 素材库宽度固定 | 列宽等宽（`flex-1`），断点与改前一致：≥1280px 5 列、1024~1279px 4 列、640~1023px 3 列、<640px 2 列；每列卡片数量均衡（20 条/5 列 = 4/4/4/4/4） |
| 素材库高度不固定 | 卡片高度由内容决定（1440 实测出现 321 / 338 / 342px 等多档，不再同一行全等）；去掉标题强制两行高（1 行标题的卡片更矮）；行与行不再对齐，列底参差 |
| 素材库不跳版 | 滚到底加载下一批（20→40 条）时，**已有卡片保持原列**（实测 20 张中 0 张换列）；切筛选/换博主时旧卡照常退场、新卡逐格入场（R-199） |
| 不引入新问题 | 卡片封面仍 4:3；多选/批量同步/删除、hover 播放、编辑抽屉、筛选/查询、点赞筛选、加载更多全部正常；六档视口无横向滚动、0 console error |

## 四、功能需求

### 4.1 脚本工作台：宽度不固定，一行最多 5 个

- 列数：<640px 1 列 / 640~1023px 2 列 / 1024~1279px 3 列 / 1280~1399px 4 列 / **≥1400px 5 列**（最多 5 个，不再继续增加）；
- 卡片宽度 = 可用宽度平均分（不写死像素），窗口变宽卡片同步变宽；5 列时单卡仍 ≥247px（1440 实测 255px），标题两行、按钮不挤压；
- 瀑布流错落、标题最多两行、删除/采用只在本列内上移等 R-258 行为全部保持。

### 4.2 素材库：宽度固定，高度不固定（瀑布流）

- 列数断点保持 R-257 的 2 / 3 / 4 / 5 列（<640 / 640~1023 / 1024~1279 / ≥1280）；
- 每张卡片高度由自己的内容决定（封面 4:3 + 标题行数 + 平台/播放/点赞/日期 + 标签行 + 操作行），不再被同行最高的卡拉高；
- 标题最多两行省略，并取消原来强制两行高度（1 行标题的卡更矮，参差更自然）；
- 卡片宽度仍按列等分（固定等宽），封面仍 4:3 裁切（R-249 口径不变）；
- 滚到底「继续下滑加载更多」：新批次追加到各列底部，已有卡片不换列、不闪动；
- 切筛选/查询/换博主：旧卡片照常退场（R-199 逐格交接），新卡片入场后按新列表重新分列。

### 4.3 边界与不做

| 项 | 处理 |
|---|---|
| 素材库封面比例 | 保持 4:3（R-249 作者确认口径），本次不改封面裁切/比例 |
| 素材库单卡宽度 | 等宽（宽度固定）；窗口变化时列数与列宽变化，但同一列内所有卡同宽 |
| 选择模式 | 多选、全选/批量同步/删除、底部批量条不变 |
| 加载骨架屏 | 按当前列数渲染同列宽骨架（素材库每列 `ceil(20/列数)` 张、草稿每列 ≥2 张），加载完不横向跳版 |
| 不做 | 不改卡片字段/按钮/筛选/分页/播放/抽屉；不改其它页面；不改接口/后端/数据库；不引入第三方瀑布流库 |

## 五、用户故事

1. **作为** 用宽屏写稿的作者，**我希望** 脚本工作台一行最多能放 5 张草稿卡、卡片宽度随窗口自适应，**这样** 一屏能看到更多草稿，不用频繁滚动。
2. **作为** 素材库的重度使用者，**我希望** 每张素材卡按自己的内容显示高度、左右等宽排成瀑布流，**这样** 就不会出现「其他卡被同行最高卡拉高、底部留一大块空白」的别扭感。
3. **作为** 会一直往下翻素材的作者，**我希望** 加载下一批时上面的卡片不要换位置，**这样** 我继续往下翻不会看丢刚才那张卡。
4. **作为** 偶尔切筛选/换博主的作者，**我希望** 素材库换批时仍有原来的逐格交接动画，**这样** 换一批结果不会突然闪白或跳版。
