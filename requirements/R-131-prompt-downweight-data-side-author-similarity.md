## 诊断依据（代码事实）
- `GENERATION_SYSTEM` 全文仅约 **260 字**（角色 + 一句"严格模仿作者语气" + 输出 JSON 结构）；「像作者」几乎全部由**运行时注入**承担：
  人设档案（含维度）、红线、金句锚点、语言习惯画像、风格样本、AI 腔禁词、最佳实践、对标风格卡。
  → 自动"优化"一条已把所有事委托给运行时的提示词，**能改的只有措辞，杠杆很小**。
- R-129 实测印证：优化器唯一能想到的"加强"就是**把作者传记/红线写进提示词**，而这正是必须禁止的（会造成"两份人设"）。
- 真正的杠杆在数据侧，但有 4 个点没吃满：
  1. **作者改写稿未进入生成上下文**：`original_script` 只用于 diff 分析、提示词优化语料与评测，**没做生成 few-shot**；
  2. 风格样本只检索 **3 条**（`_style_samples` k=3）；
  3. 「最佳实践」只有 **3 行概括**（`_best_practice_lines`），不是可模仿的开场/结尾结构；
  4. 生成后**没有自检**（红线/口癖/AI 腔词），坏了也没有补救。
- **数据底子现状（2026-09-10 实测）**：非广告素材 225 条、其中有转写稿 215 条；AI 草稿 5 篇；
  「AI 原稿 ≠ 作者改后」的成对样本只有 **4 对**；**草稿评分/采用反馈 0 条**。
  → 数据侧增强必须「有就用、没有不报错」；同时需要引导作者积累反馈，否则最强信号始终是空的。

## 范围
1. **降权 generation 自动优化**：取消「每 3 条新素材自动产出候选」与「每周日自动产出候选」，
   改为累计到阈值时**发通知提示可手动优化**（不自动烧钱）；规则型 key 的自动优化能力保留但默认关闭（可开关）。
2. **数据侧增强（"像作者"的真杠杆）**：
   - ① 把作者认可的「AI 原稿 → 作者改后」成对样本作为 few-shot 注入生成上下文（0 对时不注入）；
   - ② 风格样本检索条数可配置（默认 3 → 5~8），并支持把素材标为**风格范本**（优先注入、不被检索淘汰）；
   - ③ 高表现稿的**开场句/结尾引导句结构模板**（取代只有 3 行的概括）；
   - ④ 生成后**自检**（红线命中 / AI 腔禁用词 / 口癖覆盖率 / JSON 合法），不达标自动重写 1 次并留痕。
3. **反馈数据引导**：生成/保存草稿后引导作者打分（当前反馈为 0，是最缺的一环）。
4. **提示词页重定位**：页头说明改为「支架 + 高级设置，默认不建议改」；generation 卡片标注自动优化已改手动。

## 不包含
- 不改动人设提取/增量管线（R-128 已定稿）；
- 不删除 AI 提示词功能（保留版本/编辑/回滚/评测）；
- 不引入向量库（仍用现有 TF-IDF + 规则自检）。

## 验收标准（初稿）
1. generation 不再自动产出候选；素材/反馈累计到阈值时只发一条可读通知。
2. 有「原稿≠改后」样本时生成上下文出现 few-shot 段；0 对时该段不出现且不影响生成。
3. 风格样本条数可配置；被标为风格范本的素材必定出现在生成上下文中（在样本段内标注为范本）。
4. 生成上下文包含开场/结尾结构模板（来自高表现稿的真实片段）。
5. 生成后自检：命中红线或 AI 腔词/格式非法时自动重写 1 次，并在草稿上留可查痕迹。
6. 草稿保存后有打分引导（不打扰、可忽略）。
7. `scripts/verify.sh` 全绿；接口冒烟；服务保持运行。
