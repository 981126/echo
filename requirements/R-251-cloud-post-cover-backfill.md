- **关联**: R-244（数据看板/云端作品同步）、R-222（同步提速：封面批量下载从事务中拆出）、R-249（封面兜底与缓存版本）、R-058（封面文件命名）

## 现状核对（2026-11-05 数据取证 + 代码检查）

1. 用户截图中的博主「车厘子在努力」（creator 12 / account 15）共 79 条云端作品，其中 **6 条 `platform_posts.cover_path` 为空字符串**，`cover_url` 仍是抖音远程签名 URL；页面按设计回退远程 URL，但签名已过期 → 封面加载失败 → 显示 ECHO 占位（不是「裂图」，是**根本没有本地封面**）。
2. 全库同类数据：`platform_posts` 共 1998 条，**33 条 `cover_path` 为空**、**8 条为占位 SVG**（封面下载失败时生成的「抖音+标题」占位）→ 素材库里会出现大片占位。
3. **根因**：
   - 封面下载在 `_ensure_covers_batch()`（同步事务外）执行，任何一次同步中的中断/下载失败/后端无 `ECHO_DATA_DIR` 写权限（本次排查实测写文件 `PermissionError`）都会让当批作品留下空 `cover_path`；
   - 而后续同步只对**本次拉到的作品**再尝试封面，历史缺失行不会自愈 → 一直空着；
   - 远程签名 URL 过期后也无法靠远程回退显示。
4. 前端 R-249 兜底只会把失败变成占位，无法把「缺失的真实封面」补回来。

## 一、需求背景

作者素材库按博主筛选时，云作品卡片大面积显示 ECHO 占位，看不到真实封面；这些作品其实同步过、库里也有远程封面地址，只是本地封面没下载成功且不会自动补。需要让缺失封面**自动补齐**，并让以后同步失败也能自愈，而不是永久占位。

## 二、想要实现的目标

| 目标 | 可验收标准 |
|---|---|
| 存量缺失封面补齐 | 库里所有 `cover_path` 为空或占位 SVG 的云端作品执行一次修复：能下载到真实封面的全部落本地；下载不到的保留占位（有标题文字，不裂图） |
| 以后同步失败可自愈 | 每次账号同步结束后，自动补齐该账号**全部历史作品**的缺失封面（不只是本批），下次同步即可修复；不额外消耗 TikHub 请求（封面 CDN 直连） |
| 不重复制造占位文件 | 下载失败时复用已有占位 SVG，不再每次生成 `-2/-3` 副本 |
| 不改前端/接口/表 | 页面无需改动；同步接口请求/响应不变；无新表/新列 |

## 三、页面数据来源

| 页面字段 | 数据来源 | 更新时机 | 缺失/失败表现 |
|---|---|---|---|
| 素材库云作品封面 | `platform_posts.cover_path` → `/covers/<文件名>`；为空时回退远程 `cover_url` | 平台同步时下载；同步结束后自动补齐 | 补齐成功 → 显示真实封面；仍失败 → 占位 SVG（有标题）/前端 ECHO 兜底 |
| 新同步作品封面 | 同一次同步拉到的远端 `cover_url` → 本地 `covers/` | 同步事务外批量下载（现有） | 失败留空，由本次/下次同步补齐 |
| 占位封面 | `_cover_path_for` 生成 SVG（480×270，标注平台+标题） | 下载失败时 | 不是裂图；有文字说明 |

## 四、功能需求

### 4.1 同步后自动补齐该账号全部缺失封面

- 新增服务函数 `_backfill_account_covers(db, account, limit=200)`：
  - 查询该账号 `cover_path IS NULL / '' / like '%.svg'` 的作品（按发布时间倒序，最多 200 条）；
  - 对每条用**已存的 `cover_url`** 重新下载 → 转 web 图片（HEIC→JPEG）→ 写本地 `covers/` 并生成 400px 缩略图；
  - 成功：更新 `cover_path`，若旧值是占位 SVG 则删除旧文件；
  - 仍失败：复用已有占位 SVG（不新建副本）；本来为空的则生成一条占位 SVG。
- 调用位置：`sync_account()` 在现有 `_ensure_covers_batch()` 之后调用（任何手动/定时/单账号同步都会触发），异常不影响同步结果。
- 预算：封面下载走抖音 CDN，不调用 TikHub，不消耗每日请求额度；只有已存 URL 仍有效时才能补到真实封面（失效则保留占位）。

### 4.2 占位 SVG 复用

- `_cover_path_for(..., reuse_svg=old)`：下载失败时若旧占位文件仍存在则直接复用，避免每次重试生成新副本。

### 4.3 存量一次性修复

- 对现有库执行一次补齐：33 条空封面 + 8 条占位 SVG 逐条尝试；能下载到的写真实封面，失效的保留占位。

## 五、空数据 / 失败表现

| 情况 | 页面表现 |
|---|---|
| 补齐成功 | 卡片显示真实封面（本地 `/covers/*`，走缩略图） |
| 远端 URL 已失效 | 保留占位 SVG（平台+标题文字），不裂图；不再显示空白 ECHO |
| 后端无 `ECHO_DATA_DIR` 写权限 | 补齐失败并静默跳过（日志告警），需按部署要求修复权限后重启 |
| 同步中途重启 | 下次同步自动补齐丢失封面 |
| 无远程封面地址 | 生成/保留占位 SVG |

## 六、边界与不做

1. 不改前端、不改同步接口、不改表结构；
2. 不重新抓取已失效作品的远程详情（避免消耗 TikHub 预算）；失效封面保留占位；
3. 不改封面 CDN 下载的重试策略/缓存策略；
4. 不清理历史孤儿封面文件（本次仅修复引用关系）。

## 七、用户故事

1. 作为作者，我按博主筛选素材库时希望看到视频的真实封面，而不是一片 ECHO 占位。
2. 作为作者，即使某次同步中断/后端重启，之后同步也能把缺失封面自动补回来，不需要我手动处理。
3. 作为作者，如果某条封面源站确实失效，显示带标题的占位即可，不要裂图。
